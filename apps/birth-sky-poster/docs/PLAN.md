## 1. 前提：プロトタイプからの差分方針

本実装はゼロからの作り直しではなく、**プロトタイプの資産を引き継いだ本番化**である。

### 引き継ぐもの（変更しない）

- スイス・インターナショナルスタイルの視覚系（配色トークン・2 書体・ヘアライン・角丸なし）
- ポスターの版面設計（1000×1400、マストヘッド／円形星図／諸元欄／footer）
- 方位環・高度環・水平線サークル・方位針という計器図面のメタファ
- 天頂中心方位等距図法、外部 API に依存しない自前の天文計算
- Vite + TypeScript vanilla 構成、バックエンドなし、Docker マルチステージ配信

### 本番化のために変える／足すもの

| # | 課題（プロトタイプ） | 本実装での対応 | 対応 SPEC |
|---|---|---|---|
| P1 | 恒星の約 7 割（340/490）が乱数生成のダミー | 実測カタログ（Hipparcos 由来）921 個に置換。ダミー全廃 | FR-106 |

## 2. 技術選定

| 領域 | 採用 | 理由 |
|---|---|---|
| ビルド | Vite 8 | 既存構成の継続。静的出力・`base` 相対化が容易 |
| 言語 | TypeScript 6（strict） | 天文計算の単位・座標系の取り違えを型で減らす |
| UI 層 | フレームワークなし（vanilla DOM） | AR-01 のとおり。更新箇所が 2 点に閉じる |
| 描画 | SVG 直接構築 | 画面表示と書き出しで同一ノードを使え、乖離が構造的に起きない |
| 天文計算 | 自前実装 | AR-02。数十行で足り、依存を増やす理由がない |
| カタログ生成 | d3-celestial（devDep, BSD-3-Clause） | Hipparcos 由来の実測値と IAU 88 星座線を同梱。生成物のみコミット |
| 単体・統合テスト | Vitest 4（node / jsdom） | Vite 設定を共有でき、環境を per-file で切り替えられる |
| カバレッジ | `@vitest/coverage-v8` | 追加のインストルメンテーション不要 |
| E2E | Playwright | 実ブラウザでの描画・書き出し・コンソールエラー・ネットワーク 0 件を同時に検証できる |
| 書体 | @fontsource-variable（同梱） | CDN 参照ゼロ（NFR-001.2）。SVG への base64 埋め込みにも使える |

### 却下した選択肢

- **astronomy-engine / astronomy-bundle 等の天文ライブラリ** —
  本アプリが必要とするのは恒星の地平座標変換のみで、
  惑星暦・章動を含むライブラリはバンドルの大半が死荷重になる。AR-02 の方針を優先。
- **実行時に d3-celestial を依存に含める** — 全天 6 等（657KB）を読み込むことになり、
  4.5 等に絞った 78KB の生成物より大幅に不利。ビルド時変換で足りる。
- **Canvas による星図描画** — SVG 書き出し（FR-008.1）が別実装になり、
  画面と出力の乖離リスクが生じる。
- **jsdom での視覚回帰** — SVG の見た目は jsdom では検証できない。
  Playwright のスクリーンショットに寄せる。
- **恒星カタログの実行時 fetch** — NFR-001.1（外部リクエスト 0 件）に反する。

### データフロー

```
フォーム入力
   │  input/change イベント
   ▼
ui/validation.ts  ── 失敗 ──▶ app: state = 'invalid' ──▶ ui/form(エラー表示) + skeleton(エラー面)
   │ 成功
   ▼ PosterInputs
astro/compute.ts  ─(catalog.ts の静的データ)─▶ ComputedSky
   │
   ▼
render/chart.ts ──▶ SVGSVGElement ──┬──▶ #poster-mount（画面）
                                     └──▶ render/exportImage.ts（PNG / SVG）
```

同一の `SVGSVGElement` が画面と書き出しの両方に使われる（FR-005.5）。

### 状態機械

```
        ┌──────────┐
        │ loading  │  初期
        └────┬─────┘
             │ 初回描画完了
             ▼
   ┌──▶ ┌──────────┐ ──検証NG──▶ ┌──────────┐
   │    │  ready   │              │ invalid  │
   └────└──────────┘ ◀──検証OK──  └──────────┘
```

書き出し・現在地取得は上記と直交する短命な `busy` フラグとして扱い、
結果はステータス領域へ流す（ポスターの状態は変えない）。

## 4. デザイン方向性（維持・強化）

スタイル方向は **スイス・インターナショナル／計器図面**。プロトタイプの方向を維持し、以下を強化する。

- **階層**: 表題 46px → 諸元値 21px → ラベル 11px → 注記 9.5px。4 段のスケール差を明確に保つ
- **リズム**: 左レール 340px 固定 × 右プレビュー可変の非対称グリッド。
  fieldset ごとに `01 —` `02 —` の連番を振り、計器パネルの読み順を明示する
- **奥行き**: 影を使わず、**ヘアラインの太さ 3 段階**（`rule-strong` 1.6 / `ring-line` 1 / `rule-faint` 1 かつ淡色）
  と、破線の高度環による面の層で奥行きを出す
- **タイポ**: サンセリフ＝言語、モノスペース＝数値。この対応を例外なく守る
- **色**: 朱赤は水平線・方位針・N ラベル・プライマリボタン・フォーカス・エラーのみ。
  本実装で増える「エラー表示」も朱赤の**機能用途**に該当する
- **状態**: hover はボタン枠を朱赤へ、focus-visible は朱赤の下線＋シャドウ、
  インライン編集可能テキストは hover で朱赤に転じて可搬性を示す

新規追加する状態表示も同じ言語で作る。
ローディングは**スピナーではなく、方位環だけを描いた計器のスケルトン**とする
（汎用ローダーはライブラリデフォルト意匠に該当し NFR-006.1 に反するため）。

## 5. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 88 星座の線が密で図が煩雑になる | 可読性低下、意匠の破綻 | 線は 1px / opacity 0.32 の substrate として扱い、恒星ドットを前面に。地平線クリップで実質半減 |
| 921 恒星 ＋ 743 線分の SVG ノード増 | 再描画のもたつき | 地平線下を投影段階で除外。デバウンス 120ms。実測を NFR-003.3 で検証 |
| カタログ生成が d3-celestial の内部構造に依存 | 将来のバージョンで壊れる | バージョンを固定し、生成物をコミット。生成器に整合性アサーションを入れ、壊れたら生成時に失敗させる |
| jsdom に Canvas 実装がない | 書き出しの統合テストが書けない | `getContext` / `toBlob` / `URL.createObjectURL` をテスト内でスタブし、呼び出し契約を検証。実描画は E2E で担保 |
| Playwright のダウンロード検証が環境依存 | E2E の不安定化 | `page.waitForEvent('download')` で受け、保存先は一時ディレクトリ。サイズ検証は PNG ヘッダの幅高さで行う |
| `strict` 有効化で既存コードが広範に壊れる | 作業量の膨張 | 有効化を独立タスクに切り出し、型エラーを 1 コミットで潰し切る |
| 実測カタログ導入で見た目が変わり、ユーザー評価済みの印象を損なう | 差し戻し | 版面・配色・線幅は一切変えず、恒星の分布のみが実測値に変わる形にとどめる |

## 7. 検証計画

1. **単体（Vitest / node 環境）** — `astro/*`, `render/format`, `render/starLabels`,
   `ui/validation`, カタログ整合性。天文計算は既知の基準値と物理的不変量
   （例：北極星の高度 ≒ 観測地の緯度）で検証する。
2. **統合（Vitest / jsdom 環境）** — `render/chart` の SVG 構造、`render/editableText` の編集ライフサイクル、
   `ui/form` のエラー反映、`app.ts` の状態遷移、`exportImage` の呼び出し契約。
3. **E2E（Playwright）** — 実ブラウザで AC-01〜AC-22 を実行。
   コンソール ERROR 0 件・外部リクエスト 0 件・320〜1920px のレイアウト・スクリーンショットを取得。
4. **ビルド検証** — `npm run build` の型エラー 0、バンドルサイズの NFR-003.1 適合。
5. **コンテナ検証** — `docker build` → 起動 → HTTP 200 と実画面の描画確認。
6. **デザイン査読** — NFR-006 のチェックリストを実画面のスクリーンショットに対して目視適用。
