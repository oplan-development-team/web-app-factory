# SPEC: Birth Sky Poster — 観測星図ジェネレーター

**Feature ID**: 002-birth-sky-poster
**Status**: Approved (production implementation)
**Last updated**: 2026-08-21
**前身**: app-factory パイプラインによる自律生成プロトタイプ（同ディレクトリ）。本仕様はその本実装版。

---

## 1. 概要

任意の**日時**と**場所**を指定すると、その瞬間・その場所の天頂から見えていた星空を天文計算で再現し、
航海図・測量図のような計器図面風の円形星図ポスターとして PNG / SVG で書き出せる Web ツール。

バックエンドを持たず、天文計算・描画・書き出しのすべてをブラウザ内で完結させる。
入力された日時・位置情報は一切外部に送信しない。

### 1.1 差別化コンセプト（設計の核）

既存の星空ポスターサービス（Mapiful / StarMapCo / Louvenir 等）は
**「ダークネイビー背景 ＋ 白いドット ＋ 装飾的な円環 ＋ 筆記体の添え書き」**という同一様式に収斂している。
本アプリはこれを意図的に避け、**スイス・インターナショナルスタイル**を採る。

- **地**: ペーパーホワイト（`#f1efe7`）／**インク**: 近黒（`#17160f`）
- **アクセント**: 単色の朱赤（`#bd2a26`）のみ。**機能要素にのみ使用**し、装飾には使わない
  （水平線サークル／方位針／プライマリ操作／エラー表示／編集中インジケータ）
- **書体**: グロテスクサンセリフ（Inter Variable）＋ モノスペース（JetBrains Mono Variable）。
  **数値・座標・時刻は必ずモノスペース**で組み、計器の読み盤としての一貫性を担保する
- **図法**: カード／影／角丸を使わず、ヘアラインルールと余白の強弱だけで階層をつくる

この方向性は本アプリのアイデンティティであり、実装・テストの都合で薄めてはならない（NFR-006）。

### 1.2 対象ユーザー

- 誕生日・記念日の星空をプリントして贈りたい／飾りたい個人
- 既製の星空ポスターの画一的な意匠に満足できない層
- 天文趣味者で、任意日時の全天図を手早く出力したい層

### 1.3 スコープ外（非目標）

| 項目 | 除外理由 |
|------|----------|
| 太陽・月・惑星の位置表示 | 別種の軌道計算（ケプラー要素）が必要。恒星のみで概念は成立する |
| 都市名からの座標検索（ジオコーディング） | 外部 API が必須となり「完全クライアントサイド／送信ゼロ」の前提が壊れる |
| 逆ジオコーディング（座標→地名） | 同上。場所ラベルは常に自由記述とする |
| 歳差・固有運動・章動・大気差の補正 | 3節の FR-102 参照。ポスター用途では視認差が生じない |
| 複数カラーテーマ | 1.1 のスタイル方向そのものが製品価値。テーマ選択はそれを希釈する |
| 深宇宙天体（星雲・星団）・天の川 | 精密計器図の意匠と競合し、線画の可読性を落とす |
| 生成物のサーバー保存・共有リンク | バックエンドが必要になる |
| ユーザーアカウント／課金 | 単発小規模アプリの前提から外れる |

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| JD（ユリウス日） | 紀元前 4713 年からの通日。時刻計算の基準 |
| GMST | グリニッジ平均恒星時。JD から算出する（IAU 1982 近似式） |
| LST | 地方恒星時。`GMST + 経度(東経+)` |
| 赤経 / 赤緯（RA / Dec） | 天球上の座標。本アプリでは J2000.0 元期の値を静的に保持する |
| 高度 / 方位角（Alt / Az） | 観測地の地平座標。方位角は**真北 0°、東回り**で [0, 360) |
| 天頂中心方位等距図法 | 天頂を中心（alt=90 → r=0）、地平線を外周（alt=0 → r=R）に写す図法。`r = R·(1 − alt/90)` |
| 水平線サークル | alt = 0 の円。ポスター上で唯一の朱赤の主要線 |
| 高度環 | alt = 30° / 60° の同心破線円 |
| 方位環 | 外周の目盛りリング（5° 刻み、30° 主目盛、N/E/S/W） |
| 諸元欄（レジェンド） | ポスター下部の 4 列 × 2 行の計測値テーブル |
| 恒星カタログ | ビルド時に生成される静的 JSON（`src/data/stars.json`） |

## 3. 天文計算仕様

### FR-101: 時刻変換

- **FR-101.1** 入力は「現地日付」「現地時刻（分単位）」「UTC との時差（時間、実数）」の 3 点で受け取る。
  IANA タイムゾーン DB は使用しない（夏時間の判定はユーザーの責任とし、時差を直接入力させる）。
- **FR-101.2** UTC 時刻 = 現地時刻 − 時差。これを Unix ミリ秒に変換したのち JD へ変換する
  （`JD = utcMillis / 86400000 + 2440587.5`）。
- **FR-101.3** GMST は IAU 1982 の低精度式で求め、[0, 360) に正規化する。
- **FR-101.4** LST = `(GMST + 経度) mod 360`。
- **FR-101.5** UTC と UT1 の差（ΔUT1、最大 0.9 秒 ≒ 恒星時 0.004°）は無視する。
- **FR-101.6** 閏秒は考慮しない（JS の `Date.UTC` は閏秒を持たないため、結果的に UTC ≒ UT1 近似となる）。

### FR-102: 恒星座標の元期

- **FR-102.1** 恒星の赤経・赤緯は **J2000.0 平均位置の静的値**を用いる。
- **FR-102.2** 歳差・固有運動・章動・光行差・大気差の補正は**行わない**。
- **FR-102.3** これによる見かけ位置の誤差は、J2000.0 から ±50 年で歳差により最大約 0.7°。
  ポスターの水平線サークル直径（322 SVG 単位 ÷ 90° ≒ 3.6 単位/度）に対して約 2.5 単位であり、
  最も明るい恒星のドット半径（約 5 単位）以下。**用途上、意図的に許容する簡略化**として仕様に含める。
- **FR-102.4** ポスター footer と UI に、この簡略化を明記する（誠実性要件）。

### FR-103: 座標変換

- **FR-103.1** 時角 `H = LST − RA` を [-180, 180) に正規化する。
- **FR-103.2** 地平座標は以下の**単位ベクトル 3 成分**から求める（除算を含まない形式）。

  ```
  up    = sin(δ)·sin(φ) + cos(δ)·cos(φ)·cos(H)
  north = sin(δ)·cos(φ) − cos(δ)·sin(φ)·cos(H)
  east  = −cos(δ)·sin(H)

  alt = asin(clamp(up, −1, 1))
  az  = atan2(east, north)  を [0, 360) に正規化
  ```

  `acos` と除算による方位角算出は、**緯度 ±90°（極点）で全恒星の方位角が同一値に退化する**ため採らない。
- **FR-103.3** 緯度 ±90°、天頂（alt = 90°）、地平線直下など、いかなる入力でも
  `NaN` / `Infinity` を返してはならない。
- **FR-103.4** 天頂における方位角は数学的に不定である。実装は例外を投げず有限値を返せばよい。

### FR-104: 投影

- **FR-104.1** 天頂中心の方位等距図法：`r = R·(1 − alt/90)`。
- **FR-104.2** 画面上の向きは **北が上、東が右**（仰向けに寝て天頂を見上げ、頭を北へ向けた視界に一致）。
  `x = r·sin(az)`, `y = −r·cos(az)`。
- **FR-104.3** alt < 0（地平線下）の恒星は描画しない。

### FR-105: 星座線の地平線クリッピング

- **FR-105.1** 星座線は恒星 ID の対ではなく、**カタログが持つ折れ線の頂点座標列（RA/Dec）**として保持する。
- **FR-105.2** 各線分について、両端点の高度を評価する。
  - 両端が地平線上 → そのまま描画する
  - 片端のみ地平線上 → **地平線（alt = 0）との交点まで切り詰めて**描画する
  - 両端が地平線下 → 描画しない
- **FR-105.3** 交点は高度が単調に変化する区間の二分法で求める。誤差 0.01° 以内、反復上限 40 回。
- **FR-105.4** これにより、地平線をまたぐ星座（例：昇りかけのオリオン座）が
  「線ごと消える」プロトタイプの挙動を解消する。

### FR-106: 恒星カタログ

- **FR-106.1** カタログは **d3-celestial（BSD-3-Clause, Olaf Frohn）** が同梱する
  Hipparcos 由来の実測データからビルド時に生成する。手作業の座標入力・
  乱数によるダミー恒星の水増しは**行わない**（観測図という概念に対する誠実性要件）。
- **FR-106.2** 収録範囲は**視等級 4.5 等以下**の実在恒星、921 個。
- **FR-106.3** 各恒星は `id`(HIP番号) / `ra` / `dec` / `mag` を必ず持ち、
  固有名 `name`・バイエル符号 `bayer`・所属星座 `con` は存在する場合のみ持つ。
- **FR-106.4** 星座線は **IAU 88 星座すべて**（へび座は Caput / Cauda に分割されるため 89 フィーチャ）を収録する。
- **FR-106.5** カタログは devDependency から生成した静的 JSON として `src/data/` にコミットする。
  **実行時に外部データを取得しない。** 生成物は npm install 済み環境で再現可能でなければならない。
- **FR-106.6** 出典表記（BSD-3-Clause の帰属条項）を README とポスター footer に記載する。

### FR-107: 恒星の描画サイズ

- **FR-107.1** ドット半径は等級から算出する。等級 −1.5 〜 4.5 でクランプし、明るいほど大きい。
- **FR-107.2** 半径は常に 0.55 SVG 単位以上（最も暗い恒星でも視認可能であること）。

## 4. 機能要件（UI）

### FR-001: 日時入力

- **FR-001.1** 日付（`<input type="date">`）・時刻（`type="time"`, 分刻み）・
  UTC 時差（`type="number"`, 0.25 刻み, −12〜+14）を入力できる。
- **FR-001.2** 初期値は「今日・現在時刻・ブラウザのタイムゾーンオフセット」を用いる。
- **FR-001.3** 年は 1〜9999 を許容する。
- **FR-001.4** 存在しない日付（例: 2026-02-31）は**エラーとして扱い**、描画を更新しない。
- **FR-001.5** 時差は 0.25 時間刻みで丸めずに受け付けるが、±14 を超える値は範囲エラーとする。

### FR-002: 場所入力

- **FR-002.1** 緯度（−90〜+90）・経度（−180〜+180）を 0.0001 度刻みで入力できる。
- **FR-002.2** 「現在地を使う」ボタンで Geolocation API から緯度・経度を取得し、両欄に反映する。
  取得後もユーザーが手動で上書きできる。
- **FR-002.3** Geolocation の状態は `aria-live` 領域に日本語で提示する。
  - 取得中: 進行中であることを示し、ボタンを `disabled` かつ `aria-busy="true"` にする
  - 成功: 取得した緯度・経度を読み上げ可能な形で提示する
  - 権限拒否 / 非対応 / タイムアウト: それぞれ区別したメッセージを出し、手入力を促す
- **FR-002.4** 場所ラベルは 40 字以内の自由記述（任意）。逆ジオコーディングは行わない。
- **FR-002.5** 場所ラベルが空の場合、ポスターには `UNSPECIFIED LOCATION` を表示する。

### FR-003: 表示オプション

- **FR-003.1** 「星座線を表示する」チェックボックス（既定 ON）。
- **FR-003.2** 「恒星名を表示する」チェックボックス（既定 ON）。
  OFF のとき、恒星のドットは描画するがラベルは描画しない。

### FR-004: 入力バリデーションとエラー状態

- **FR-004.1** 検証は**純関数**として実装し、ブラウザのネイティブ検証ポップアップ（`reportValidity`）に依存しない。
- **FR-004.2** 不正な項目には、当該入力欄の直下に日本語のエラーメッセージを表示する。
  入力欄には `aria-invalid="true"` と `aria-describedby` を設定する。
- **FR-004.3** 1 つでもエラーがある間、ポスター領域は**エラー状態**を表示する。
  直前の正常な描画を残したまま黙って固まってはならない。
- **FR-004.4** エラー状態では書き出しボタンを `disabled` にする。
- **FR-004.5** エラーが解消されたら即座に通常描画へ戻し、エラー表示を除去する。
- **FR-004.6** 検証エラーの種類は最低限、以下を区別する。
  空欄 / 数値でない / 範囲外 / 存在しない日付。

### FR-005: ポスター描画

- **FR-005.1** ポスターは 1000 × 1400 の SVG（`viewBox` 固定、比率 5:7）として構築する。
- **FR-005.2** 構成要素は上から マストヘッド（表題・日付・場所・罫）／ 円形星図（方位環・高度環・
  水平線サークル・方位針・星座線・恒星）／ 諸元欄 ／ footer。
- **FR-005.3** 諸元欄には以下 8 項目を表示する。
  LOCAL TIME / LATITUDE / LONGITUDE / EPOCH / JULIAN DATE /
  GREENWICH SIDEREAL TIME / LOCAL SIDEREAL TIME / STARS SHOWN。
- **FR-005.4** 数値表示は次の書式に従い、**繰り上がりによる `60` 秒 / `60` 分表記を発生させてはならない**。
  - 恒星時: `HH:MM:SS`
  - 緯度経度: `DD°MM'SS"N|S|E|W`
  - UTC 時差: `UTC±HH:MM`
  - 日付: `YYYY.MM.DD`
- **FR-005.5** 画面上のプレビューと書き出される SVG は**同一の DOM ツリー**から生成する
  （見た目の乖離を構造的に防ぐ）。

### FR-006: 恒星名ラベルの衝突回避

- **FR-006.1** ラベルを付与する対象は「固有名を持ち、かつ視等級 2.5 等以下」の恒星とする。
- **FR-006.2** 明るい順に配置し、既配置ラベルの矩形と重なる場合はそのラベルを**描画しない**
  （ずらさない。計器図面の整列を崩さないため）。
- **FR-006.3** 矩形はフォントメトリクスの近似（1 文字あたり 0.6em）で見積もる。
- **FR-006.4** 水平線サークルの外側にはみ出すラベルは描画しない。

### FR-007: ポスター文言のインライン編集

- **FR-007.1** 表題 / 日付行 / 場所行の 3 つはポスター上で直接編集できる。
- **FR-007.2** 編集起動はクリックに加え、**キーボードでも可能**とする
  （`tabindex="0"` ＋ Enter / Space、`role="button"`、`aria-label` 付与）。
- **FR-007.3** 編集中はテキストの直上にフローティング入力欄を重ね、書体・字送り・寄せを一致させる。
- **FR-007.4** Enter で確定、Escape で取り消し、フォーカスアウトで確定。
- **FR-007.5** 空文字での確定は無視し、元の値を保つ。
- **FR-007.6** 手動編集された項目は、以後フォーム入力が変わっても**上書きされない**。
- **FR-007.7** 「表示文言をリセット」操作で、3 項目すべてをフォーム入力からの自動生成に戻せる。
  手動編集が 1 つもないときは当該操作を `disabled` にする。
- **FR-007.8** 再描画時に、編集用フローティング入力欄が取り残されてはならない。

### FR-008: 書き出し

- **FR-008.1** SVG 書き出し：画面と同一の描画を、**フォントを base64 で埋め込んだ自己完結ファイル**として保存する。
- **FR-008.2** PNG 書き出し：1x (1000×1400) / 2x (2000×2800) / 4x (4000×5600) を選択できる。既定は 2x。
- **FR-008.3** PNG は SVG を `<img>` 経由で Canvas にラスタライズして生成する。
  背景は必ず用紙色で塗り、透過 PNG にしない（印刷用途のため）。
- **FR-008.4** ファイル名は `birth-sky-poster_<場所スラグ>_<YYYYMMDD>.{png,svg}`。
  スラグは英数字とハイフンのみに正規化し、空になる場合は `chart` を用いる。
- **FR-008.5** 書き出し中はボタンを `disabled` かつ `aria-busy="true"` にし、進行中である旨を提示する。
- **FR-008.6** 成功時は「書き出しました」旨をステータス領域に提示する（`window.alert` を使わない）。
- **FR-008.7** 失敗時はステータス領域にエラーとして提示する。
  Canvas サイズ上限超過など、4x で失敗しうることを含意したメッセージとする。

### FR-009: 再描画とパフォーマンス

- **FR-009.1** フォーム入力の変更から描画反映までは 120ms デバウンスする。
- **FR-009.2** 再描画中もポスター領域の**寸法は変化してはならない**（レイアウトシフト 0）。
- **FR-009.3** 差し替え時のちらつきを避けるため、ポスター領域は常に `aspect-ratio: 5/7` で予約する。
- **FR-009.4** 初回描画完了までは、ポスター領域にローディング状態を表示する。

### FR-010: 状態表示（ローディング / 空 / エラー / 成功）

- **FR-010.1** アプリは以下の状態を明示的に持ち、ポスター領域に対応する表示を出す。

  | 状態 | 契機 | 表示 |
  |------|------|------|
  | `loading` | 初回描画前 | 計器風のプレースホルダ（方位環のみのスケルトン）＋「観測条件を計算しています」 |
  | `ready` | 描画成功 | ポスター |
  | `invalid` | 入力エラー | 朱赤の枠 ＋ 「入力を確認してください」＋ エラー項目の列挙 |

- **FR-010.2** 書き出し・現在地取得の成功／失敗はステータス領域（`role="status"` / `role="alert"`）で通知する。
- **FR-010.3** すべての状態遷移メッセージは日本語で提示する。

## 5. 非機能要件

### NFR-001: プライバシー（最重要）

- **NFR-001.1** バックエンドを持たない。実行時に**いかなる外部ネットワークリクエストも発生させない**。
- **NFR-001.2** フォント・カタログはすべてビルド成果物に同梱する（CDN を参照しない）。
- **NFR-001.3** 日時・緯度経度・場所ラベルを外部へ送信しない。解析タグ・トラッキングを含めない。
- **NFR-001.4** Geolocation API はブラウザネイティブ機能としてのみ使用し、取得結果を送信しない。

### NFR-002: 配信形態

- **NFR-002.1** 静的ファイル（`dist/`）のみで動作する。
- **NFR-002.2** `base: './'` により、サブディレクトリ配下にも配置できる。
- **NFR-002.3** `Dockerfile` は node:22-alpine でビルドし nginx:alpine で `dist/` を配信する
  マルチステージ構成を維持する。ビルドは npm ci による再現可能インストールとする。

### NFR-003: パフォーマンス

- **NFR-003.1** 本番 JS バンドルは gzip 後 150KB 未満、CSS は gzip 後 30KB 未満。
- **NFR-003.2** フォーム変更から再描画完了まで、通常入力で 200ms 以内（デバウンス込み）。
- **NFR-003.3** 天文計算（921 恒星 ＋ 743 線分）は 1 回あたり 30ms 以内。
- **NFR-003.4** CLS = 0（ポスター領域の寸法予約により保証する）。

### NFR-004: レスポンシブ

- **NFR-004.1** 320 / 375 / 768 / 1024 / 1440 / 1920px で横スクロールが発生しないこと。
- **NFR-004.2** 900px 未満では 2 カラムを 1 カラムへ切り替える。
- **NFR-004.3** ポスタープレビューは常にアスペクト比 5:7 を保つ。

### NFR-005: アクセシビリティ

- **NFR-005.1** すべての入力欄に `<label>` を関連付ける。
- **NFR-005.2** キーボードのみで全機能（入力・現在地取得・インライン編集・リセット・書き出し）を操作できる。
- **NFR-005.3** フォーカスリングを可視化する（朱赤のアンダーライン／アウトライン）。
- **NFR-005.4** 状態変化は `aria-live` で通知する。
- **NFR-005.5** 本文テキストと背景のコントラスト比は 4.5:1 以上。
- **NFR-005.6** `prefers-reduced-motion: reduce` を尊重し、トランジションを無効化する。
- **NFR-005.7** ポスター SVG に `role="img"` と内容を説明する `aria-label` を与える。

### NFR-006: デザイン品質（Anti-Template Policy）

- **NFR-006.1** 以下を**禁止**する。
  画一的なカードグリッド／中央寄せ＋グラデーションブロブのヒーロー／ライブラリのデフォルト意匠そのまま／
  一様な角丸・影・余白／グレー基調＋差し色 1 色だけの安全策／ダークネイビー星図テンプレートへの回帰。
- **NFR-006.2** 以下を**最低 4 項目**満たす。
  1. スケール差による明確な階層（表題 46px / 諸元値 21px / 注記 11.5px）
  2. 意図的な余白のリズム（左レール 340px 固定 ＋ 可変プレビュー、非対称グリッド）
  3. ヘアラインルールによる面の分節（カード・影を用いない）
  4. 用途の分かれた 2 書体（サンセリフ＝言語、モノスペース＝数値）
  5. 意味を持った配色（朱赤＝機能のみ）
  6. 作り込まれた hover / focus / active 状態
- **NFR-006.3** 角丸は用いない（`border-radius: 0`）。影は用いない。
- **NFR-006.4** 1.1 のスタイル方向は、実装容易性・テスト容易性を理由に変更しない。

### NFR-007: ブラウザサポート

- **NFR-007.1** Chrome / Edge / Firefox / Safari の最新 2 バージョン。
- **NFR-007.2** ES2022 をターゲットにビルドする。
- **NFR-007.3** Geolocation 非対応環境でも、手入力で全機能が使用できる。

### NFR-008: コード品質・テスト

- **NFR-008.1** TypeScript は `strict: true`（`noUncheckedIndexedAccess` を含む）でコンパイルが通ること。
- **NFR-008.2** `as` による無検査の DOM キャストを行わない。要素が見つからない場合は起動時に明示的に失敗する。
- **NFR-008.3** テストは単体 / 統合 / E2E の 3 種を備える。
- **NFR-008.4** 行カバレッジ 80% 以上（`src/` 対象、エントリポイントと生成データを除く）。
- **NFR-008.5** 1 ファイル 400 行以内を目安とし、800 行を上限とする。

## 7. エッジケース

| ケース | 期待挙動 |
|--------|----------|
| 緯度 = +90.0（北極点） | 全恒星の方位角が退化せず分散する。天の北極が天頂に来る |
| 緯度 = −90.0（南極点） | 同上（天の南極が天頂） |
| 恒星が天頂に一致 | 方位角は不定だが有限値。チャート中心に描画される |
| 経度 = ±180.0 | LST が正しく [0,360) に折り返る |
| 時差 = +14 / −12 | 受理する。範囲外はエラー |
| 時差に 0.5 / 0.75 などの端数 | 受理する（+5:45 のネパール等） |
| 年 = 1 / 年 = 9999 | 受理する。歳差誤差の警告は footer の一般注記でカバーする |
| うるう年 2 月 29 日 | 受理する |
| 2026-02-31 | エラー（FR-001.4） |
| 場所ラベルが空 | `UNSPECIFIED LOCATION` を表示 |
| 場所ラベルが日本語のみ | ポスターには入力どおり表示。ファイル名スラグは `chart` にフォールバック |
| 場所ラベルに `<script>` 等 | `textContent` 経由のみで挿入し、HTML/SVG として解釈しない |
| 地平線上に恒星が 0 個 | 空の星図として正常に描画する（諸元欄の STARS SHOWN が 0） |
| Geolocation 非対応 | 非対応メッセージ。ボタンは押せるがエラー表示で終わる |
| Geolocation タイムアウト（10s） | タイムアウト用メッセージ |
| PNG 4x が Canvas 上限を超過 | `toBlob` が null を返した場合にエラーメッセージを出し、解像度を下げるよう促す |
| 編集中に別の編集を開始 | 先の編集を確定してから新しい編集を開く |
| 編集入力を空にして確定 | 元の値を保持する |

## 8. アーキテクチャ制約

- **AR-01** Vite + TypeScript の vanilla 構成。UI フレームワーク（React/Vue 等）を導入しない。
  DOM の更新箇所が「フォーム」と「ポスター SVG の丸ごと差し替え」の 2 点に閉じており、
  仮想 DOM の利点よりバンドル増と抽象化コストが上回るため。
- **AR-02** 天文計算は外部ライブラリに依存せず自前実装する（`src/astro/`）。
  必要な計算は数十行であり、依存を増やす合理性がない。また学習・検証可能性を保つため。
- **AR-03** 恒星カタログの生成のみ devDependency（d3-celestial）に依存する。
  生成物は静的 JSON としてコミットし、**実行時依存にはしない**。
- **AR-04** 描画は SVG を直接構築する。同一ノードを画面表示と書き出しの両方に用いる。
- **AR-05** DOM に触れるモジュールと純関数モジュールを分離し、後者を単体テストの主対象とする。
- **AR-06** 他の `apps/` 配下と一切のコード・依存を共有しない。

## 9. 既知の限界（仕様として許容）

1. **歳期補正なし** — FR-102 のとおり。±50 年で最大 0.7°。
2. **大気差補正なし** — 地平線付近で実際には約 0.5° 浮き上がって見えるが、補正しない。
3. **恒星は 4.5 等まで** — 肉眼限界（6 等）より明るい範囲に留める。
   6 等まで収録すると 5044 個となり、ポスターとして黒くつぶれ、可読性が落ちるため。
4. **恒星の色を表現しない** — カタログは B−V 色指数を持つが、
   単色インクのスタイル方向（1.1）に反するため使用しない。
5. **タイムゾーン DB を持たない** — 夏時間の適用判断はユーザーに委ねる。
6. **星座線は IAU 公式の「星座線」ではない** — IAU が定めるのは境界線のみであり、
   線画（アステリズム）は慣習に基づく。d3-celestial の定義をそのまま採用する。
7. **PNG 4x は環境依存で失敗しうる** — Canvas の面積上限はブラウザ・端末により異なる。
   失敗時はエラー提示に留め、自動フォールバックはしない（ユーザーが解像度を選び直す）。
