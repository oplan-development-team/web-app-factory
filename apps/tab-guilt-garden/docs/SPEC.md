# SPEC — タブ庭園 (Tab Guilt Garden) 本実装

- ステータス: 確定（2026-08-31）
- 起点: app-factory が自律生成したプロトタイプ（コミット `4fe54f3`）
- スコープ: 単発・小規模Webアプリ。バックエンドなし、同一ブラウザ内のタブ間同期のみ。

---

## 1. 製品定義

### 1.1 コアループ

このアプリを開いた**ブラウザタブ1本＝庭の苗1本**。開いているすべてのタブの苗が、
どのタブから見ても同じ1つの「庭」として集約表示される。

1. タブを開く → 苗が生える（発芽）
2. そのタブにフォーカスしている間は健康。**フォーカスを外した実時間**に比例してしおれる
3. フォーカスを戻すと回復する
4. タブを閉じる（またはクラッシュする）と、苗は**墓標**として恒久的に記録される

タブを溜め込みがちな自分への自虐ジョークツールであり、同時に
**進行が実時間に紐づく放置系インクリメンタルゲーム**でもある。後者の性質
（閉じても記録が残る／じわじわ育ち朽ちる過程を眺める／通算記録が積み上がる）を
本実装では明確に強化する。

### 1.2 スコープ外（意図的に作らない）

- サーバー・アカウント・複数ブラウザ/端末間の同期
- 課金要素、複雑な成長ツリー、アップグレード購入などの本格ゲームシステム
- 水やり等のクリックで苗を能動的に救うミニゲーム（回復トリガーはフォーカス復帰のみ）
- タブ本来のページタイトル/favicon の取得（同一オリジン制約により技術的に不可能）
- サウンド演出、PWA化、通知/リマインダー
- 苗の種類を手動選択するカスタマイズUI（ランダム割当のみ）

## 2. 時間モデル

### FR-100 圧縮内部クロックと誇張表示

内部の崩壊は分単位で高速にチューニングし、**表示テキストのみ** `DISPLAY_TIME_SCALE`
（=60）倍して「3時間放置」のように誇張する。

| 定数 | 値 | 意味 |
|---|---|---|
| `TICK_MS` | 1000 | 各タブが再計算・再描画する周期 |
| `GROWTH_MS` | 40_000 | 植栽から満開（成熟度100）までの実時間 |
| `DECAY_MS` | 180_000 | フォーカスを外してから枯死（生命力0）までの実時間 |
| `HUSK_AT_MS` | 360_000 | 枯死後さらに放置して「立ち枯れ」になる放置実時間 |
| `FOSSIL_AT_MS` | 720_000 | 「化石化」になる放置実時間 |
| `HEARTBEAT_BROADCAST_MS` | 3000 | 生存信号のブロードキャスト間隔 |
| `GHOST_TIMEOUT_MS` | 90_000 | この時間ハートビートが途絶えたらクラッシュとみなす |
| `DISPLAY_TIME_SCALE` | 60 | 表示テキスト専用の誇張倍率 |

- AC-100a: `DISPLAY_TIME_SCALE` は表示関数（`formatNeglect`）のみに作用し、
  生命力・成熟度・段階判定・ゴースト判定のいずれにも影響しない。
- AC-100b: 保存される時刻・期間はすべて実ミリ秒（誇張前）である。

### FR-101 成熟度 (maturity)

`maturity = clamp((now - plantedAt) / GROWTH_MS * 100, 0, 100)`。
フォーカスの有無に関係なく、存在時間だけで進む。

- AC-101a: 植栽直後は 0、`GROWTH_MS` 経過以降は 100 で頭打ち。

### FR-102 生命力 (vitality)

`vitality = clamp(100 - (now - lastFocusAt) / DECAY_MS * 100, 0, 100)`。
フォーカス中は `lastFocusAt` が毎tick現在時刻に更新されるため 100 を保つ。

- AC-102a: フォーカス復帰時、生命力は即座に 100 に戻る（回復は不可逆でない）。
- AC-102b: `now < lastFocusAt`（時刻巻き戻り等）の場合も 100 を返し、NaN や
  100超を返さない。

### FR-103 段階 (stage)

生命力・成熟度・放置時間から 7 段階を決定する。判定は上から順に評価する。

| 段階 | ID | 条件 |
|---|---|---|
| 化石化 | `fossil` | 放置実時間 > `FOSSIL_AT_MS` |
| 立ち枯れ | `husk` | 放置実時間 > `HUSK_AT_MS` |
| 枯死 | `dead` | `vitality <= DEAD_AT` (=4) |
| しおれ | `wilt` | `vitality <= WILT_AT` (=50) |
| 発芽 | `sprout` | `maturity < 33` |
| 若葉 | `leaf` | `maturity < 75` |
| 満開 | `bloom` | それ以外 |

`husk` / `fossil` はプロトタイプから新設。**枯死で終わりにせず、放置し続けた
プレイヤーにも変化が起き続ける**ようにするための、放置ゲームとしての意図的な追加。

- AC-103a: 苗を閉じずに放置し続けると `dead` → `husk` → `fossil` と表示が変化する。
- AC-103b: `fossil` の苗もフォーカス復帰で `sprout`〜`bloom` に回復する（不可逆ではない）。

## 3. タブ間同期

### FR-200 タブ識別

各タブは読み込み時に `crypto.randomUUID()` で自身の ID を発行する。ID はページ
リロードで再発行される（＝リロードは「閉じて開き直した」扱い）。

### FR-201 状態の保存先

`localStorage` のみ。キーは以下。

| キー | 内容 |
|---|---|
| `tgg:plants:v1` | 生存中の苗 `PlantRecord[]` |
| `tgg:graveyard:v1` | 墓標 `GraveyardEntry[]` |
| `tgg:ledger:v1` | 通算記録 `LifetimeLedger` |
| `tgg:intro-seen:v1` | 初回説明を閉じたか |

### FR-202 通知

`BroadcastChannel('tab-guilt-garden:v1')` でイベントを通知し、受信側は
localStorage を読み直して再描画する。メッセージ本体には状態を載せない
（localStorage を単一の真実とし、二重管理しない）。

メッセージ種別: `planted` / `heartbeat` / `buried` / `reset`。
`buried` は**埋葬された苗の ID** を運ぶ（プロトタイプは誤って送信者自身の ID を
送っていた。FR-202a で是正）。

- AC-202a: ゴースト埋葬時のブロードキャストは、埋葬された苗の ID を運ぶ。
- AC-202b: `BroadcastChannel` が存在しない環境でも例外を投げず、`TICK_MS` 周期の
  localStorage 再読込によって結果的に同期する。

### FR-203 自タブ以外への書き込み禁止

各タブは `plants` 配列のうち**自分の ID のレコードのみ**を更新する。他タブの
レコードは読み取り時の値をそのまま書き戻す。

- AC-203a: タブAで苗の名前を入力中に、タブBのtickが走っても入力内容が消えない。

### FR-204 ゴースト判定

`now - lastHeartbeatAt > GHOST_TIMEOUT_MS` の他タブレコードは、クラッシュ・
強制終了とみなして死因 `ghost` で墓標に移す。

- AC-204a: 複数のタブが同時に同じゴーストを検出しても、墓標は 1 基しか増えない
  （ID による重複排除）。
- AC-204b: 自分自身をゴースト判定しない。

### FR-205 通常終了

`pagehide` / `beforeunload` で、自分の苗を死因 `closed` で墓標に移し、生存リストから外す。

- AC-205a: 二重発火しても墓標は 1 基しか増えない。
- AC-205b: bfcache から復帰（`pageshow`）した場合、そのタブは再び生存する苗として
  庭に戻り、以後の通常終了も正しく記録される。

### FR-206 埋葬済みIDの自己修復

生存リストに、既に墓標が存在する ID の苗が現れた場合は表示・保存から除外する
（クロスタブの最終書き込み優先による一時的な蘇りを打ち消す）。

## 4. 永続化の堅牢性

### FR-300 ストレージの機能検出

`localStorage` は**存在確認ではなく機能検出**（`typeof s.setItem === 'function'` かつ
実際に書き込みを試行）で判定する。使用不可の場合はメモリ内フォールバックに退避し、
アプリは単一タブ・非永続モードとして動作を継続する（クラッシュしない）。

- AC-300a: プライベートモード等で `localStorage` が使えなくても画面が表示され操作できる。
- AC-300b: フォールバック時、その旨がUIに1行表示される（黙って壊れない）。

### FR-301 スキーマ検証

読み込んだ JSON は配列であることに加え、**要素ごとに必須フィールドの型を検証**し、
不正なレコードは黙って捨てる。破損データでアプリ全体が落ちてはならない。

- AC-301a: `tgg:plants:v1` に `"not json"` や `[{"broken":true}]` が入っていても
  例外を投げず、空の庭として起動する。

### FR-302 容量上限

墓標は最大 `MAX_GRAVEYARD` (=200) 件。超過時は古い順に破棄する。
書き込みが `QuotaExceededError` で失敗した場合は墓標を半分に切り詰めて 1 度だけ再試行する。

- AC-302a: 墓標が 200 を超えても書き込みが失敗せず、最新 200 件が保持される。

## 5. 放置ゲーム性（本実装での強化点）

> ユーザーフィードバック 1「放置系インクリメンタルゲームでもある」への対応。
> 進行が実時間に紐づく／閉じても記録として残る／じわじわ育つ・朽ちる過程を眺める、
> という3点を損なわず強化する。スコープは単発・小規模の範囲に収める。

### FR-400 通算記録 (Lifetime Ledger)

「庭を焼き払う」でリセットされない通算記録を保持する。放置ゲームの
「積み上がったものは消えない」感覚を担保するための中核データ。

```ts
interface LifetimeLedger {
  totalPlanted: number;        // 通算で芽吹いた苗の数
  totalBuried: number;         // 通算で埋葬した苗の数
  longestNeglectMs: number;    // 通算の最長放置（実ms）
  longestLifespanMs: number;   // 通算の最長生存（実ms）
  burnCount: number;           // 庭を焼き払った回数
  firstPlantedAt: number|null; // 最初の苗の植栽時刻
  unlocked: string[];          // 解除済み実績ID
}
```

- AC-400a: 庭を焼き払っても `totalPlanted` / `totalBuried` / 各最長記録は減らない。
- AC-400b: 通算記録は単調非減少である（`burnCount` を除き、いかなる操作でも減らない）。
- AC-400c: 通算記録を消すには、焼き払いモーダル内の明示的なトグルを ON にする必要がある。

### FR-401 罪の階級 (Rank)

`totalBuried`（通算埋葬数）で決まる階級を、**次の階級までの進捗つき**で表示する。
放置ゲームにおける進行の背骨。

| 階級 | 必要な通算埋葬数 |
|---|---|
| 無垢 | 0 |
| 軽犯罪 | 1 |
| 常習犯 | 3 |
| 重罪人 | 6 |
| 庭の破壊神 | 11 |

- AC-401a: 最高階級では「次の階級」ではなく到達済みである旨を表示する（進捗バーが
  100%のまま張り付いた見た目にしない）。

### FR-402 実績 (Achievements)

達成条件を満たすと解除されるスタンプ。全 10 種。解除は不可逆。

| ID | 名称 | 条件 |
|---|---|---|
| `first-sprout` | 最初の罪 | 通算1本植えた |
| `first-grave` | 初めての葬儀 | 通算1基埋葬した |
| `five-alive` | 同時多発 | 同時に5本生存させた |
| `ten-alive` | 二桁の罪 | 同時に10本生存させた |
| `full-bloom` | 満開 | 苗を満開まで育てた |
| `first-wilt` | しおれの兆し | しおれ段階に到達させた |
| `fossil-hunter` | 化石発掘 | 化石化まで放置した |
| `ghosted` | 音信不通 | ゴースト判定で埋葬された |
| `gravekeeper` | 墓守 | 通算10基埋葬した |
| `arsonist` | 放火魔 | 庭を焼き払った |

- AC-402a: 新規解除時にトースト通知が1回だけ出る（同じ実績で再通知しない）。
- AC-402b: 未解除の実績も名称と条件が見える（何を目指せばよいか分かる）。
- AC-402c: 実績の解除判定は純粋関数であり、現在状態と通算記録のみに依存する。

### FR-403 墓標の経過時間

墓標には「埋葬からの経過時間」を表示し、tick ごとに更新する。庭に生存中の苗が
1本もなくても、画面上で時間が進み続けていることが分かるようにする。

## 6. 初見での理解（本実装での強化点）

> ユーザーフィードバック 2「アプリ単体で何をするアプリか伝わりにくい」への対応。

### FR-500 初回説明パネル

初回訪問時、庭の上部に説明パネルを表示する。3ステップ（①タブを開くと苗が生える
②放置するとしおれる ③閉じると墓標が残る）を、実際の苗SVGを使った図で示す。

- AC-500a: 画面を覆うブロッキングモーダルにはしない（庭そのものが最初の説明になる
  ため、庭を隠さない）。
- AC-500b: 閉じると `tgg:intro-seen:v1` に記録し、次回以降は自動表示しない。
- AC-500c: ヘッダーの「これは何？」ボタンでいつでも再表示できる。
- AC-500d: 「庭を焼き払う」では初回説明フラグをリセットしない（説明の再表示は
  焼き払いの目的ではない）。

### FR-501 一文での説明

ヘッダーに、コアループを一文で述べたコピーを常設する。
初見のユーザーがスクロールせずに「タブを開くと苗が生え、放置するとしおれる」と
理解できること。

### FR-502 空状態

苗が0本・墓標が0基のときに、次に何をすればよいかを述べた空状態を表示する。

### FR-503 README

README 冒頭で、コアループ・遊び方・放置ゲームとしての側面が伝わるようにする。

## 7. ビジュアル要件

### FR-600 スタイル方向の維持

ネオブルータリズムを維持する。堅牢化・テスト容易性を理由にデザインを薄めない。

- 太い黒枠（3/4/6px）、ぼかしゼロのオフセット影のみ、角丸は一切使わない
- 配色: 生成り紙色 `#f2e9d8` ベース ＋ からし色 `#e8a93a` / 警告レッド `#d64545` /
  庭グリーン `#3f7d4e` のベタ塗り3色。グラデーション・パステル不使用
- 色は装飾ではなく意味を持つ（緑=健康、からし=注意/しおれ、赤=危険/墓標、灰=枯死）
- 書体3種の使い分け: `Archivo Black`（見出し）/ `Space Grotesk`（本文・UI）/
  `JetBrains Mono`（統計・時刻・墓碑銘）
- モーションは状態遷移にのみ使う（しおれ角度・彩度、ボタンの押し込み、墓標のホバー浮き）

- AC-600a: 新規追加UI（実績・階級・初回説明・トースト）も上記の言語に従う。
  ライブラリのデフォルト外観をそのまま使わない。
- AC-600b: `husk` / `fossil` 段階にも専用の配色を与え、`dead` と見分けがつく。

### FR-601 視覚検証

実装後、`visual-qa` スキルの検証項目を数値で裏取りする。

- 境界線が実際に視認できるコントラストを持つか
- UIチャンクの `line-height` 継承崩れがないか
- 対称であるべき装飾が実際に対称か
- `overflow: hidden` / `clip-path` による意図しないクリップがないか
- 長い実データ（40字の名前・80字の言い訳）でレイアウトが崩れないか
- カスタムフォントが実際に読み込まれ適用されているか

- AC-601a: 上記の各項目について、目視ではなく計測値で合否を記録する。

### FR-602 アクセシビリティ

- すべての操作可能要素にキーボードでの `:focus-visible` 表示がある
- 装飾SVGは `aria-hidden`、意味を持つ状態変化はテキストでも表現される
- 実績トーストは `role="status"` で読み上げ可能

## 8. 品質要件

### FR-700 テスト

- Vitest + jsdom。行カバレッジ **80% 以上**（`src/` 全体）
- 純粋ロジック（時間・段階・階級・実績・通算記録・庭の状態遷移）は単体テスト必須
- 破損データ・ストレージ不能・容量超過の各異常系にテストがあること

### FR-701 ビルド

- `npm run build` が型エラー 0 で `dist/` に静的ファイル一式を出力する
- `vite.config.ts` の `base: './'` を維持（GitHub Pages のサブパス配信のため）

### FR-702 コンテナ

- マルチステージ Dockerfile（build → `nginx:alpine` が `dist/` を配信）が実際にビルドでき、
  起動して 200 を返す

### FR-703 デプロイ設定

- `deploy.json` は `{"pages": true}`（バックエンド不要のため GitHub Pages プレビュー対象）

### FR-704 コード構成

- 1ファイル 200 行程度、最大 800 行
- DOM・ストレージ・時刻に依存しない純粋ロジックを `domain/` に分離し、副作用を持つ
  配線を `main.ts` に閉じ込める
