# クリップボード詩人 — Clipboard Poet

セッション中に `Ctrl+V` / `Cmd+V` で貼り付けたテキスト断片を、80〜90年代のPOS／ラベルプリンター筐体を模したツールが感熱レシートへ印字し続けます。「行分割」「トリミング」「シャッフル」という3つのルールベース処理（AIによる文章生成は一切使いません）を通して、貼り付けた断片をその場限りの「見つけ詩（found poem）」に組み替えます。

本プロトタイプは **app-factory パイプラインによって自律生成されたプロトタイプ** です（アイディア出し〜コンセプト具体化〜実装〜検証までを専門エージェント群が一括で実行しています）。

## 遊び方

1. 画面上部の筐体はどこにフォーカスがなくても構いません。ページ上で `Ctrl+V`（Macは`Cmd+V`）を押すと、クリップボード内のテキストが感熱紙にドットマトリクス風に印字されます。
2. 3つのトグルスイッチで組版ルールを切り替えられます。
   - **LINE BREAK（行分割）**: 句読点（。！？.!?）と改行位置で行・フレーズに分割します。
   - **TRIM（トリミング）**: 行を短・中・長に分類し、短い行はそのまま、長い行はランダムな連続区間を省略記号付きで切り出します。
   - **SHUFFLE（シャッフル）**: 行のプールをFisher-Yatesでシャッフルし、短い行→スタンザ→空行というパターンで再配置します。短い行が2つ以上あれば1行をリフレインとして冒頭・末尾に再利用します。
3. 赤い「詩を刷る」ボタンを押すと、その時点までに貼り付けた全断片＋現在のトグル設定から新しい詩を生成します。**同じ断片プールでも、押すたびに違う詩になります**（毎回新しい乱数シードを使うため）。
4. 生成された詩は「◆ FOUND POEM No.XX ◆」のスタンプ枠付きで印字され、生ログと視覚的に区別されます。
5. 各詩には「コピー / COPY」（プレーンテキストをクリップボードへ）と「切り取る / PNG」（詩の部分をPNG画像として書き出し）のボタンがあります。これがセッション内で唯一の永続的な持ち帰り手段です。
6. 「オールカット」ボタンで、紙を切る演出とともに蓄積済みの断片・印字ログをすべて消去できます。

## プライバシー・一期一会について

貼り付けた内容・生ログ・生成済みの詩は、すべてメモリ上のみで保持されます。`localStorage` / Cookie / サーバーへの送信は一切行いません。ページをリロードするかタブを閉じると、すべてのデータが完全に消えます（切り取ったPNG・コピーしたテキストのみ手元に残ります）。

## 技術スタック

- Vite + TypeScript（フレームワークを使わない素のDOM操作）
- フォント: [VT323](https://fonts.google.com/specimen/VT323)（LEDカウンター）、[DotGothic16](https://fonts.google.com/specimen/DotGothic16)（レシート印字・日本語対応）、[Oswald](https://fonts.google.com/specimen/Oswald)（英字ラベル）、[Zen Kaku Gothic New](https://fonts.google.com/specimen/Zen+Kaku+Gothic+New)（日本語UIラベル。OS標準の日本語フォントに依存せず確実にレンダリングするためバンドル）
- PNG書き出しはCanvas 2D APIで手描き（外部ライブラリなし）
- 完全クライアントサイド完結。バックエンドなし、外部APIなし、音声演出なし

## 開発

```bash
npm install
npm run dev      # 開発サーバー
npm run build    # 型チェック + 本番ビルド（dist/ に静的サイト一式を出力）
npm run preview  # ビルド結果をローカルで確認
```

## Docker

静的サイトなので、マルチステージビルドで `nginx:alpine` から配信します。

```bash
docker build -t clipboard-poet .
docker run --rm -p 8080:80 clipboard-poet
# http://localhost:8080 で確認
```

## スコープ外（プロトタイプゆえの割り切り）

- 貼り付けテキストのサーバー送信・永続保存は一切行いません（仕様）。
- AI/LLMによる詩の生成・言い換えは行いません。行分割・トリミング・シャッフルは断片の長さ・句読点・改行位置のみを手がかりにした決定的なルールベース処理です。
- アカウント・ログイン・複数セッションにまたがる履歴はありません。
- 貼り付け前のテキスト編集UI・音声効果・生成した詩の共有機能（SNS投稿等）は実装していません。
- `Ctrl+V` というキーボード操作が前提の体験のため、スマートフォンでの貼り付けUXは作り込みの対象外です（レイアウト自体はレスポンシブ対応済み）。
