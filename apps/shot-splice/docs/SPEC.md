# SPEC: SHOT SPLICE — スクリーンショット継ぎ足しツール（本実装）

**Feature ID**: 004-shot-splice
**Status**: Approved（本実装）
**Last updated**: 2026-09-01
**前身**: app-factory 由来のプロトタイプ 3 本（`shot-splice-darkroom` / `shot-splice-grid` / `shot-splice-brutal`）。
本実装は **アルゴリズムのみを継承し、UI・デザインはゼロから設計し直す**。

---

## 1. 概要

縦に分割して撮った複数枚のスクリーンショットを、重なり部分を自動検出して 1 枚の縦長画像に継ぎ直すツール。
すべての処理をブラウザ内（Canvas 2D）で完結させ、画像は一切外部に送信しない。バックエンド・認証・保存機能を持たない。

プロトタイプからの本質的な変更点は 4 つ：

| # | プロトタイプ | 本実装 |
|---|---|---|
| 1 | デスクトップ前提（左サイドバー + 中央ステージ） | **モバイルファースト**（375/390/428 を主ターゲット、片手・タッチ操作前提） |
| 2 | 上下 2 枚固定 | **任意枚数（2〜12 枚）の順序付き画像列** |
| 3 | 固定ヘッダー/フッターのカット px を手入力 | **全画像に共通する固定帯を自動検出**し、提示した上で適用（解除・微調整可） |
| 4 | 3 種のデスクトップ的スタイル | **iOS ライクな質感を土台にした独自の視覚方向**（§7） |

### 1.1 継承する技術的教訓（必須）

`shot-splice-grid` の粗探索は当初、画像の**高さも**縮小していた。
スクリーンショットの真の継ぎ目は「1px ずれただけでコストが跳ね上がる鋭いスパイク」として現れるため、
高さ方向に平均化するとこのスパイクが隣接行へ滲み、探索が別の位置を指す不具合が起きた。

**本実装でも、粗探索において行方向の平均化（縮小）を行ってはならない。**
高速化は「幅の縮小」と「行の間引き（サンプリング）」で行う。間引きは平均化と違い、
1px ずれたときに比較対象の行内容が入れ替わるため、スパイクは保存される（FR-104 / AC-104）。

## 2. 用語

| 用語 | 定義 |
|---|---|
| **ショット** | 読み込んだ 1 枚の画像。順序を持つ列 `S0 … S(n-1)` を成す |
| **継ぎ目 (seam)** | 隣接するショット `Si` と `Si+1` の境目。継ぎ目は n-1 個ある |
| **重なり (overlap)** | 継ぎ目で共有される行数（px）。`Si` の下端 h 行と `Si+1` の上端 h 行が同一内容 |
| **共通ヘッダー帯 / 共通フッター帯** | 全ショットの上端 / 下端に共通して現れる固定領域（ステータスバー・ナビゲーションバー等） |
| **一致度 (cost)** | 重なり領域のグレースケール平均絶対差。0 に近いほど一致 |
| **ルーペ** | 継ぎ目の周辺だけを等倍で表示する検証ビュー |

## 3. 機能要件

### 3.1 画像の読み込みと管理

- **FR-001** ファイル選択（`<input type="file" multiple accept="image/*">`）で複数画像を一度に追加できる。
- **FR-002** ドラッグ&ドロップで複数画像を追加できる（デスクトップ）。ドロップ領域は視覚的に反応する。
- **FR-003** 追加された画像は選択順（ドロップ時はファイル名の自然順）で列末尾に追加される。
- **FR-004** ショットは 2 枚以上で合成可能。**上限は 12 枚**。上限超過分は追加されず、理由を明示する。
- **FR-005** 各ショットを個別に削除できる。削除後は残りのショットで継ぎ目を再構成する。
- **FR-006** ショットの順序を変更できる。手段は 2 系統を**両方**提供する。
  - **FR-006a** 前後入れ替えボタン（各ショットに「◀ / ▶」相当、44pt 以上）
  - **FR-006b** 長押し（200ms）起動のポインタドラッグによる並べ替え。ページの縦スクロールと競合しないよう、長押しが成立するまでドラッグを開始せず、成立前に一定距離（8px）動いたらスクロール操作とみなして中止する
- **FR-007** すべてクリアする操作を提供する。誤操作防止のため確認を挟む。
- **FR-008** 画像以外のファイル、デコードできない画像は個別にスキップし、何がスキップされたかを通知する。他の正常な画像の読み込みは継続する。
- **FR-009** 幅の異なる画像が混在する場合、先頭ショットの幅を基準に他をアスペクト比維持でスケールする。基準幅と異なる画像があったことをユーザーに通知する。

### 3.2 重なりの自動検出

- **FR-101** 隣接ペアごとに、グレースケール行差分の最小化により重なり px を検出する。
- **FR-102** 探索は 2 段階とする。
  - 粗探索: 幅を 100px 相当に縮小（**高さは原寸のまま**）し、候補となる重なり量を走査する
  - 精密探索: 粗探索の最良候補の近傍のみをフル解像度で 1px 刻みに再評価する
- **FR-103** 粗探索の計算量は、候補数の上限（既定 4000）と、1 候補あたりの比較行数の上限（既定 256 行のサンプリング）で抑える。
- **FR-104** 粗探索では**行の平均化・縮小を行わない**。高速化は幅の縮小と行の間引きのみで行う（§1.1）。
- **FR-105** 探索範囲は `MIN_OVERLAP_PX`（既定 8）以上、隣接 2 ショットの短い方の高さの 95% 以下とする。
- **FR-106** 検出結果には一致度 `cost` と、`cost` が閾値（既定 12.0）以下かを表す `matched` を含める。
  `matched === false` の場合は「重なりを検出できなかった」として扱い、重なりを 0 とした上でユーザーに手動調整を促す。
- **FR-107** 全継ぎ目の一括自動検出を実行できる。実行中は進捗（何番目の継ぎ目を処理中か）を表示し、UI を固まらせない。
- **FR-108** 個別の継ぎ目のみを再検出できる。

### 3.3 共通ヘッダー / フッターの自動検出とカット

- **FR-201** 全ショットを基準幅に揃えた上で、**上端から連続して全ショット間で一致する行数**を共通ヘッダー帯の高さとして検出する。同様に下端からの連続一致行数を共通フッター帯とする。
- **FR-202** 行の一致判定は、全ショットの当該行のグレースケール平均絶対差が閾値（既定 6.0）以下であることとする。
- **FR-203** 検出結果には上限を設ける。ヘッダー帯・フッター帯はそれぞれ**最短ショット高さの 25% を超えない**。
  これは全面が単色のスクリーンショットや完全に同一な画像で、画像全体が「共通帯」と誤判定されるのを防ぐため。
- **FR-204** 検出された帯は**必ずユーザーに見える形で提示する**。無言・不可逆にカットしてはならない。
  - 検出結果（ヘッダー N px / フッター M px）を数値で表示する
  - 適用のオン・オフを切り替えられる
  - 適用値を 1px 単位で手動調整できる（0 以上、上限は FR-203 と同じ）
- **FR-205** カットの適用範囲は既定で「継ぎ目に隣接する側のみ」とする。すなわち：
  - ショット `Si`（i > 0）の上端から ヘッダー帯をカット
  - ショット `Si`（i < n-1）の下端から フッター帯をカット
  - 先頭ショットのヘッダーと末尾ショットのフッターは残す（完成画像の最上部・最下部に 1 回だけ現れるのが自然なため）
- **FR-206** FR-205 の挙動は「先頭/末尾も含めてすべてカットする」に切り替えられる。
- **FR-207** ショットの追加・削除・並べ替えが起きたら共通帯を再検出する。ユーザーが手動調整した値がある場合は上書きせず、再検出値との差異を提示する。

### 3.4 手動調整

- **FR-301** 継ぎ目ごとに重なり px を手動で調整できる。手段は以下すべてを提供する。
  - **FR-301a** ポインタドラッグ（マウス / タッチ / ペンを Pointer Events で統一的に扱う）による連続調整
  - **FR-301b** 数値入力（キーボード）
  - **FR-301c** ステッパーボタン（±1 / ±10）
  - **FR-301d** 数値入力にフォーカスがある間の矢印キー（Shift で 10px 単位）
- **FR-302** 調整値は `0` 以上、当該ペアの `maxOverlapPx` 以下にクランプされる。
- **FR-303** 調整中はルーペ表示がリアルタイムに追従する（60fps 目標、rAF で間引く）。
- **FR-304** 継ぎ目ごとに、重なり領域でどちらのショットを前面に出すかを選択できる（`前 = 上側` / `前 = 下側`）。

### 3.5 検証（差分表示）

- **FR-401** 継ぎ目ごとに差分表示モードへ切り替えられる。重なり領域に 2 枚の絶対差分を描画し、完全一致なら黒くなる。
- **FR-402** 差分表示は**フル解像度**で行う。プレビュー全体は縮小描画するため、差分は継ぎ目周辺を切り出したルーペ上で等倍表示する。
- **FR-403** 一致度を数値（`Δ` 値）とラベル（一致 / ほぼ一致 / 要調整）で示す。ラベルは色と連動する（§7 の意味論的配色）。

### 3.6 プレビューと出力

- **FR-501** 合成結果のプレビューを常時表示する。プレビューは表示幅に合わせた縮小キャンバスで描画し、フル解像度の合成キャンバスは生成しない（性能・メモリ・Canvas 面積上限のため）。
- **FR-502** 出力サイズ（幅 × 高さ px）、総重なり px、ショット枚数を数値表示する。
- **FR-503** PNG として書き出せる。ファイル名は `shot-splice-YYYYMMDD-HHMMSS.png`。
- **FR-504** 書き出し時のみフル解像度の合成キャンバスを生成する。
- **FR-505** 出力ピクセル数がブラウザの Canvas 面積上限に近づく場合（既定閾値 `16,777,216 px²`）、書き出し前に警告を表示する。書き出しに失敗した場合は原因と対処（枚数を減らす等）を提示する。

### 3.7 状態・フィードバック（体験品質）

- **FR-601** 空状態（画像なし）に、何をするアプリかと最初の操作が分かる表示を置く。
- **FR-602** 画像 1 枚のみの状態（合成不可）に、あと 1 枚必要であることを示す表示を置く。
- **FR-603** 画像デコード中・自動検出中はローディング状態を表示する。裸の空白で止まって見えてはならない。
- **FR-604** エラー（デコード失敗・書き出し失敗・上限超過）は、原因と次にすべきことが分かる文言で表示する。
- **FR-605** 成功（読み込み完了・検出完了・書き出し完了）にもフィードバックを出す。
- **FR-606** すべての操作結果は 1 つのライブリージョン（`aria-live="polite"`）に集約し、スクリーンリーダーにも伝わるようにする。

## 4. 非機能要件

- **NFR-001** バックエンド不要。完全クライアントサイド。画像は外部へ送信しない。ネットワークリクエストを一切発生させない（フォントも Web フォントを読み込まずシステムフォントのみを使う）。
- **NFR-002** モバイルファースト。375 / 390 / 428 の幅で横スクロールが発生してはならない。デスクトップ幅（1024 以上）は二次的なリフローとして成立させる。
- **NFR-003** タップターゲットは 44 × 44 CSS px 以上。
- **NFR-004** `env(safe-area-inset-*)` を尊重し、ノッチ・ホームインジケータに UI が潜り込まない。
- **NFR-005** Pointer Events で実装し、マウス・タッチ・ペンで同一の操作性を得る。タッチ操作中の意図しないスクロール・ズームを `touch-action` で抑止する。
- **NFR-006** `prefers-reduced-motion: reduce` でモーションを無効化する。
- **NFR-007** 単体テストのカバレッジ 80% 以上。アルゴリズム（重なり検出・共通帯検出・レイアウト計算）は Canvas に依存しない純粋関数として実装し、フルにテストする。
- **NFR-008** ビルド成果物は `dist/` に出力し、GitHub Pages のサブパス配信に対応する（Vite `base: './'`、`deploy.json` は `{"pages": true}`）。
- **NFR-009** マルチステージ Dockerfile（build → `nginx:alpine`）でコンテナ化する。
- **NFR-010** §7 の視覚方向は、実装・テストの都合で薄めてはならない。Anti-Template Policy に適合すること。
- **NFR-011** ショット 5 枚（各 1179×2556 相当）で、一括自動検出が 3 秒以内に完了すること。

## 5. アーキテクチャ境界（テスト可能性のための設計制約）

Canvas 2D は jsdom に存在しないため、以下の分離を**設計上の必須制約**とする。

```
src/
├── core/          … 純粋関数のみ。DOM / Canvas に一切依存しない（テスト対象の中心）
│   ├── types.ts
│   ├── gray.ts        GrayImage 型と行差分プリミティブ
│   ├── alignment.ts   detectOverlapGray(top, bottom, opts) -> AlignmentResult
│   ├── banding.ts     detectCommonBands(grays, opts) -> BandDetection
│   ├── layout.ts      computeLayout(shotSizes, overlaps, cuts) -> Layout
│   └── naming.ts      出力ファイル名など
├── imaging/       … Canvas 依存。core との変換層に限定
│   ├── canvas.ts      HTMLImageElement -> Canvas, crop, scale
│   ├── grayscale.ts   Canvas -> GrayImage（幅縮小あり/なし）
│   └── compose.ts     Layout に従って描画（narrow interface 経由）
├── ui/            … DOM。表示と入力
└── main.ts        … 配線のみ
```

`core` は `HTMLCanvasElement` を import してはならない。`imaging/compose.ts` の描画対象は
実際に使うメソッドだけを列挙した構造的部分型（`Ctx2DLike` / `CanvasLike`）に依存させ、テストでフェイクを注入できるようにする。

## 6. データモデル

```ts
type ShotId = string;

interface Shot {
  readonly id: ShotId;
  readonly name: string;
  readonly image: HTMLImageElement;   // 原寸
  readonly width: number;
  readonly height: number;
}

interface SeamState {
  readonly overlapPx: number;
  readonly maxOverlapPx: number;
  readonly cost: number | null;       // 未検出は null
  readonly matched: boolean;
  readonly front: 'upper' | 'lower';
}

interface BandState {
  readonly detectedHeaderPx: number;  // 自動検出の生値
  readonly detectedFooterPx: number;
  readonly headerPx: number;          // 実際に適用される値（手動調整後）
  readonly footerPx: number;
  readonly enabled: boolean;
  readonly manuallyEdited: boolean;
  readonly trimEnds: boolean;         // FR-206
}
```

`AppState` はこれらと `shots: Shot[]`、`seams: SeamState[]`（長さ = shots.length - 1）、`bands: BandState`、
`activeSeamIndex: number | null`、`diffMode: boolean`、`status` を保持する。
状態更新は必ず新しいオブジェクトを返す（イミュータブル）。

## 7. 視覚方向（決定事項 / `frontend-design` 適用結果）

### 7.1 方向: **SPLICE BAY — 編集室のスプライサー**

フィルムを物理的に繋ぐ編集機材の質感を、iOS のマテリアル感で再構成する。
「計測して合わせる」行為が主題なので、**数値が主役**になる階層を組む。
既存 3 プロトタイプ（暗室レッド / スイス・オフホワイト / ネオブルータリズム）とは配色・書体・構図すべてを分ける。

### 7.2 配色（意味論的に使う。装飾で色を足さない）

| トークン | 値 | 役割 |
|---|---|---|
| `--bg` | `oklch(15.5% 0.014 264)` | 地。純黒にせず青みを残し、画像内の黒と区別できるようにする |
| `--surface-1` | `oklch(20% 0.014 264)` | カード |
| `--surface-2` | `oklch(25.5% 0.015 264)` | カード内の内包面・シート |
| `--hairline` | `oklch(100% 0 0 / 0.10)` | 境界線。地に埋もれないことを実測で確認する |
| `--text` | `oklch(96% 0.004 264)` | 主テキスト |
| `--text-dim` | `oklch(70% 0.008 264)` | 副次テキスト |
| `--align` | `oklch(80% 0.13 183)` | **シアン＝一致している**。整列済みの継ぎ目・成功状態 |
| `--drift` | `oklch(80% 0.14 76)` | **アンバー＝ずれている**。要調整の継ぎ目・警告 |
| `--danger` | `oklch(64% 0.19 22)` | 破壊操作（削除・全クリア） |

一致度は `--drift` → `--align` を連続補間して継ぎ目インジケータの色に反映する。
**色は「今どれくらい合っているか」を表す情報チャネルであり、装飾ではない。**

### 7.3 タイポグラフィ

- UI: `-apple-system, BlinkMacSystemFont, "Segoe UI", "Hiragino Sans", "Noto Sans JP", system-ui, sans-serif`
  （Apple 端末では実際に San Francisco が表示される。フォントファイルはバンドルしない = NFR-001）
- 数値: `ui-monospace, "SF Mono", SFMono-Regular, Menlo, monospace` + `font-variant-numeric: tabular-nums`
- **スケールのコントラストを強くつける**: 本文 15px に対し、重なり量の readout は 40px 相当の mono。
  桁が変わっても幅が揺れない（tabular-nums）ことが「計測器」の質感を作る。
- 見出しは iOS の Large Title 相当（34px / -0.4px トラッキング / weight 700）を 1 箇所だけに使う。

### 7.4 レイアウトと構図

- 縦 1 列のスクロール。左サイドバーは持たない。
- **プレビューステージ**は画面上部に `position: sticky` で貼り付き、高さ 38svh。常に結果が見える。
- **リール**（ショットと継ぎ目を織り交ぜた縦 1 列）が画面の主要部分。
  `ショット → 継ぎ目 → ショット → 継ぎ目 → ショット` の順で交互に並べ、フィルムの 1 本のストリップに見せる。
  ショット行はサムネイル・連番・ファイル名・実寸、継ぎ目行は一致度バーと重なり px（大きい mono）で構成する。
  - **当初案（横スクロールのフィルムストリップ ＋ 別立ての継ぎ目カード）から変更した。** 理由は 2 つ。
    (1) 幅 375px で 44pt のタップターゲットを 3 つ（削除・前へ・後へ）横並びに置くと、サムネイルが判別不能な幅になる。
    (2) 継ぎ目は「どのショットとどのショットの間か」でしか意味を持たないのに、別リストに置くと関係が読めない。
    縦の連続したリールなら、順序も隣接関係も 1 つの視線移動で読める。
  - 交互に現れる 2 種類の行（厚いショット行 / 薄い継ぎ目行）が、均一なカードグリッドを自然に崩す（Anti-Template 要件 7）。
    余白は均一にせず、継ぎ目の数値の上下だけ広く取る（リズム = 要件 2）。
  - サムネイル列を貫く縦線（splice line）が、ショットが 1 本に繋がっていることを示す。
- **調整シート**は iOS のボトムシート。ドラッグハンドル付き、上部にルーペ（等倍の継ぎ目拡大）、下部に操作系。
- **下部ツールバー**は `position: fixed` + `padding-bottom: env(safe-area-inset-bottom)`。

### 7.5 質感・奥行き

- 角丸: 大 22px / 中 14px / 小 10px。iOS 的に大きめ。
- カード上端に `inset 0 1px 0 oklch(100% 0 0 / 0.06)` のハイライトを入れ、面が起きているように見せる（重なり・奥行き = Anti-Template 要件 3）。
- 背景に SVG `feTurbulence` 由来の極薄ノイズ（opacity 0.03、data URI、ネットワーク不要）。
- プレビューステージの背後に、**読み込んだ画像の平均色から生成した淡いグロー**を敷く。
  扱っている画像に画面が呼応するため、汎用テンプレートには成立しない固有の表現になる。

### 7.6 モーション（意味のある動きだけ）

| 対象 | 挙動 |
|---|---|
| ボトムシート | spring 風 `cubic-bezier(0.32, 0.72, 0, 1)` / 340ms。ドラッグで追従し、閾値以下なら戻る |
| 自動検出の完了 | 対象の継ぎ目ラインが 1 回だけパルスし、色が `--drift` から `--align` へ遷移する。**どこが解決したかを示す** |
| ショットの追加 | フィルムストリップの末尾から差し込まれる（新しい要素の位置を教える） |
| ショットの削除 | 高さを畳んで消える（リストの再構成を理解させる） |
| 一致度バー | 値の変化を 180ms でイージングし、ドラッグ中の傾向が読めるようにする |

`prefers-reduced-motion: reduce` ではすべて即時遷移にする（透明度の変化のみ残す）。

## 8. 受け入れ基準（AC）

### アルゴリズム

- **AC-101** 既知の重なり量 h を持つ合成テスト画像ペアに対し、`detectOverlapGray` が h を**誤差 0px** で返す。
- **AC-102** 重なりのない 2 枚（無関係なノイズ画像）に対し、`matched === false` を返す。
- **AC-103** 完全に同一な 2 枚に対しても、探索上限（短辺の 95%）を超える値を返さず、クラッシュしない。
- **AC-104** 粗探索の間引きが有効な高さ（例: 重なり 1200px）でも、正解 ±0px で検出する。
  行を平均化する実装ではこのテストが落ちること（回帰テストとして機能すること）。
- **AC-105** ショット 3 枚以上の列に対し、継ぎ目ごとに独立して重なりが検出される。
- **AC-106** 高さが `MIN_OVERLAP_PX` 未満の極小画像を渡してもクラッシュせず、重なり 0 として扱われる。

### 共通帯検出

- **AC-201** 全画像の上端 88px / 下端 132px が同一な合成テスト画像列に対し、`detectCommonBands` が
  ヘッダー 88 / フッター 132 を返す。
- **AC-202** 全画像が完全に同一な場合、返る帯は最短高さの 25% でクリップされる（画像全体にならない）。
- **AC-203** 共通帯が存在しない画像列に対し、ヘッダー 0 / フッター 0 を返す。
- **AC-204** ショット 1 枚のみの場合、帯検出は 0 / 0 を返す（比較対象がないため）。
- **AC-205** 検出値がそのまま自動適用されるのではなく、UI 上に数値として提示され、
  トグルで無効化でき、手動で書き換えられる。

### レイアウト

- **AC-301** n 枚・重なり列 `o` に対する出力高さが `Σheight - Σo`（カット適用後）と一致する。
- **AC-302** 重なりが隣接ショットの高さを超える指定はクランプされ、出力高さが負にならない。

### UI / 体験

- **AC-401** 375 / 390 / 428 幅で横スクロールが発生しない（`documentElement.scrollWidth <= clientWidth`）。
- **AC-402** すべての操作要素の実測サイズが 44×44 CSS px 以上。
- **AC-403** タッチ（Pointer Events）で継ぎ目の重なりを調整でき、マウスと同じ結果になる。
- **AC-404** 空状態・1 枚状態・ローディング・エラー・成功のそれぞれに専用表示が存在する。
- **AC-405** 画像 3 枚を読み込み → 一括自動検出 → PNG 書き出し、までがコンソールエラー 0 件で完了する。
- **AC-406** `prefers-reduced-motion: reduce` でアニメーションが無効化される。

### 品質ゲート

- **AC-501** `npm run build` が成功する。
- **AC-502** `npm run test` が全通過し、カバレッジが 80% 以上。
- **AC-503** `docker build` が成功し、コンテナが画面を配信する。
- **AC-504** `deploy.json` が `{"pages": true}`、Vite の `base` が `'./'`。
- **AC-505** `visual-qa` の完了基準（境界線の知覚可能性・line-height 継承・意図した視覚効果の実測）を満たす。
