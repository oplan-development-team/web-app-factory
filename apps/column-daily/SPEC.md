# SPEC — The Column Daily (`apps/column-daily`)

ステータス: 確定（メインセッションとユーザー間で擦り合わせ済みの要件を反映）
起点: ユーザーがChatGPT Imageで生成した完成イメージ 1 枚
参考画像: `/Users/gijutsukaihatsushitsu/Downloads/ChatGPT Image 2026年8月28日 16_51_44.png`

---

## 1. 概要

ヴィンテージ新聞・エディトリアル意匠のコラムメディアサイト。読み物としてのコラムを
一覧・検索・閲覧できる、**バックエンドなしの完全クライアントサイド完結アプリ**。

投稿・認証はUIのみを実装し、実データの永続化・認証ロジックは持たない（見た目の完成度を
検証するためのメディアサイトであり、実運用のCMSではない）。

### 1.1 スコープ外（明示）

| 項目 | 扱い |
|---|---|
| サーバー / API / DB | 持たない |
| 実行時の外部APIフェッチ（画像含む） | 一切行わない |
| 認証・セッション・パスワード | 実装しない。認証情報を一切扱わない |
| 記事投稿の永続化 | しない（送信は成功表示のみのダミー） |
| 記事の編集・削除 | 実装しない |

## 2. 機能要件

### FR-01 記事データ

- ダミー記事を **18 件** 静的データ（TypeScript モジュール）として持つ。
- 1 記事のフィールド: `id` / `title` / `category` / `publishedAt` / `excerpt` / `body`(複数段落) /
  `author`(`name`) / `tags`(1〜4) / `readMinutes` / `popularity`(順位付け用スコア) /
  `series`(任意) / `isEditorsPick`(1 件のみ true)。
- カテゴリは次の 8 種に限定する:
  `ライフスタイル` `エッセイ` `仕事術` `フード` `旅` `暮らし` `カルチャー` `その他`
- 全記事が「カテゴリ」「著者」「日付」「タグ」を必ず持つ（欠損状態を作らない）。
- `series` を持つ記事が複数存在し、少なくとも 2 つの連載が成立すること。

### FR-02 記事画像

- 外部画像URL・実行時フェッチを使わない。**ビルド時に確定する静的表現**とする。
- 記事ごとに1枚、Picsum Photos（Unsplash由来、Unsplash License準拠）から選んだ写真を
  `src/assets/photos/` に静的バンドルし、`src/data/photos.ts` で記事IDと対応付ける。
- 同じ記事は常に同じ写真になること。

  > **改訂（2026-08-28）**: 初版はカテゴリ+記事IDから決定的に生成するインラインSVG
  > イラストだったが、参考画像が実写であるのに対し見た目の乖離が大きいとユーザーから
  > 差し戻しを受け、実写素材の静的バンドルに変更した。

### FR-03 ページ構成

| ルート | 内容 |
|---|---|
| `/` | トップ。参考画像のレイアウト（メイン特集 + 新着コラム 4 件 + サイドバー） |
| `/articles/:id` | 記事詳細 |
| `/category/:slug` | カテゴリー別一覧（8 カテゴリ分） |
| `/latest` | 新着コラム一覧（公開日降順・全件） |
| `/popular` | 人気コラム一覧（popularity 降順・全件） |
| `/series` | 連載一覧 |
| `/search` | 検索結果（クエリは `?q=`） |
| `/tag/:tag` | タグ別一覧（下記の仕様ギャップ対応で追加） |
| `/write` | コラムを書く（投稿フォームUI・保存しない） |
| `/login` `/register` `/mypage` | ダミー画面（認証ロジックなし） |

- 存在しない記事ID・カテゴリスラッグ・タグ・未定義ルートは、専用の「見つかりませんでした」表示に
  する（白画面・クラッシュにしない）。

**仕様ギャップと解決（実装中に検出）**: FR-04 はサイドバーに「注目のタグ」を要求しているが、
タグの遷移先が未定義だった。チップをクリックできない飾りにすると「押せそうで押せない」状態に
なるため、`/tag/:tag` を追加してタグ別一覧へ遷移させる。バックエンド不要・既存の
`articlesWithTag` セレクタで完結するため、確定要件の範囲を実質的に広げるものではない。

### FR-04 トップページ

参考画像の構成を踏襲する。

1. ユーティリティバー: 左に日付 + 天気アイコン + 気温、右に「ログイン / 会員登録」+ 検索ボックス
2. マストヘッド: 中央に大きなロゴ「The Column Daily」、その下にキャッチコピー
   「言葉がつくる、わたしの景色。」、左にサブコピー「さまざまな視点が／あたらしい気づきを生む」、
   右に「TODAY'S PAPER / 最新の注目コラムを毎日お届け」
3. ナビゲーション（紙色の帯。現在地と「マイページ」だけを墨色のピルで強調）: `トップ／新着コラム／人気のコラム／連載一覧／カテゴリー▾／コラムを書く`
   + 右端に強調ボタン「マイページ」
4. メイン特集: `EDITOR'S PICK` ラベル（朱色）、見出し・カテゴリタグ・日付・抜粋・著者
5. 新着コラム: 4 カラム（画像 + カテゴリタグ + タイトル + 著者 + 日付）、「もっと見る」→ `/latest`
6. サイドバー:
   - 人気ランキング 1〜5 位（番号を大きく見せる）、「もっと見る」→ `/popular`
   - カテゴリー一覧（アイコン付きグリッド、8 種）、「一覧を見る」
   - 注目のタグ

- 日付表示は**実行時の現在日付**を「YYYY年M月D日 曜日」形式で表示する。
- 天気は静的な表示（外部APIを叩かない）。

### FR-05 ナビゲーション「カテゴリー▾」

- ホバー / フォーカス / クリックで 8 カテゴリのドロップダウンを開く。
- キーボード操作（Tab で到達、Enter/Space で開閉、Escape で閉じる）に対応する。

### FR-06 検索

- ヘッダーの検索ボックスから、**記事タイトルに対する** クライアントサイド部分一致検索を行う。
- 大文字小文字を区別しない。前後の空白は無視する。
- 検索実行で `/search?q=<query>` に遷移し、結果件数と一覧を表示する。
- 0 件のときは空状態（該当なしの旨 + 全記事を見る導線）を表示する。
- 空文字での検索は実行しない。

### FR-07 コラムを書く（`/write`）

- 入力項目: タイトル（必須）/ カテゴリ（必須・8 種から選択）/ タグ（任意）/
  本文（必須）/ アイキャッチ画像アップロード（任意）。
- 必須項目が未入力のまま送信しようとした場合、**どの項目が足りないかを画面上に明示**する。
- 送信成功時は「投稿を受け付けました」相当のダミー成功表示に切り替える。
  **記事データには一切追加しない。** リロードすると元に戻る。
- 画像アップロードは、選択したファイル名 / プレビューをローカルで表示するに留める
  （どこにも送信しない）。

### FR-08 ログイン・会員登録・マイページ

- リンク / ボタンとして存在し、クリックで見た目だけのダミー画面へ遷移する。
- 「この画面はデモであり認証は行われません」旨を画面上に明記する。
- **パスワード等の認証情報入力欄は置かない**（扱わないことを保証するため）。

## 3. デザイン要件

`frontend-design` スキルを実装前に適用済み。方向は **エディトリアル（ヴィンテージ新聞）** 一本に
コミットする。

### DR-01 タイポグラフィ

| 用途 | フォント |
|---|---|
| ロゴ（マストヘッド） | `UnifrakturCook` 700（重厚な Old English 系ブラックレター） |
| 見出し・本文（和欧共通） | `Shippori Mincho`（400 / 700） |

- 読み込むファミリは 2 つまで。`font-display: swap`。
- 欧文ラベル（`TODAY'S PAPER` `EDITOR'S PICK` 等）は Shippori Mincho の欧文グリフを
  大文字 + レタースペーシングで使う。
- スケールに明確な差をつける（マストヘッド ≫ 特集見出し ＞ セクション見出し ＞ 本文 ＞ メタ）。

### DR-02 カラー

| トークン | 値 | 意味 |
|---|---|---|
| `--paper-base` | `#f2ece0` | 生成りの紙地 |
| `--paper-light` | `#faf6ec` | 面を持ち上げる紙 |
| `--paper-shade` | `#e8e0d0` | 沈めた紙 |
| `--ink` | `#1c1a17` | 主要な墨 |
| `--ink-soft` | `#453f37` | 従属テキスト |
| `--ink-mute` | `#7a7167` | メタ情報 |
| `--rule` | `#c9bfae` | 罫線 |
| `--vermilion` | `#6b1108` | オックスブラッド・アクセント |
| `--band` | `#211f1c` | ナビ現在地・マイページのピル、ランキング等の墨色ブロック |
| `--frame` | `#362d24` | ページ全体を載せる台紙（デスク）の濃茶色 |

- アクセント色は**意味を持つ場所にだけ**使う: `EDITOR'S PICK` ラベル / 必須項目マーク / エラー。
  装飾目的で撒かない。ナビの現在地・ランキング数字は墨色（`--band` / `--ink`）で統一し、
  アクセント色は使わない。

### DR-03 質感・装飾

- ページ全体は濃茶色の台紙（デスク）に載った1枚の紙として構成する。紙面（`.site-shell`）は
  角丸・ドロップシャドウを持つカードとし、紙質感（多層のラジアルグラデーション + SVG ノイズ +
  ヴィネット）はこのカードの内側にだけ敷く。ベタ塗りは禁止。
- 罫線・二重罫（`border: 3px double`）を新聞的な区切りとして活用する。
- 個々のコンポーネント（見出し・カード・ボタン等）の `border-radius` は原則 0
  （例外: 著者アバターの円、台紙カード自体、カテゴリータグの微小な丸み）。
- ドロップシャドウを多用しない。特集画像のみ、印刷版のような硬いオフセット枠を許容する。

### DR-04 レイアウト

- トップは `1fr / サイドバー` の非対称 2 カラム。
- マストヘッドは中央ロゴに対して左右に別内容を置く非対称構成（中央寄せ 1 本にしない）。
- 新着コラムは 4 カラムだが、浮いたカードではなく**新聞の段組**として縦罫で区切る。
- 余白は均一にしない。メタ行は詰め、セクション間は大きく空ける。

### DR-05 モーション

- 記憶に残る瞬間は 1 つ: 初回ロード時の「刷り上がり」演出
  （マストヘッドのインクが定着し、罫線が横に引かれる）。
- ホバーは、下線がインクのように左から引かれる / 紙の面がわずかに沈む。浮かせて影を落とさない。
- アニメーションは `transform` / `opacity` のみ。
- `prefers-reduced-motion: reduce` で全ての動きを無効化する。

### DR-06 Anti-Template Policy

次を満たすこと（最低 4 項目 → 全項目を狙う）:
階層のはっきりしたスケール差 / 意図のあるリズム / 重なりと奥行き / 個性のあるタイポグラフィ /
意味を持った配色 / 作り込まれた hover・focus・active 状態 / 段組を崩したエディトリアル構成 /
テクスチャと空気感。

禁止: 画一的なカードグリッド、中央寄せ + グラデーションブロブのヒーロー、ライブラリのデフォルト
そのまま、単調な余白・角丸・影、グレー基調 + 差し色 1 色だけ。

| ID | 要件 |
|---|---|
| UX-01 | 検索結果 0 件・カテゴリ 0 件に空状態を用意する（裸の空白にしない） |

| UX-06 | モーションはレイアウトシフト（CLS）を起こさない |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 技術スタック: Vite + React + TypeScript + `react-router-dom`。状態管理は素の React state |
| NFR-02 | TypeScript `strict: true`。`npm run build`（`tsc -b && vite build`）が警告なく通る |
| NFR-03 | JS バンドル gzip < 150kb、CSS < 30kb |
| NFR-04 | レスポンシブ: 375 / 768 / 1024 / 1440 で横スクロールが発生しない |
| NFR-05 | セマンティックHTML（`header` / `nav` / `main` / `article` / `aside` / `footer`）を用いる |
| NFR-06 | キーボードのみで全ページに到達・操作でき、フォーカスリングが視認できる |
| NFR-07 | 本文テキストの前景背景コントラストが 4.5:1 以上 |
| NFR-08 | 実行時のコンソールエラー 0 件 |
| NFR-09 | 秘密情報・APIキー・認証情報をコードに一切含めない |
| NFR-10 | `dangerouslySetInnerHTML` を使わない（XSS 経路を作らない） |

## 6. デプロイ要件

| ID | 要件 |
|---|---|
| DEP-01 | `apps/column-daily/Dockerfile`: `node:22-alpine` でビルド → `nginx:alpine` で `dist/` 配信のマルチステージ |
| DEP-02 | `apps/column-daily/deploy.json` を `{"pages": true}` にする |
| DEP-03 | `vite.config.ts` に `base: './'` を設定する |
| DEP-04 | `npm run build` が `dist/` に静的サイト一式を出力する |
| DEP-05 | GitHub Pages のサブパス配信（`/web-app-factory/column-daily/`）で全ルートが直接開けること |

**DEP-05 に対する設計判断**: GitHub Pages は SPA の history fallback を提供しない。
`base: './'` との組み合わせで確実に動く `HashRouter` を採用する
（`BrowserRouter` + 404.html ハックは採らない）。同じ成果物が nginx コンテナでもそのまま動く。

## 7. 受け入れ基準（AC）

| ID | 基準 |
|---|---|
| AC-01 | トップページが参考画像の構成（濃茶色の台紙に載った紙面 / ユーティリティバー / マストヘッド / 紙色ナビ+現在地とマイページの墨色ピル / 特集 / 新着4件 / サイドバー3ブロック）を再現している |
| AC-02 | 18 件の記事すべてが詳細ページで表示でき、本文・著者・カテゴリ・日付・タグが揃っている |
| AC-03 | 8 カテゴリすべての一覧ページが該当記事のみを表示する |
| AC-04 | `/latest` が公開日降順、`/popular` が人気順で全件表示する |
| AC-05 | 連載一覧が 2 つ以上の連載を表示し、各連載から記事へ遷移できる |
| AC-06 | タイトル検索が部分一致で機能し、大文字小文字を区別しない。0 件時に空状態が出る |
| AC-07 | `/write` で必須未入力時にエラーが出て、全項目入力時にダミー成功表示に切り替わる。記事一覧は変化しない |
| AC-08 | ログイン / 会員登録 / マイページがダミー画面として開き、認証を行わない旨が明示される。パスワード欄が存在しない |
| AC-09 | 不正な記事ID・カテゴリ・未定義ルートで Not Found 表示になり、クラッシュしない |
| AC-10 | 375 / 768 / 1024 / 1440 で横スクロールが発生しない |
| AC-11 | `prefers-reduced-motion: reduce` でアニメーションが止まる |
| AC-12 | `npm run build` がエラーなく完了する |
| AC-13 | `docker build` が成功し、コンテナ起動後にトップが表示される |
| AC-14 | ブラウザのコンソールに ERROR レベルのログが 0 件 |
| AC-15 | 実行時に外部ドメインへのネットワークリクエストが Google Fonts 以外に発生しない |
| AC-16 | DR-06 の Anti-Template 項目を 4 つ以上満たす |
