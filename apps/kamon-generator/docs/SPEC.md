# SPEC: 家紋帳 — オリジナル家紋ジェネレーター

**Feature ID**: 003-kamon-generator
**Status**: Approved (production implementation)
**Last updated**: 2026-08-24
**前身**: app-factory パイプラインによる自律生成プロトタイプ（同ディレクトリ）。本仕様はその本実装版。

---

## 1. 概要

名前・誕生日などの任意文字列を**シード**として、正円の中に左右対称／点対称の紋様を決定的に生成し、
「家紋帳の見開きページ」として提示する Web ツール。同一シードからは常に同一の紋様が再現される。

バックエンドを持たず、生成・描画・書き出しのすべてをブラウザ内で完結させる。入力文字列は一切外部に送信しない。

### 1.1 本実装の中心課題（この仕様が存在する理由）

プロトタイプの生成結果は、**「家紋」ではなく「小さな図形の散布」**になっていた。

| プロトタイプの実測値 | 帰結 |
|---|---|
| 線幅 1.6〜6px（viewBox 400 基準 = 直径の 0.4〜1.5%） | 遠目・縮小時に消える |
| 描画プリミティブ数 最大 42（単位図形 7 × 6 複製） | 視線の焦点が定まらない |
| 外周モチーフの半径 96〜138 に対し、モチーフ寸法 12〜22 | 円の中身がほぼ空白で、点が散っているだけ |
| 中心にモチーフが接触しない（半径 26〜54 に浮いている） | 一個の図として結像しない |
| 塗り確率 中心 60% / 外周 40% | 線画優位で、シルエットが立たない |

実在の家紋（五三桐・丸に三つ柏・丸に違い鷹の羽など）はこの逆を行く。
一次資料・解説から確認できる構成上の特徴は以下のとおり：

- **単色・高コントラスト前提**。白黒化しても形が識別できることが必須要件で、色や濃淡に依存しない
  （[紋章の書](https://heraldrybook.com/design/original-kamon-design)）
- **「余白・対称・反復・整列」の 4 要素**が紋らしさを決める。モチーフの充実度より、**見えない空間の設計**が支配的
  （同上）
- **主要線幅の実務目安は直径 1.5cm に対し 0.25〜0.5mm**、かつ**直径 1.5cm 内の交点は 8 点以下**に抑えると
  小サイズでの再現性が上がる（同上）。**直径比に換算すると線幅 1.7〜3.3%**
- 戦場での識別を起源とするため、**大胆な図形（bold graphics）による一目での識別性**が設計目的そのものである
  （[Japan House LA](https://www.japanhousela.com/articles/kamon-chronicles-the-secrets-of-japanese-family-crests-shogun-tokugawa/)、
  [Atelier Miyabi](https://ateliermiyabi.com/the-origins-of-kamon/)）
- **グラデーション・陰影を持たず、面と線だけで成立する**単色エンブレムである
  （[The Art of Zen](https://theartofzen.org/the-art-of-kamon/)）
- モチーフは**回転対称に再構成され、部分を省略・簡略化して図案性を強める**変形技法（割り出し法）で洗練されてきた
  （[彫金よろず](https://choukinyorozu.com/family-crest-design-meaning-20039.html)）

したがって本実装は、生成ロジックを**「小さな部品を円の中に散らす」から「少数の大きな面を中心で噛み合わせて 1 つの塊にする」**へ設計転換する。
これは見た目の微調整ではなく、生成モデルそのものの置換である（3.2 節 FR-2xx 系）。

### 1.2 視覚方向（維持する資産）

プロトタイプの**「家紋帳」＝ 和紙 × 朱の見開き書籍**というエディトリアル方向は本アプリのアイデンティティであり、維持・強化する。

- **地**: 和紙のオフホワイト（`#f7f1e3` / `#efe6d2`）／**インク**: 墨（`#241f18`）
- **アクセント**: 朱（`#c33a2e`）**のみ**。装飾ではなく機能要素（現在地・主要操作・エラー・割り出し線）に限定
- **書体**: 日本語 = Noto Serif JP、欧文・数字 = Cormorant Garamond（イタリックを図版番号に）
- **構図**: 左ページ = 編む（入力・図版帖）／中央 = 綴じ目の影／右ページ = 大きな紋 1 点
- **カード・角丸・均一グリッドを使わない**。階層はヘアラインと余白の強弱だけでつくる

この方向性は実装・テストの都合で薄めてはならない（NFR-006）。

### 1.3 対象ユーザー

- 自分・家族・屋号のための「あるようでない紋」を求める個人
- 同人・小規模ブランドで印章的なシンボルを必要とする層
- 家紋の意匠そのものに興味があり、生成結果を眺めて楽しみたい層

### 1.4 スコープ外（非目標）

| 項目 | 除外理由 |
|------|----------|
| 実在家紋データベースの収録・検索 | 権利・出典管理の負担が単発小規模アプリの前提を超える。本アプリは「実在紋に似た新しい紋」を作るもので、実在紋の再現器ではない |
| 任意カラーピッカー | 単色エンブレムであることが家紋の要件（1.1）。自由配色はその要件を壊す |
| ユーザーがモチーフを手で選ぶ編集モード | 「名前が紋になる」決定性が体験の核。手動編集は決定性の意味を失わせる |
| 円形以外の外郭（盾形・楕円など） | 「正円と直線から構成される」という家紋の骨格要件から外れる |
| アカウント登録・共有 URL・SNS 連携 | バックエンドが必要になる |
| 名刺・封筒・印鑑テンプレートへの合成 | 別アプリの領分 |
| 多言語 UI | 日本語のみ |

### 1.5 判断を要した任意要件（依頼事項 #5 への回答）

| 項目 | 判断 | 根拠 |
|---|---|---|
| **生成履歴の永続化** | **対応する**（localStorage） | 「帳（＝台帳）」というメタファの中核。閉じると白紙に戻る帳面は概念矛盾である。かつ**決定的生成器なのでシード文字列とバリアント番号だけを保存すれば図版は完全に復元でき**、保存コストが極小で済む（FR-007） |
| **PNG 書き出し** | **対応する** | SVG を扱えない投稿先・入稿先が実用上多く、書き出し機能の到達点が SVG だけでは片手落ち。外部依存なしに Canvas で完結できる（FR-008.3） |

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| シード（種） | 入力文字列（名前 / 誕生日等）を結合した文字列。紋の同一性の根拠 |
| バリアント | 同一シードから別解を得るための連番（0 起点）。`seed::variant:N` をハッシュする |
| 構造（KamonStructure） | 色情報を含まない、紋の幾何構造の完全記述。同一シード・同一バリアントから常に同一 |
| 外郭（enclosure） | 紋を囲む輪。`丸` / `二重丸` / `隅切り角` / `亀甲` / `無し` |
| 紋様域（field） | 外郭の内側で、モチーフが占めてよい正円領域。半径 `R_INNER` |
| モチーフ（motif） | 紋を構成する意匠単位（柏・桐・鷹の羽・巴 等）。14 種を登録 |
| 単位（unit） | 複製の基本となるモチーフ 1 個 |
| 構成（composition） | 単位の配置法則。`放射` / `単独` / `違い` / `連環` の 4 種 |
| 白抜き（negative cut） | 塗り面の内部に開けた穴（葉脈・羽の筋・輻など）。`fill-rule="evenodd"` の副パスで表現 |
| 座（center seat） | 紋の中心に置く小さな装飾（丸・輪・小花菱）または無し |
| 割り出し | 同心円と放射線のガイド上で形を決める、家紋の伝統的作図法。本アプリでは生成中表示のモチーフに用いる |
| 紋名 | 構造から決定的に組み立てる呼称（例「丸に三つ柏」） |
| 図版（plate） | 図版帖に記録された生成結果 1 件。通し番号を持つ |

## 3. 機能要件

### 3.1 入力とシード（FR-0xx）

- **FR-001** 入力欄は「名前」「誕生日・記念日など」の 2 つ。いずれも自由記述、各 40 文字上限。
  - **FR-001.1** シードは `[名前, 誕生日].filter(非空).join(" / ")` で組み立てる。
  - **FR-001.2** 両方が空のときはシードなしとみなし、空状態（FR-009.1）を表示する。
  - **FR-001.3** 前後の空白は除去する。中間の空白は保持する（シードの一部）。
  - **FR-001.4** 入力は 200ms のデバウンスの後に確定させる。確定するまで前回の紋を表示したままにする。
- **FR-002** 同一シード・同一バリアントからは、**実行環境・実行時刻によらず常に同一の構造**が得られる。
  - **FR-002.1** ハッシュは FNV-1a 32bit。乱数は mulberry32。`Math.random` / `Date` / ロケールに依存する処理を生成経路に含めてはならない。
  - **FR-002.2** シード文字列は `NFC` 正規化してからハッシュする（結合文字の差異で紋が変わらないようにする）。
  - **FR-002.3** サロゲートペア（絵文字等）を含む文字列でも例外を投げず、決定的に処理する。
- **FR-003** 「次の紋へ」操作でバリアント番号を +1 し、同一シードの別解を生成する。上限は設けない。

### 3.2 紋様生成モデル（FR-1xx）— 本実装の中核

すべての座標は `viewBox="0 0 400 400"`、中心 `(200, 200)` を基準とする。

#### 3.2.1 大域制約（家紋らしさの成立条件）

- **FR-101 面優先の原則**
  - **FR-101.1** モチーフは原則として**塗り（fill）**で描く。輪郭補強のための stroke を使ってはならない。
  - **FR-101.2** stroke を用いてよいのは「線そのものが意匠である」場合に限る（外郭の輪、源氏車の輻、井桁の桟）。
  - **FR-101.3** stroke を用いる場合、線幅は **9 単位以上**（= 直径の 2.25% 以上）。
    根拠: 1.1 節の実務目安「直径 1.5cm に対し 0.25〜0.5mm」＝ 直径比 1.7〜3.3% の範囲内で、下限側に十分な余裕を取った値。
  - **FR-101.4** 白抜きの最小幅は **6 単位以上**（= 直径の 1.5%）。かつ、白抜きを開ける対象の面の幅の 1/3 以下とし、面が分断されないようにする。
- **FR-102 少数要素の原則**
  - **FR-102.1** 1 つの紋を構成する描画プリミティブ（外郭・単位モチーフ・座）の合計は **8 個以下**。
    根拠: 1.1 節「直径 1.5cm 内の交点 8 点以下」に対応する複雑度の上限。
  - **FR-102.2** 主モチーフの単位数は 1〜6。6 は幾何系の単純モチーフ（巴・菱・目結）に限る。
  - **FR-102.3** 種類の異なるモチーフを 1 つの紋に混在させてはならない（座を除く）。
    プロトタイプは中心モチーフと外周モチーフを独立に選んでおり、これが散漫さの主因であった。
- **FR-103 充填の原則**
  - **FR-103.1** 主モチーフの外接半径は `R_INNER × f`（`f ∈ [0.85, 0.95]`）に収める。
    すなわち**紋様域のほぼ全体を使い切り、外郭の直近まで到達する**。
  - **FR-103.2** 放射構成では、各単位の**基部が中心から半径 22 単位以内**に置かれ、単位同士が中心付近で接触または重複する。
    「中心に空隙を残したまま外周に部品が浮く」配置を禁じる。
  - **FR-103.3** 単位の幅は、隣接単位との角度間隔に対し十分に大きく取る（放射 n 分割時、単位の最大半幅角 ≥ `360/n × 0.30`）。
- **FR-104 対称の原則**
  - **FR-104.1** 完成した紋は、線対称（縦軸）または n 回回転対称のいずれかを厳密に満たす。
  - **FR-104.2** 対称性は座標計算ではなく SVG の `rotate` / `matrix` 変換による複製で担保する（浮動小数誤差で崩れないようにする）。
  - **FR-104.3** 単位内部に乱数ジッターを与えてよいが、**複製後の対称性を壊す位置ジッターを与えてはならない**。

#### 3.2.2 外郭（FR-11x）

- **FR-110** 外郭は次の 5 種から決定的に選ぶ。

| id | 名称 | 幾何 | `R_INNER` |
|---|---|---|---|
| `maru` | 丸 | 中心半径 176・線幅 20 の環 | 156 |
| `futae` | 二重丸 | 中心半径 180・線幅 13 の環 ＋ 中心半径 152・線幅 10 の環 | 138 |
| `kaku` | 隅切り角 | 一辺 300・隅を 34 落とした角丸なし多角形の輪、線幅 18 | 140 |
| `kikkou` | 亀甲 | 外接半径 184 の正六角形の輪、線幅 18 | 146 |
| `none` | 無し | 描かない | 178 |

- **FR-110.1** 出現比率は `maru` を最頻とする（丸が最も一般的な外郭であるため）。目安 `maru` 40% / `none` 22% / `futae` 14% / `kaku` 12% / `kikkou` 12%。
- **FR-110.2** 外郭の輪は完全な閉曲線として描き、モチーフと交差させない。

#### 3.2.3 モチーフ登録簿（FR-12x）

- **FR-120** 次の 14 モチーフを実装する。すべて**塗りを基調**とし、必要に応じて白抜きを持つ。

| id | 名 | 分類 | 適合構成 | 白抜き |
|---|---|---|---|---|
| `kashiwa` | 柏 | 植物 | 放射3 / 単独 | 主脈＋側脈 2 |
| `kiri` | 桐 | 植物 | 放射3 / 単独 | 花序の割れ |
| `kikyou` | 桔梗 | 植物 | 放射5 | 中央脈 |
| `hanabishi` | 花菱 | 植物 | 放射4 | 内菱 |
| `omodaka` | 沢瀉 | 植物 | 放射3 / 単独 | 葉脈 |
| `tachibana` | 橘 | 植物 | 放射3 / 放射4 | 実の輪 |
| `tsuta` | 蔦 | 植物 | 放射3 / 単独 | 葉脈 |
| `takanoha` | 鷹の羽 | 動物 | 違い2 / 単独 | 羽の筋 4 |
| `chou` | 蝶 | 動物 | 単独 | 翅の紋 |
| `ougi` | 扇 | 器物 | 放射3 / 単独 | 骨 3 |
| `kuruma` | 源氏車 | 器物 | 単独 | 輻 8（線意匠） |
| `hishi` | 菱 | 幾何 | 放射4 / 連環4 | 内菱 |
| `tomoe` | 巴 | 幾何 | 放射3 / 放射4 | なし |
| `meyui` | 目結 | 幾何 | 連環4 / 連環5 / 放射4 | 中央の角孔 |

適合構成は「その意匠がそう読める配置」だけを宣言する。実装時に描画結果を確認して、
次の 4 件は当初案から適合構成を狭めた。いずれも**紋名と図が食い違う**ことが理由である。

- `hanabishi` から単独を外した — 花菱は 4 弁で 1 つの意匠であり、単弁だけを大きく置くと「花菱」に見えない
- `hishi` から違い2 を外した — 菱 2 枚を傾けて重ねると内側の抜きが互いに埋まり、輪郭のない塊になる。
  同じ理由で放射も 4 枚までとする（6 枚では隣接する菱が完全に重なる）
- `takanoha` から放射3 を外した — 鷹の羽は「違い鷹の羽」の交差が意匠の核で、放射させると羽に読めない
- `tomoe` から放射2 を外した — 巴 2 つでは渦の連続が閉じず、太極図に近い別の figure になる

- **FR-120.1** 各モチーフは、原点 `(0,0)` を基部、`-y` 方向を伸長方向とするローカル座標で定義し、`translate` + `rotate` で配置する。
- **FR-120.2** 各モチーフは自身の**外接長 `L`**（基部から先端までの距離）を宣言し、配置側が `R_INNER` から逆算して `L` を与える。
- **FR-120.3** 各モチーフは適合構成を宣言し、生成器は適合外の組み合わせを選択してはならない。

#### 3.2.4 構成（FR-13x）

- **FR-130** 構成は次の 4 種。

| id | 名称 | 単位数 n | 配置 |
|---|---|---|---|
| `radial` | 放射 | 2〜6 | 単位を `360/n` 度おきに回転複製。基部を中心に集める |
| `single` | 単独 | 1 | 単位を中心に 1 つだけ、紋様域いっぱいに配置 |
| `crossed` | 違い | 2 | 単位を `±(24〜34)` 度に傾けて交差させる。縦軸線対称 |
| `ring` | 連環 | 4〜6 | 単位を半径 `R_INNER × 0.52` の円周上に、隣接単位が接するサイズで配置 |

- **FR-130.1** `radial` は中心で単位同士が接触するため、結果として中心に厚みのある塊ができる（FR-103.2）。
- **FR-130.2** `crossed` は線対称であり回転対称ではない。「違い鷹の羽」型の意匠に対応する。
- **FR-130.3** `ring` では隣接単位の外接円が接するか僅かに重なるようサイズを決め、環全体が連続した帯として読めるようにする。

#### 3.2.5 座（FR-14x）

- **FR-140** 中心の座は `none` / `dot`（塗り丸 r=14〜20） / `ring`（環、線幅 10） / `hanabishi`（小花菱 半径 26〜34）から選ぶ。
- **FR-140.1** `single` 構成および `crossed` 構成では、モチーフ自体が中心を占めるため座は `none` 固定とする。
- **FR-140.2** 座は FR-102.1 のプリミティブ数に算入する。

#### 3.2.6 紋名（FR-15x）

- **FR-150** 構造から決定的に紋名を組み立てて表示する。形式は `{外郭}{数詞}{モチーフ名}`。
  - 外郭: `丸に` / `二重丸に` / `隅切り角に` / `亀甲に` / （無しは空）
  - 数詞: `single`→空、`crossed`→`違い`、`radial`/`ring`→`三つ`〜`六つ`（n=1 は空）
  - 例: `丸に三つ柏`、`二重丸に違い鷹の羽`、`亀甲に花菱`、`五つ桔梗`、`四つ目結`
- **FR-150.1** 紋名は右ページの見出しとして大きく表示し、ダウンロードファイル名にも用いる。

### 3.3 配色（FR-2xx）

- **FR-200** 配色は 3 プリセット（`墨×白` / `朱×白` / `白×紺`）から選ぶ。
- **FR-200.1** 配色変更時、**幾何構造を再計算してはならない**（同一構造に色だけを差し替える）。
- **FR-200.2** 白抜きは背景色のベタ塗りではなく `fill-rule="evenodd"` による真の穴として実装し、任意の下地で成立させる。
- **FR-200.3** 選択中の配色は図版帖のサムネイルにも即座に反映する。

### 3.4 図版帖（FR-3xx）

- **FR-300** 生成した紋は図版帖に通し番号（図版 01, 02, …）付きで記録する。
- **FR-300.1** 新しい図版を先頭に積む。項目クリック／Enter／Space で右ページに再表示し、入力欄も当該シードへ戻す。
- **FR-300.2** 同一シード・同一バリアントの図版が既に存在する場合、新規追加せず既存項目を選択し直す（重複記録の防止）。
- **FR-301 永続化**（1.5 の判断に基づく）
  - **FR-301.1** 図版帖を `localStorage` キー `kamon-generator/plates/v1` に保存する。保存する値は
    `{ plateNo, name, birthday, seedText, variantIndex, savedAt }` のみで、**幾何構造は保存しない**（読み込み時に再生成する）。
  - **FR-301.2** 上限 60 件。超過時は最も古い図版から削除する。
  - **FR-301.3** 保存値が壊れている／スキーマが不一致の場合は、その項目を黙って捨てて残りを読み込む。全滅した場合は空状態から始める。
  - **FR-301.4** `localStorage` が使用不可（プライベートモード・容量超過等）の場合、機能を停止せず**メモリ内保持に降格**し、その旨を 1 度だけ通知する。
  - **FR-301.5** 「帳を空にする」操作を提供する。実行前に確認を求める。
  - **FR-301.6** 保存はローカル端末内で完結する旨を UI 上で明示する。

### 3.5 書き出し（FR-4xx）

- **FR-400** 表示中の紋を書き出せる。形式は **SVG** と **PNG** の 2 つ。
- **FR-400.1** SVG は `<?xml ... ?>` 宣言付き、`viewBox` 400×400、外部フォント・外部参照を含まない自己完結ファイルとする。
- **FR-400.2** PNG は 1200×1200px、選択中の配色の地色を敷いて出力する（透過にしない）。
  Canvas 経由で生成し、外部ライブラリを使わない。
- **FR-400.3** ファイル名は `kamon-{紋名}-{シード先頭16文字}-{変体番号}.{svg|png}`。
  ファイル名として不正な文字（`\ / : * ? " < > |` および制御文字）を除去し、空になった場合は `無銘` を用いる。
- **FR-400.4** 書き出しの進行中・成功・失敗をステータス領域（`aria-live="polite"`）に集約する。`window.alert` を使わない。
- **FR-400.5** 生成した Object URL は解放する。

### 3.6 状態表示と体験（FR-5xx）

- **FR-500** アプリは `empty` / `drafting` / `ready` / `error` の 4 状態を明示的に持つ。

| 状態 | 契機 | 表示 |
|---|---|---|
| `empty` | シードなし | 割り出しガイドのみの淡い正円 ＋ 誘い文 |
| `drafting` | シード確定〜描画完了 | **割り出し線**（同心円 3 本 ＋ 放射線）を朱の細線で描いた作図中の面 |
| `ready` | 構造生成成功 | 紋 ＋ 紋名 ＋ 諸元 ＋ 書き出し操作 |
| `error` | 構造生成・描画の失敗 | エラー面 ＋ 復帰操作（`role="alert"`） |

- **FR-500.1** `drafting` は最低 260ms 表示する（一瞬で消えて瞬きのように見えることを防ぐ）。
- **FR-500.2** 紋の出現は「割り出し線の上に墨が入る」モーション（不透明度 ＋ 微小スケール、220ms）で表現する。
  これは体験上の主要モーメントであり、装飾的なマイクロインタラクションを他所に散らさない。
- **FR-500.3** 紋表示域は `aspect-ratio` で領域を先に確保し、状態遷移でレイアウトシフトを起こさない（CLS 寄与 0）。
- **FR-500.4** `prefers-reduced-motion: reduce` のとき、すべてのアニメーションを無効化し、状態遷移は即時とする。
- **FR-501** 繰り返し操作への配慮
  - **FR-501.1** 「次の紋へ」の連打で描画が詰まらないよう、進行中の描画要求は最新のもので置き換える。
  - **FR-501.2** 図版帖は最大高を持ち内部スクロールする。項目数が増えてもページ全体の高さが伸び続けない。
  - **FR-501.3** 書き出し成功表示は 3.2 秒で自動的に消える。

### 3.7 アクセシビリティ（FR-6xx）

- **FR-600** すべての操作要素がキーボードで到達・操作可能。フォーカスリングを可視化する。
- **FR-601** 図版帖の項目は `<button>` 要素とする（`div` に `role="button"` を付けない）。
- **FR-602** 紋の SVG に `role="img"` と、紋名を含む `aria-label` を与える。
- **FR-603** 状態変化はステータス領域（`aria-live="polite"`）、エラーは `role="alert"` で通知する。
- **FR-604** 本文・UI 文字のコントラスト比は 4.5:1 以上。

## 4. 非機能要件

- **NFR-001 完全クライアントサイド**: ネットワーク送信を行わない（Web フォント取得を除く）。
- **NFR-002 ビルド／配信**
  - **NFR-002.1** Vite + TypeScript（vanilla）。UI フレームワーク・図形描画ライブラリを導入しない。
  - **NFR-002.2** `vite.config.ts` で `base: './'` を設定し、サブパス配信でも壊れないようにする。
  - **NFR-002.3** `Dockerfile`（node:22-alpine ビルド → nginx:alpine 配信）が変更後も通ること。
- **NFR-003 独立性**: `apps/kamon-generator/` 内で自己完結し、他アプリとコード・依存を共有しない。
- **NFR-004 性能**: 1 紋の構造生成 + SVG 文字列化は 5ms 未満。入力から描画確定まで（デバウンス除き）100ms 未満。
  JS バンドル（gzip）40KB 未満。
- **NFR-005 レスポンシブ**: 320 / 375 / 768 / 1024 / 1440px で横スクロールが発生しない。
  900px 未満で見開きを上下 2 段に折る。
- **NFR-006 意匠の保全**: 1.2 節の視覚方向を維持する。カード積み・均一グリッド・角丸の多用・グレー基調 + 差し色 1 色のみ、といった
  テンプレート的表現に退行させない。
- **NFR-007 セキュリティ**: ユーザー入力を `innerHTML` に生の文字列として流し込まない。SVG 文字列に混入させる値は
  数値・列挙値・エスケープ済みテキストに限る。
- **NFR-008 コード品質**
  - **NFR-008.1** `tsconfig` に `strict` と `noUncheckedIndexedAccess` を有効化する。
  - **NFR-008.2** DOM 要素の取得は検査付きヘルパで行い、無検査の `as` キャストを置かない。
  - **NFR-008.3** テストは単体・統合・E2E の 3 種を備える。
  - **NFR-008.4** 行・分岐カバレッジ 80% 以上をしきい値として強制する（`src/main.ts` のブートストラップを除く）。
  - **NFR-008.5** 1 ファイル 400 行以内を目安とする。

## 6. 判断と根拠の記録

| 決定 | 選択 | 却下した案と理由 |
|---|---|---|
| 白抜きの実装 | `fill-rule="evenodd"` の副パス | 地色の矩形/パスを上に重ねる案 — 書き出した SVG を別背景に置くと破綻する |
| モチーフ混在 | 禁止（1 紋 1 モチーフ） | プロトタイプ同様に中心・外周で別モチーフを選ぶ案 — 散漫さの主因であり、実在紋の構成法則にも反する |
| 対称性の担保 | SVG 変換による複製 | 各単位の座標を個別計算する案 — 浮動小数誤差で対称が崩れ、テストで検証しづらい |
| 履歴の保存内容 | シードとバリアントのみ | 構造 JSON を保存する案 — 決定的生成器では冗長で、生成ロジック更新時に古い構造が残り不整合を起こす |
| モチーフの寸法決定 | `R_INNER` から逆算して各モチーフに `L` を与える | モチーフ側が絶対寸法を持つ案 — 外郭を変えると充填率が崩れる |
| 生成中の表示 | 割り出し線（作図ガイド） | 汎用スピナー／スケルトン矩形 — 意匠と無関係で、家紋帳の世界観を壊す |
| 動物紋 3 種目 | `雁金` を落とし `蔦` を入れた | 雁金は飛翔する鳥の輪郭で、面に還元すると「鳥」と読める最小形が本アプリの単位寸法を大きく超える。`蔦` は十大家紋の一つで、面と葉脈の白抜きだけで成立し、放射・単独の双方に耐える。結果として登録数 14 は変わらず、動物紋は 2 種・植物紋は 7 種となった |
| 「帳を空にする」の確認 | ボタン自体を 2 段階にする（押すと「本当に空にする / やめる」に変わる） | `window.confirm` — モーダルがページを止め、家紋帳の見開きから意識が外れる。かつ E2E から扱いづらい |
| 書き出しボタンの形 | 朱文（塗り）と白文（陰刻）の角印 2 顆を並べる | 汎用のボタン 2 個を並べる案 — 落款は様式の違う印を並べるのが実際の作法であり、SVG / PNG の主従をその様式差で表せる |
