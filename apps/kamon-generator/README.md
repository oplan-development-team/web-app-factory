# 家紋帳 — オリジナル家紋ジェネレーター

名前や誕生日を「種」にして、正円のなかに左右対称・点対称の紋様を**決定的に**割り出す Web ツールです。
同じ種からは、いつ・どの端末で開いても必ず同じ紋が戻ります。画面は家紋帳の見開きに見立て、
左の丁で編み、右の丁に一点だけ大きく据えます。

- 仕様: [`docs/SPEC.md`](docs/SPEC.md) ／ 実装計画: [`docs/PLAN.md`](docs/PLAN.md) ／ タスク: [`docs/TASKS.md`](docs/TASKS.md)
- 前身は app-factory パイプラインが自律生成したプロトタイプ。本実装はその仕様化・作り直し版です。

## できること

- 名前・誕生日（各 40 文字まで）を種に、その場で紋を割り出す
- 「次の紋へ」で、同じ種のまま別案を呼び出す（案の数に上限なし）
- 色目は 3 プリセット（墨×白／朱×白／白×紺）。家紋は単色エンブレムなので任意配色は持たない
- 割り出した紋は「図版帖」に通し番号つきで綴じられ、**ブラウザを閉じても残る**（最大 60 葉）
- 表示中の紋を **SVG**（自己完結・外部参照なし）と **PNG**（1200×1200・地色つき）で書き出せる
- 紋名（「丸に三つ柏」など）を構造から決定的に組み立てて表示し、ファイル名にも使う
- 通信は一切行わない。入力した名前が端末の外へ出ることはない

## 本実装で変えたこと — 生成モデルの置き換え

プロトタイプの出力は「家紋」ではなく**小さな図形の散布**になっていました。実測すると次のとおりです。

| プロトタイプ | 帰結 |
|---|---|
| 線幅 1.6〜6px（直径比 0.4〜1.5%） | 遠目・縮小時に消える |
| 描画プリミティブ数 最大 42 | 視線の焦点が定まらない |
| 外周モチーフの半径 96〜138 に対し、モチーフ寸法 12〜22 | 円の中身がほぼ空白 |
| 中心にモチーフが接触しない | 一個の図として結像しない |
| 塗り確率 中心 60% / 外周 40% | 線画優位でシルエットが立たない |

実在の家紋（五三桐・丸に三つ柏・丸に違い鷹の羽など）はこの逆を行きます。単色・高コントラストが前提で、
白黒にしても形が判別できることが要件。作図実務の目安では**直径 1.5cm に対し主要線幅 0.25〜0.5mm
（直径比 1.7〜3.3%）、直径 1.5cm 内の交点は 8 点以下**に抑えます。戦場での識別が起源なので、
大胆な図形による一目での判別性が設計目的そのものです。

そこで生成モデルを、**「小さな部品を円の中に散らす」から「少数の大きな面を中心で噛み合わせて
一つの塊にする」**へ置き換えました。見た目の微調整ではなく、生成ロジックの設計転換です。

| 原則 | 具体 |
|---|---|
| **面優先** | モチーフは塗りで描く。輪郭補強の stroke を持たない。線が意匠そのものである場合（外郭の輪・源氏車の輻）だけ stroke を使い、線幅は 9 単位以上（直径比 2.25%）を保証する |
| **少数要素** | 1 紋の描画プリミティブは 8 個以下。1 紋に 1 種類のモチーフしか使わない（プロトタイプは中心と外周で別モチーフを選んでおり、これが散漫さの主因だった） |
| **充填** | 紋の外接半径は紋様域の 85〜95%。放射構成では各単位の基部が中心から 22 単位以内に集まり、単位同士が中心付近で接触する |
| **対称** | 座標計算ではなく SVG の `rotate` / `matrix` 変換による複製で対称性を担保する（浮動小数誤差で崩れない） |

これらは「だいたい守れている」ではなく、**100 シード × 3 バリアントの全数走査**で不変条件として
検証しています（`tests/unit/kamon.test.ts`）。

### 割り出しの手順

1. 種文字列を `NFC` 正規化し、バリアント番号と連ねて FNV-1a で 32bit ハッシュ化
2. そのハッシュを種に mulberry32（決定的 PRNG）を初期化。`Math.random` / `Date` / ロケールは生成経路に一切入れない
3. **制約の強い順に抽選する** — 外郭 → モチーフ → 構成 → 充填率 → 形状のゆらぎ → 座。
   外郭を先に決めると紋様域の半径が確定し、以降の寸法がそこから逆算できるので、無効な組み合わせが生じない
4. 単位を一度組み立てて外接半径を実測し、同じ乱数列のまま寸法だけ直して組み直す。
   これで充填率が構成によらず正確に成立する
5. 配置ぶんだけ `<g transform>` で複製する

- **外郭 5 種**: 丸 / 二重丸 / 隅切り角 / 亀甲 / 無し
- **モチーフ 14 種**: 柏・桐・桔梗・花菱・沢瀉・橘・蔦（植物紋）／鷹の羽・蝶（動物紋）／扇・源氏車（器物紋）／菱・巴・目結（幾何紋）
- **構成 4 種**: 放射（2〜6）／単独／違い（2）／連環（4〜6）
- 白抜き（葉脈・羽の筋・輻）は地色のベタ塗りではなく `fill-rule="evenodd"` の副パスで開ける。
  書き出した SVG を別の背景に置いても破綻しない

各モチーフは「その意匠がそう読める配置」だけを宣言します。実装時に描画を確認して適合構成を
狭めた 4 件（花菱・菱・鷹の羽・巴）の理由は SPEC 3.2.3 に記録しています。

## 判断した任意要件

| 項目 | 判断 | 理由 |
|---|---|---|
| 生成履歴の永続化 | **対応した**（localStorage） | 「帳（＝台帳）」というメタファの中核。閉じると白紙に戻る帳面は概念矛盾。かつ決定的生成器なので**シード文字列とバリアント番号だけ保存すれば図版は完全に復元でき**、保存コストが極小で済む |
| PNG 書き出し | **対応した** | SVG を扱えない投稿先・入稿先が実用上多い。外部依存なしに Canvas で完結できる |

幾何構造そのものは保存しません。構造を保存すると、生成ロジックを更新したときに古い構造が
残って不整合を起こすためです。

## 体験の設計

- **4 状態**（空 / 割り出し中 / 表示 / エラー）を `data-state` 一箇所で表し、DOM を付け外ししない。
  紋の領域は `aspect-ratio` で先に確保するので、状態が変わっても行がずれない
- **割り出し中は汎用スピナーを出さない**。家紋は同心円と放射線のガイド（割り出し線）の上で作図されるため、
  その作図線をゆっくり回す。待ち時間が所作として読める。最短 260ms 表示して、瞬きのように消えるのを防ぐ
- 紋の出現は「割り出し線の上に墨が入る」動き（220ms）に集約し、装飾的な小技を他所へ散らさない
- 「次の紋へ」の連打では、**記録は要求した瞬間に確定させ、右ページの差し替えだけを最新要求優先で間引く**。
  連打しても図版帖から取りこぼれない
- `prefers-reduced-motion: reduce` ではすべての動きを止め、割り出しの待ちも挟まない
- 保存できない環境（プライベートモード等）では機能を止めず、メモリ保持へ降格して 1 度だけ知らせる

## 技術スタック

素の HTML / CSS / TypeScript。UI フレームワークも SVG 描画ライブラリも使っていません。
図形はすべて自前の SVG 文字列生成です。Vite はバンドルと開発サーバーとしてのみ使用しています。
バックエンド・データベースはありません。

- 本番 JS は gzip 約 11KB（予算 40KB）、CSS は約 3.5KB
- `tsconfig` は `strict` + `noUncheckedIndexedAccess`。DOM 取得は検査付きヘルパに一本化し、無検査キャストを置かない

## 開発

```bash
npm install
npm run dev          # 開発サーバー
npm run build        # 型チェック + 本番ビルド（dist/ へ出力）
npm run preview      # ビルド結果の確認
npm test             # 単体 + 統合テスト（カバレッジしきい値 80%）
npm run test:e2e     # Playwright E2E（Chromium / Firefox / WebKit）
```

E2E は開発サーバーではなく本番ビルドに当てています。`base: './'` や CSS の取り込みなど、
ビルドを通してはじめて効く設定があるためです。

### 生成結果の目視

```bash
npx vite-node scripts/contact-sheet.ts -- contact-sheet.html 40
```

紋を一覧するコンタクトシートを書き出します。「面が主役になっているか」「中心が噛み合っているか」を
まとめて確かめるための開発用スクリプトです。

```bash
docker build -t kamon-generator .
docker run --rm -p 8080:80 kamon-generator

```

## 対象外

| 項目 | 理由 |
|---|---|
| 実在家紋データベースの収録・検索 | 権利・出典管理の負担が単発小規模アプリの前提を超える。本アプリは「実在紋に似た新しい紋」を作るもので、実在紋の再現器ではない |
| 任意カラーピッカー | 単色エンブレムであることが家紋の成立要件。自由配色はその要件を壊す |
| モチーフを手で選ぶ編集モード | 「名前が紋になる」決定性が体験の核。手動編集は決定性の意味を失わせる |
| 円形以外の外郭（盾形・楕円など） | 「正円と直線から構成される」という家紋の骨格要件から外れる |
| アカウント・共有 URL・SNS 連携 | バックエンドが必要になる |
| 名刺・封筒・印鑑テンプレートへの合成 | 別アプリの領分 |
| 多言語 UI | 日本語のみ |
