# PLAN: サイアノタイプ・ポスターメーカー 本実装

対応 SPEC: `./SPEC.md`

---

## 1. 方針

プロトタイプの画像処理パイプライン（輝度化 → 誤差拡散 → ムラ変調 → マスク → 質感 → ラベル）は
意匠として成立しており、**構造をそのまま活かす**。作り直すのは次の 3 点に限る。

1. **図案ソースの抽象化** — 現状 `HTMLImageElement | null` に直結している入力を、
   「アップロード画像」と「所蔵標本」を等しく扱える境界に置き換える。
2. **描画層のテスト可能化** — `CanvasRenderingContext2D` 直依存を、
   実際に使うメンバーだけの構造的部分型へ差し替える（NFR-007.2）。
   jsdom に Canvas 2D 実装がないため、これをやらないとカバレッジ 80% に到達しない。
3. **プロトタイプの割り切りの解消** — 巨大画像の上限なし（FR-110.4）、
   `crypto.subtle` 失敗時の `Math.random` フォールバック（FR-111.1）、
   Geolocation プロンプト放置でのハングアップ（FR-404.2）、
   繊維テクスチャキャッシュの無制限増加（FR-302.2）。いずれも本実装では許容しない。

意匠に関わるコード（`edgeMask` の欠けの散らし方、`drawLabel` の 3 層タイポグラフィ、
`vignette` の減衰カーブ、CSS の傾き・真鍮の留め具）は、テスト容易性を理由に
単純化しない（NFR-006）。

## 3. 設計上の判断

### 3.1 図案ソースを判別共用体にする

```ts
type PosterSource =
  | { kind: "upload"; image: HTMLImageElement; width: number; height: number }
  | { kind: "specimen"; specimenId: string };
```

`seed` はソースと独立の値として `AppState` に持つ。アップロードならファイルのハッシュ、
所蔵標本なら再抽選のたびに更新される値であり、どちらも「紙目・縁のゆらぎ・図案の個体差」を
同じ 1 つのシードで駆動する。シードを増やすと再現性の議論が二重になるため 1 本に絞る。

`compose` 側は感光域の階調を作る段だけを分岐させ、以降（誤差拡散〜ラベル）は完全に共通にする。

### 3.2 所蔵標本を「プレート解像度で直接描く」

```ts
interface Specimen {
  id: string;
  plateNo: string;        // 図版番号（図案帳の表示に使う）
  label: string;          // 和名
  scientificName: string;
  commonName: string;
  locality: string;
  draw(ctx: Ctx2D, w: number, h: number, rng: Rng): void;
}
```

`draw` は幅・高さを受け取り、その寸法に対する相対座標で図を組む。
サムネイル（112×140）でもプレート（1104×1180 など）でも同じ手続きが走るため、
**サムネイルは製品そのものの縮小**であり、別途アイコンを用意する必要がない（FR-124）。

地の露光ムラだけは画素単位の fbm が必要なので、**低解像度（96px 級）のノイズ面を作って
拡大合成**する。露光ムラは元来低周波なので拡大しても破綻せず、3600×4800 でも
画素ループを回さずに済む。

### 3.3 陰画（フォトグラム）の階調設計

| 部位 | 輝度目安 | 二階調化後 |
|---|---|---|
| 地（露光部） | 20〜70（fbm でゆらぐ） | ほぼインクのベタ。粗密で露光ムラが残る |
| 葉身・膜状部（薄い） | 150〜185 | 中間の網点 |
| 葉脈・茎・托葉（厚い） | 210〜250 | ほぼ紙色 |
| 半影（接触の甘い縁） | 地と葉身の中間 | 網点が疎から密へ遷移する柔らかい縁 |

`ctx.filter = "blur()"` は使わない（WebKit の対応差と、拡大縮小合成での挙動差を避けるため）。
半影は**同一パスを太らせながら低不透明度でストロークする多重描画**で作る。
描画回数はパスあたり 3 回に固定されるので、解像度にも図形数にも比例して悪化しない。

### 3.4 Canvas を構造的部分型に置き換える

`src/core/ctx2d.ts` に、実際に使うメンバーだけを並べた `Ctx2D` と、
`CanvasFactory`（幅高を受けてキャンバス様オブジェクトを返す関数）を置く。

- `fillStyle` などは DOM の型（`string | CanvasGradient | CanvasPattern`）をそのまま採る。
  独自 union にすると実 context が代入できなくなる。
- `drawImage` の第 1 引数は `CanvasLike | CanvasImageSource` の union にする。
  片方だけだと双変性チェックが両方向とも通らない。
- 注入口は `CanvasFactory` の 1 箇所だけにする。差し替え口を増やすと本番経路と
  テスト経路が乖離する。

テストのフェイクでは `measureText` を**フォントサイズに比例**させる。固定幅だと
「収まるまで縮小する」ロジック（FR-402 の学名）が素通りする。

### 3.5 ラベル自動投入の規則

`AppState` に `labelTouched: Set<keyof LabelFields>` 相当の記録を持ち、
標本選択時の既定値適用は未 touch のフィールドにのみ行う（FR-127）。
これを描画側ではなく状態遷移の純関数に置くことで、UI を起動せずに単体テストできる。

### 3.6 再描画のスケジューリング

- プレビュー: `requestAnimationFrame` で 1 フレーム 1 回に束ねる（FR-605、既存踏襲）
- 図案帳サムネイル: 種の一覧は起動時に 1 回、選択中の 1 枚だけシード変更時に再描画（FR-606）

E2E から再描画の完了を待てるよう、プレビュー要素に単調増加するレンダーカウンタを
`data-render-count` として出す。「状態が ready になるのを待つ」だけでは、
再描画前の古い DOM にアサーションが当たる。

## 4. テスト戦略

| 層 | 対象 | 環境 |
|---|---|---|
| 単体 | 乱数・輝度化・誤差拡散・cover 配置・座標整形・標本番号・状態遷移 | node |
| 単体（描画） | ラベル描画・縁マスク・質感・各所蔵標本の作図 | node + Ctx2D フェイク |
| 統合 | 採取 → 調整 → 書き出しの結線、ラベル自動投入 | jsdom |
| E2E | AC-01〜AC-19 の主要動線 | Playwright ×3 エンジン（本番ビルド） |

所蔵標本には**全種共通の不変条件テスト**を置く（AC-07 も含む）。

1. 決定性: 同一 `(id, seed)` の描画呼び出し列が完全一致する
2. 階調範囲: 使われる塗り色が FR-122 の帯に収まる
3. 被覆: 図が描画領域の 25%〜85% を占める（空白すぎ／埋まりすぎを弾く）
4. 収まり: 描画座標が領域外へ大きくはみ出さない
5. 個体差: シード違いで描画呼び出し列が異なる

これは「6 種それぞれの絵を目で確認する」代わりに、**意匠の要件を数値の不変条件へ落とす**
アプローチ。見た目の最終判断はブラウザ実機で行う。

## 5. リスク

| リスク | 対処 |
|---|---|
| 手続き生成の図案が「植物に見えない」 | 不変条件テストで最低限を担保しつつ、実機のコンタクトシートで全種を目視確認する |
| 3× 書き出しで図案の描画コストが跳ねる | 半影の描画回数をパスあたり固定にし、地は低解像度合成にする（3.2, 3.3） |
| Ctx2D 差し替えで実ブラウザの型が合わなくなる | 型は DOM の定義をそのまま採り、ビルド（`tsc`）と E2E の両方で担保する |
| エンジン差で E2E がすり抜ける | 最初から 3 エンジンで回す。Chromium 単独の緑を完了条件にしない |
| 傾き（`rotate(-0.25deg)`）を持つカードが増えて崩れる | 図案帳はカード内部に置き、カード自体の枚数を増やさない |
