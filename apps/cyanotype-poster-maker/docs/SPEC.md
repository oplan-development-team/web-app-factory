# SPEC: サイアノタイプ・ポスターメーカー

**Feature ID**: 004-cyanotype-poster-maker
**Status**: Approved (production implementation)
**Last updated**: 2026-08-27
**前身**: app-factory パイプラインによる自律生成プロトタイプ（同ディレクトリ）。本仕様はその本実装版。

---

## 1. 概要

写真、または本アプリが手続き的に生成する植物標本図案を、Floyd-Steinberg 誤差拡散で
プルシアンブルーの二階調ハーフトーンへ変換し、紙の繊維・藍液の塗りムラ・周辺減光・
不規則な感光縁まで再現して、植物標本ラベル付きの一枚のサイアノタイプ風ポスターとして
高解像度 PNG に書き出す Web ツール。

バックエンドを持たず、画像処理・図案生成・書き出しのすべてをブラウザ内で完結させる。
入力画像・ラベル情報は一切外部に送信しない。

### 1.1 本実装で追加する中心機能 — 所蔵標本（プリセット図案）

プロトタイプは**ユーザーが写真を持ち込むことを唯一の入口**にしていた。これは
「手元に良い被写体の写真がある人」しか一枚目に到達できないことを意味し、
ツールの体験の入口が実質的に閉じている。

本実装では、写真アップロードと並ぶ第二の入口として**所蔵標本（プリセット図案）**を追加する。
図案は静的な画像アセットではなく、**シードから決定的に組み立てる手続き生成の植物図案**とする。

この設計を選ぶ理由：

- **技法的な必然性がある。** サイアノタイプの原点である Anna Atkins
  『Photographs of British Algae: Cyanotype Impressions』(1843) は、カメラを使わず
  植物そのものを印画紙に伏せて焼き付けた**フォトグラム**である。植物は光を遮って紙色のまま残り、
  露光した地が藍に沈む。つまり「出来合いの植物図案」は本アプリのコンセプトにとって
  後付けの便宜ではなく、**技法の本来の姿**にあたる。
- **解像度の劣化がない。** 図案をラスタのアセットとして持つと、3× 書き出し時に拡大ボケが出る。
  手続き生成なら**プレート解像度で直接描き起こせる**ため、どの倍率でも輪郭が保たれる。
- **個体差が出せる。** 同じ「シダ」でも、シードを変えれば羽片の数・湾曲・裂片の深さが変わる。
  現実の標本と同じく「同じ種の別個体」として提示できる。
- **アプリ間でコードを共有しない方針を守れる。** 姉妹アプリ `kamon-generator` の
  「シードから決定的に図形を組む」考え方は参考にするが、実装は本アプリ内で自己完結させる。

### 1.2 視覚方向（維持する資産）

プロトタイプの**19世紀ハーバリウム・シート様式のエディトリアル**という方向は本アプリの
アイデンティティであり、維持・強化する。堅牢化・テスト容易性を理由に薄めてはならない（NFR-006）。

- **生成物（ポスター本体）**: プルシアンブルー系インク × 生成り〜クリームの紙色の **2 色のみ**。
  実在の単色印画技法としてのリアリティを崩す第三の色を入れない
- **ツール UI（囲い）**: ダークな陳列室の壁（`--room-void`）に、クリームの索引カード
  （`--card-paper`）を微妙に傾けて並べ、真鍮の金具（`--brass`）を留め具・フォーカス・
  現在地に限定して効かせる標本キャビネットの構成
- **書体 3 層**: 学名 = EB Garamond イタリック／日付・座標・標本番号 = Special Elite（タイプライター）／
  産地・付帯情報 = 本文セリフのスモールキャップス
- **均一なカードグリッド・大きな角丸・影の一律適用を使わない**。階層はスケール差・
  ヘアライン・余白の強弱でつくる

### 1.3 対象ユーザー

- 手元の写真を「作品」として仕立て直したい個人
- 植物標本・博物図版の意匠が好きで、飾れる一枚を手早く得たい層
- 素材を持っていないが、まず何か一枚つくってみたい初回訪問者（← 所蔵標本が受け皿）

### 1.4 スコープ外（非目標）

| 項目 | 除外理由 |
|------|----------|
| 実際の化学反応（露光時間・薬品）のシミュレーション | 意匠の再現が目的であり、化学的正確さは体験に寄与しない |
| 地名からの自動ジオコーディング | 外部 API 依存を避ける。座標は手入力＋現在地取得のみ |
| 画像認識による植物種の自動判定 | 外部 API / 大きなモデル依存を避ける |
| 複数写真の合成・コラージュ | 「一枚の標本シート」という制約が意匠を成立させている |
| 印刷注文・物理プリント連携 | 外部サービス依存 |
| 作品のギャラリー化・履歴保存・共有 | 単発ツールとしての単純さを保つ（YAGNI） |
| 藍以外の色調（セピア・モノクロ） | 「サイアノタイプ」という技法の同一性が失われる |
| 所蔵標本のユーザー追加・自由編集 | 図案は完成された意匠として提示する。パラメータ露出は個体差の再抽選に留める |

## 2. 用語

| 語 | 意味 |
|---|---|
| **プレート / 台紙** | 出力される一枚のポスター全体（紙色の地 + 感光域 + ラベル帯） |
| **感光域** | プレート内で図像が焼き付いている矩形領域 |
| **図案ソース** | 感光域の元になる階調画像。「持ち込み標本（アップロード）」と「所蔵標本（プリセット）」の 2 系統 |
| **所蔵標本 / 図案帳** | 本アプリが手続き生成する植物図案と、その一覧 UI |
| **陰画（フォトグラム）方式** | 植物を明部、地を暗部として描く階調の与え方。二階調化後、植物が紙色・地がインクになる |
| **個体** | 同一の所蔵標本種における、シード違いのバリエーション |

## 3. 機能要件

### 3.1 図案ソース（FR-100）

- **FR-101** 図案ソースは次の 2 系統を持ち、いずれか一方が選択されている状態を取る。
  - **FR-101.1** `upload` — ユーザーがアップロードした画像
  - **FR-101.2** `specimen` — 所蔵標本（手続き生成図案）
- **FR-102** 起動直後は**どちらも未選択**とし、プレビュー領域は未感光（空状態）を表示する。
- **FR-103** 一方を選択すると他方の選択は解除される。切り替えても、選択済みだった側の
  状態（アップロード画像・選択中の標本と個体シード）は保持し、戻せば復元される。
- **FR-104** 図案ソースが選択された時点で、調整・ラベル・書き出しの各カードが開示される。

#### 3.1.1 持ち込み標本（アップロード）

- **FR-110** JPEG / PNG を、ドラッグ&ドロップ、クリックによるファイル選択のいずれでも受け付ける。
  - **FR-110.1** ドロップゾーンはキーボード（Enter / Space）でも起動できる。
  - **FR-110.2** MIME タイプが `image/jpeg` / `image/png` 以外のファイルは受け付けず、
    理由を示すエラーを表示する。
  - **FR-110.3** 復号に失敗した場合も、破損の可能性を示すエラーを表示し、
    直前の状態を壊さない。
  - **FR-110.4** 画素数の上限を設け（長辺 12000px 相当、総画素 4000 万）、
    超過時は「大きすぎる」旨のエラーを返して読み込みを中止する。
    → 巨大画像で `getImageData` が失敗し、無言で真っ白になる事故を防ぐ。
- **FR-111** 読み込んだファイルの先頭バイト列から SHA-1 を取り、
  標本番号（`YYYY.NNNN.X` 形式）と質感シードを決定的に導出する。
  同じ写真からは常に同じ紙目・縁のゆらぎが再現される。
  - **FR-111.1** `crypto.subtle` が利用できない環境（非セキュアコンテキスト等）では
    ファイル名・サイズ・更新時刻からの決定的フォールバックを用いる。
    `Math.random` による非決定的な採番は行わない。
- **FR-112** 感光域への配置は `object-fit: cover` 相当（中央基準の切り抜き）とし、
  縦横比を歪めない。

#### 3.1.2 所蔵標本（プリセット図案）

- **FR-120** 所蔵標本は **6 種**を登録簿として持つ。各標本は次を宣言する。
  和名 / 学名 / 既定の採集地 / 図版番号 / 描画手続き。

  | id | 和名 | 学名 | 意匠の要点 |
  |---|---|---|---|
  | `fern` | シダ（ワラビ） | *Pteridium aquilinum* | 湾曲する中軸に羽片が交互に並ぶ羽状複葉 |
  | `algae` | 海藻（ダルス） | *Delesseria sanguinea* | 二叉分岐する膜状葉。Atkins の原典的題材 |
  | `venation` | 葉脈標本（インドボダイジュ） | *Ficus religiosa* | 主脈・二次脈・網状の三次脈が主役 |
  | `grass` | エノコログサ | *Setaria viridis* | 細く弧を描く稈と、剛毛を持つ穂 |
  | `umbel` | ノラニンジン | *Daucus carota* | 放射する散形花序の入れ子構造 |
  | `ginkgo` | イチョウ | *Ginkgo biloba* | 扇形の葉身と二叉分枝する平行脈 |

- **FR-121** 各標本は**シードから決定的に**組み立てられる。同一 `(id, seed)` からは
  常に同一の図案が再現される。描画手続きは `Math.random` / `Date` / ロケール依存処理を含まない。
- **FR-122** 図案は**陰画（フォトグラム）方式**で階調を与える。
  - **FR-122.1** 地は暗部（輝度 20〜70 相当）とし、露光ムラを模した緩やかな低周波の
    濃淡を持たせる。完全な均一値にしない（誤差拡散後に機械的なベタになるため）。
  - **FR-122.2** 植物体は明部（輝度 150〜250 相当）とする。葉身などの薄い組織は
    中間調、葉脈・茎などの厚い組織はより明るい値とし、透過の差を階調で表す。
  - **FR-122.3** 輪郭には接触の甘さを表す半影（penumbra）を持たせ、
    完全な硬いエッジにしない。
- **FR-123** 図案は**感光域の解像度で直接描画**する。低解像度で一度描いてから
  拡大する実装にしてはならない（1×/2×/3× のいずれでも輪郭が保たれること）。
- **FR-124** 図案帳 UI は 6 種を一覧で提示し、各項目に**実際の生成器で描いた
  サムネイル**を表示する。固定の代替アイコン・静的画像を用いない。
- **FR-125** 選択中の標本に対して「別個体を採取」操作を提供する。
  実行するとシードのみが変わり、種は変わらない。
  - **FR-125.1** 再抽選のたびに標本番号を採り直す。
  - **FR-125.2** 再抽選しても、ユーザーが手で編集したラベル項目は上書きしない（FR-127）。
- **FR-126** 標本の選択・再抽選の結果は、サムネイルにも即座に反映される
  （選択中の項目のサムネイルは現在のシードで描かれる）。
- **FR-127** 標本を選択したとき、ラベルの学名・和名・採集地に既定値を投入する。
  ただし**ユーザーが自分で編集した項目は上書きしない**。
  - **FR-127.1** 「編集済み」の判定はフィールド単位で行い、一度でもユーザー入力が
    発生したフィールドは以後自動投入の対象外とする。

### 3.2 二階調化（FR-200）

- **FR-201** 図案ソースを Rec.709 輝度（`0.2126R + 0.7152G + 0.0722B`）でグレースケール化する。
- **FR-202** コントラストを -100〜100 の範囲で調整できる。0 で無変換。
- **FR-203** Floyd-Steinberg 誤差拡散により 1bit 化する。
  - **FR-203.1** 走査は行ごとに向きを反転させる（ブースト・スキャン）。
    一定方向の走査で出る斜めの縞を避けるため。
  - **FR-203.2** 誤差の配分は 7/16・3/16・5/16・1/16 とし、
    走査方向の反転に合わせて左右を入れ替える。
  - **FR-203.3 感光しきい値** — 60〜200 の範囲で調整でき、値を上げるほど
    インクが増える（印画紙を長く焼くほど藍が濃くなるのと同じ向き）。
    これは**誤差拡散のしきい値ではなく、二階調化の前段に置く露光量**として実装する。
    → 誤差拡散は、はみ出した誤差を隣の画素へ送って帳尻を合わせる仕組みなので、
      出力の平均濃度は入力の明るさに追従し、しきい値をどこへ置いてもほとんど変わらない
      （実装当初はこちらに繋いでいて、60〜195 の全域でインク比率が 0.431 から
      動かなかった）。露光量として輝度そのものを上下させることで、
      スライダーが実際に効くようになる。
- **FR-204** 二階調化の結果は「インク（1）／紙（0）」のビットマップであり、
  中間色を含まない。濃淡の見えはドットの粗密のみで表現される。

### 3.3 質感（FR-300）

- **FR-301 藍液のムラ** — 手引きの塗りムラを模した低周波ノイズでインクの不透明度を
  画素ごとに変調する。0〜100 で強度調整。
- **FR-302 紙の繊維** — 手続き生成したタイル可能な繊維テクスチャを
  `overlay` 合成で重ねる。0〜100 で強度調整。
  - **FR-302.1** テクスチャはシードごとにキャッシュし、スライダー操作のたびに
    焼き直さない。
  - **FR-302.2** キャッシュは上限（16 タイル）を持ち、超過分は古いものから捨てる。
    → 再抽選を繰り返してメモリが単調増加するのを防ぐ。
- **FR-303 周辺減光** — 感光域に対する放射状の暗化。0〜100 で強度調整。
- **FR-304 感光域の縁** — 次の 2 種から選択する。
  - **FR-304.1** `straight` — 直線の矩形マスク
  - **FR-304.2** `rough` — ノイズで揺らした不規則な境界に、
    柔らかい欠け（塗り残し）を散らしたマスク。外側への膨らみを許すため
    マスクは余白付きで生成する。
- **FR-305** プレート全体に、ごく淡い経年の四隅暗化を常時かける。

### 3.4 レイアウトとラベル（FR-400）

- **FR-401** 台紙の形式を「縦長標本シート（3:4）」「正方形（1:1）」から選択する。
- **FR-402** ラベル帯は感光域の下に置き、次を描画する。
  - 学名（イタリックセリフ、幅に収まるまで自動縮小）
  - 和名・通称（セリフ）
  - 罫線
  - 採集地（スモールキャップス）
  - `DATE` / `COORDINATES` / `SPECIMEN NO.` の 3 欄（タイプライター体）
- **FR-403** 未入力項目は伏字（`----.--.--`、`--.----°`、`—`）で埋め、
  レイアウトを崩さない。
- **FR-404** 緯度経度は Geolocation API による現在地取得ボタンを持つ。
  - **FR-404.1** 許可拒否・取得不能・タイムアウトを区別した日本語メッセージを返す。
  - **FR-404.2** 許可プロンプトの応答待ちは `PositionOptions.timeout` に含まれないため、
    アプリ側で独自の締め切り（12 秒）を設ける。
    → 応答しないままボタンが無効で固まるのを防ぐ。
  - **FR-404.3** 取得値は小数第 4 位までに整形して投入する。
- **FR-405** 緯度は -90〜90、経度は -180〜180 の範囲でのみ座標として整形し、
  範囲外・非数値は伏字にフォールバックする。
- **FR-406** ラベルの各テキストは上限文字数で切り詰め、
  超過分は省略記号にする（帯からの溢れを防ぐ）。

### 3.5 書き出し（FR-500）

- **FR-501** 1× / 2× / 3× の倍率で PNG に書き出す。基準寸法は
  縦長 1200×1600 / 正方形 1200×1200。
- **FR-502** 書き出しはプレビューの拡大ではなく、**指定解像度で全工程を再実行**する
  （誤差拡散・図案生成ともに出力解像度で行う）。
- **FR-503** ファイル名は `cyanotype-<標本番号>.png`。標本番号中の
  ファイル名に使えない文字は `_` に置換する。
- **FR-504** 書き出し中はボタンを無効化し、進行状態を表示する。
  完了・失敗のいずれも結果を明示する。
- **FR-505** 生成した Object URL は必ず解放する。

### 3.6 UI・体験（FR-600）

- **FR-601** 図案ソース未選択時、プレビュー領域は「未感光の台紙」を示す空状態を表示する。
- **FR-602** 重い処理（画像読み込み・図案生成・書き出し）の間は、
  何が起きているかを述べる進行表示を出す。
  - **FR-602.1** 同期的に重い描画を始める前に 1 フレーム譲り、
    進行表示が実際に描画されてから処理に入る。
- **FR-603** エラーは原因と次の行動が分かる日本語で示す。無言で失敗しない。
- **FR-604** 成功（読み込み完了・座標取得・書き出し完了）にも明示的なフィードバックを返す。
- **FR-605** プレビューの再描画は `requestAnimationFrame` で 1 フレームに 1 回へ束ねる。
  スライダーの連続操作でフレームごとに複数回の重い描画を走らせない。
- **FR-606** 図案帳のサムネイル生成はプレビュー描画と独立にスケジュールし、
  スライダー操作のたびに 6 枚を焼き直さない。
- **FR-607** 主要操作はキーボードのみで到達できる。図案帳の各項目は
  ラジオグループとして矢印キーで移動できる。
- **FR-608** `prefers-reduced-motion: reduce` では、装飾的な遷移・脈動を無効化する。

## 4. 非機能要件

- **NFR-001 完全クライアントサイド**
  - **NFR-001.1** 画像・ラベル情報を外部へ送信しない。ネットワーク通信は
    Web フォント取得を除いて行わない。
  - **NFR-001.2** Web フォントの取得に失敗しても、システムフォントに縮退して
    全機能が動作する。
- **NFR-002 配信**
  - **NFR-002.1** `deploy.json` は `{"pages": true}` を維持する。
  - **NFR-002.2** `vite.config.ts` の `base: './'` を維持する
    （GitHub Pages のサブパス配信で壊れないため）。
  - **NFR-002.3** `npm run build` は `dist/` に静的サイト一式を出力する。
- **NFR-003 性能**
  - **NFR-003.1** スライダー操作時のプレビュー再描画は、
    820px 幅プレビューで 1 フレーム 200ms 以内に収まること。
  - **NFR-003.2** 図案帳サムネイル 6 枚の初回生成は 600ms 以内。
  - **NFR-003.3** 3× 書き出し（3600×4800）が現実的な時間で完了すること。
