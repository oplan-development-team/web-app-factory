# サイアノタイプ・ポスターメーカー

写真、または本アプリが手続き的に生成する植物標本図案を、Floyd-Steinberg誤差拡散でプルシアンブルーの二階調ハーフトーンへ変換し、紙の繊維・藍液の塗りムラ・周辺減光・不規則な感光縁まで再現して、植物標本ラベル付きの一枚のサイアノタイプ風ポスターとして高解像度PNGに書き出すWebツールです。

バックエンドを持たず、画像処理・図案生成・書き出しのすべてをブラウザ内で完結させます。入力画像・ラベル情報は一切外部に送信されません。

仕様・実装計画・タスク分解は [`docs/SPEC.md`](docs/SPEC.md) / [`docs/PLAN.md`](docs/PLAN.md) / [`docs/TASKS.md`](docs/TASKS.md) にあります。

## できること

### 図案ソース — 2つの入口

**所蔵標本（プリセット図案）**

手元に素材が無くても一枚目に到達できるよう、アプリ側が植物図案を手続き生成します。静的な画像アセットではなく、シードから決定的に組み立てる図形なので、3×書き出しでも拡大ボケが出ません（出力解像度で直接描き起こします）。

| 図版 | 和名 | 学名 | 意匠の要点 |
|---|---|---|---|
| PL. I | シダ（ワラビ） | *Pteridium aquilinum* | 湾曲する中軸に羽片が交互に並ぶ羽状複葉 |
| PL. II | 海藻（ダルス） | *Delesseria sanguinea* | 二叉分岐する膜状葉。Anna Atkinsの原典的題材 |
| PL. III | 葉脈標本（インドボダイジュ） | *Ficus religiosa* | 主脈・二次脈・網状の三次脈が主役 |
| PL. IV | イチョウ | *Ginkgo biloba* | 扇形の葉身と二叉分枝する平行脈 |
| PL. V | エノコログサ | *Setaria viridis* | 細く弧を描く稈と、剛毛を持つ穂 |
| PL. VI | ノラニンジン | *Daucus carota* | 放射する散形花序の入れ子構造 |

- 図案帳のサムネイルは、固定アイコンではなく**本番と同じ生成器＋同じ誤差拡散**で描いています（選ぶ前に何が出るか分かる）
- 「別個体を採取」でシードのみを振り直せます。種は変わらず、同じシダの別個体が採れます
- 階調は**陰画（フォトグラム）方式**。植物が光を遮って紙色のまま残り、露光した地が藍に沈む、というサイアノタイプ本来の焼き付け方に合わせています。輪郭には接触の甘さを表す半影を持たせ、地には露光ムラを模した低周波の濃淡を入れています

**持ち込み標本（アップロード）**

- JPEG / PNGをドラッグ&ドロップ、またはファイル選択で受け付けます（キーボードのEnter / Spaceでも起動可）
- 感光域への配置は`object-fit: cover`相当（中央基準の切り抜き）で、縦横比を歪めません
- ファイル先頭バイト列のSHA-1から標本番号と質感シードを決定的に導出するため、**同じ写真からは常に同じ紙目・縁のゆらぎ**が再現されます

両者は切り替えても互いの状態（アップロード画像・選択中の標本と個体シード）を保持し、戻せば復元されます。

### 二階調化

- Rec.709輝度（`0.2126R + 0.7152G + 0.0722B`）でグレースケール化
- コントラスト（-100〜100）と感光しきい値（60〜200）を調整
- Floyd-Steinberg誤差拡散で1bit化。走査は行ごとに向きを反転させ（ブースト・スキャン）、一定方向の走査で出る斜めの縞を避けています
- 出力は「インク／紙」の2色のみで、中間色を含みません。濃淡の見えはドットの粗密だけで表現されます

### 質感・レイアウト・書き出し

- 藍液のムラ／紙の繊維／周辺減光を各0〜100で調整。感光域の縁は「直線」と「ラフな手塗り」から選択
- インク・紙色プリセット3種（クラシック濃藍 / 褪色ヴィンテージ / 深藍）
- 台紙は縦長標本シート（3:4）／正方形（1:1）
- 植物標本ラベル（学名イタリック・和名・採集地・緯度経度・採集日・標本番号）。未入力項目は伏字で埋めてレイアウトを崩しません。緯度経度はGeolocation APIでの現在地取得ボタン付き
- 1× / 2× / 3×のPNG書き出し（基準寸法 縦長1200×1600 / 正方形1200×1200）。**書き出しはプレビューの拡大ではなく、指定解像度で全工程を再実行**します

## 技術構成

Vite + TypeScript（バニラ構成、フレームワーク不使用）。画像処理・図案生成はすべてCanvas 2D APIによる自前実装で、外部の画像処理／フィルターライブラリには依存していません。

設計上の要点：

- **描画層は`CanvasRenderingContext2D`に直接依存しない。** 実際に使うメンバーだけを宣言した構造的部分型（`src/core/ctx2d.ts`の`Ctx2D`）に依存させ、Canvasの生成口を注入可能にしています。jsdomにCanvas 2D実装が無いため、これが無いと描画ロジックを一切テストできません
- **図案生成の入口は`drawSpecimen()`の1つに絞る。** 呼び出し側が乱数を渡す形にすると、同じシードでも呼び出し順で図案が変わりえます。プレビュー・サムネイル・書き出しで同じ絵が出ることが要件なので、乱数は`(id, seed)`からのみ組み立てます
- **状態は不変更新のリデューサ**（`src/state/appState.ts`）で扱います
- プレビュー再描画は`requestAnimationFrame`で1フレーム1回に束ね、図案帳サムネイルの生成はプレビュー描画と独立にスケジュールします（スライダー操作のたびに6枚を焼き直さない）
- 繊維テクスチャはシードごとにキャッシュし、上限16タイルで古いものから捨てます（再抽選の繰り返しでメモリが単調増加しないため）

## デザイン方針

自然史博物館の植物標本アーカイブ（19世紀ハーバリウム・シート様式）をエディトリアルに再構成しています。

- **生成物（ポスター本体）**: プルシアンブルー系インク × 生成り〜クリームの紙色の**2色のみ**。実在の単色印画技法としてのリアリティを崩す第三の色を入れません
- **ツールUI（囲い）**: ダークな陳列室の壁に、クリームの索引カードを微妙に傾けて並べ、真鍮の金具を留め具・フォーカス・現在地に限定して効かせる標本キャビネットの構成
- **書体3層**: 学名 = EB Garamondイタリック／日付・座標・標本番号 = Special Elite（タイプライター）／産地・付帯情報 = 本文セリフのスモールキャップス
- 均一なカードグリッド・大きな角丸・影の一律適用を使わず、階層はスケール差・ヘアライン・余白の強弱でつくります

Webフォントの取得に失敗した場合もシステムフォントに縮退して全機能が動作します。

## 開発

```bash
npm install
npm run dev        # 開発サーバー
npm run build      # 型チェック(tsc) + 本番ビルド（dist/ に出力）
npm run preview    # ビルド成果物のプレビュー
npm run test       # 単体・統合テスト（Vitest, カバレッジしきい値80%）
npm run test:e2e   # E2E（Playwright / chromium・firefox・webkit の3エンジン）
```

TypeScriptは`strict` + `noUncheckedIndexedAccess`で通ります。

E2Eは開発サーバーではなく**本番ビルド**に当てます（`base: './'`やCSSの取り込みなど、ビルドを通してはじめて効く設定があるため）。初回は`npx playwright install`でブラウザの取得が必要です。

> **注意**: VitestとPlaywrightを同時に走らせないでください。CPUを奪い合い、本来200ms程度で終わる画素ループのテストがタイムアウトしたり、`page.goto`が30秒を超えたりして、実装とは無関係に赤くなります。順番に実行してください。

```bash
docker run --rm -p 8080:80 cyanotype-poster-maker
# http://localhost:8080 で確認
```

## GitHub Pagesプレビュー

バックエンド不要・完全クライアントサイド完結のため、`deploy.json`は`{"pages": true}`です。mainへのマージをトリガーにGitHub Pagesへ自動デプロイされます。サブパス配信で壊れないよう`vite.config.ts`に`base: './'`を設定しています。

これはあくまで動作確認・共有用のプレビューであり、本番運用時は上記Dockerでのデプロイが前提です。

## 既知の制約

- **Geolocationの許可プロンプト**: 許可プロンプトの応答待ちは`PositionOptions.timeout`に含まれないため、アプリ側で独自の締め切り（12秒）を設けています。プロンプトを放置した場合、12秒後にタイムアウト扱いになります
- **アップロード画像の上限**: 長辺12000px相当／総画素4000万を超える画像は受け付けません（`getImageData`が失敗して無言で真っ白になる事故を防ぐため）
- **3×書き出しの所要時間**: 3600×4800の全工程を再実行するため、端末によっては数秒かかります。書き出し中はボタンを無効化し進行状態を表示します
- **Webフォントの取得**: ネットワーク通信はGoogle Fontsからの書体取得のみ行います（画像・ラベル情報の送信は一切ありません）

## スコープ外

| 項目 | 除外理由 |
|---|---|
| 実際の化学反応（露光時間・薬品）のシミュレーション | 意匠の再現が目的であり、化学的正確さは体験に寄与しない |
| 地名からの自動ジオコーディング | 外部API依存を避ける。座標は手入力＋現在地取得のみ |
| 画像認識による植物種の自動判定 | 外部API / 大きなモデル依存を避ける |
| 複数写真の合成・コラージュ | 「一枚の標本シート」という制約が意匠を成立させている |
| 印刷注文・物理プリント連携 | 外部サービス依存 |
| 作品のギャラリー化・履歴保存・共有 | 単発ツールとしての単純さを保つ |
| 藍以外の色調（セピア・モノクロ） | 「サイアノタイプ」という技法の同一性が失われる |
| 所蔵標本のユーザー追加・自由編集 | 図案は完成された意匠として提示する。パラメータ露出は個体差の再抽選に留める |
