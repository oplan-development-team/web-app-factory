# SPEC: 傾きガチャ（Tilt Gacha）

**Feature ID**: tilt-gacha
**Status**: Approved（要件はメインセッションとユーザーの擦り合わせ済み。本書はその確定要件を仕様化したもの）
**Last updated**: 2026-09-02

---

## 1. 概要

スマートフォンを**振る**と、そのときの**端末の傾き**に応じたパラメトリックな幾何学模様が 1 枚出現し、
**図鑑（コレクション）**に溜まっていく感覚トイ。

出発点は [bookofshapes.com](https://bookofshapes.com) — スライダーで幾何学パターンをリアルタイム生成する
SVG パターン集（黒背景 + 単色の細い線画）。本アプリはその意匠を踏襲しつつ、
**「自由に調整する」道具から「引き当てて集める」トイ**へ操作モデルを反転させている。

バックエンドを持たず、生成・描画・永続化のすべてをブラウザ内で完結させる。

### 1.1 設計上の中心的な判断

| 判断 | 内容 | 理由 |
|---|---|---|
| **自由度をあえて捨てる** | Book of Shapes 本来の「スライダーで無限に調整」という自由度を排し、パラメータ範囲を「型」ごとに制約する | 何でも作れると「引き当てた」感が消える。収集ゲームとして成立させるには、出る側の分布を設計者が握る必要がある |
| **傾きは確率を歪めるだけ** | 傾き → 系統は決定ではなく**重み付き抽選のバイアス**（相性系統 55%） | 完全決定だと「4 方向を順に試して終わり」で 4 回で飽きる。完全ランダムだと傾きを取る意味が消える。バイアスにすることで「たてに構えるとながれが出やすい」という**体感的な学習**が成立する |
| **型ごとに軽い jitter** | 同一の型でも毎回パラメータが微妙に違う | 「同じ型を 2 枚目引いた」ときに完全同一だと収集の手触りが死ぬ。ただし型を跨いで見えるほどの揺れは与えない |
| **決定的生成器 + シードのみ永続化** | 模様は `(系統, レア度, シード)` から決定的に再生成できる。図鑑には**シード整数だけ**保存する | 生成済み SVG を保存すると localStorage を圧迫し、生成ロジック改修時に過去分と整合しなくなる |
| **センサー非対応でも体験が成立する** | ジャイロ非対応環境ではボタンタップ 1 回で抽選が成立する（FR-2xx） | PC・非対応ブラウザ・自動テスト環境で「何も起きない画面」になると検証も共有もできない |

### 1.2 視覚方向

**ダーク・ミニマル / 抑制の効いた光り方。** メインセッションがユーザーと擦り合わせ・承認済みのモックアップに準拠する。

- **地** `#0b0b0c` ／ **カード面** `#131315` ／ **罫線** `#232326`
- **テキスト主色** `#eceae6` ／ **テキスト副色** `#8b8b90`
- **レア度アクセント**: COMMON `#8b8b90`（アクセントなし＝ニュートラル）／ RARE `#8fc4e0`（淡いシアンブルー）／ EPIC `#e0b56a`（淡いアンバーゴールド）
- **書体**: 見出し = Space Grotesk ／ データ・ラベル = JetBrains Mono
- **出現演出**は派手なパーティクル爆発を用いず、**ソフトなグロー + 控えめなフェード / スケール**で表現する

この方向性はテスト容易性や実装の都合で薄めてはならない（NFR-006）。

### 1.3 スコープ外（非目標）

| 項目 | 除外理由 |
|---|---|
| パラメータを直接いじるスライダー UI | 1.1 の「自由度をあえて捨てる」判断と正面から矛盾する |
| アカウント・サーバ同期・図鑑の共有 URL | バックエンドが必要になる |
| 画像書き出し（PNG / SVG ダウンロード） | 今回の確定要件に含まれない。図鑑内で眺める体験に絞る |
| 交換・ガチャ石・スタミナ等の経済システム | 感覚トイの範囲を超える |
| 多言語 UI | 日本語のみ（系統名の英語表記は意匠として使う） |
| コンパス方位（alpha）の利用 | 較正が要り、屋内で不安定。beta / gamma だけで 4 方向は十分に分離できる |

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 系統（family） | 模様の骨格。`FLOW` / `GRID` / `RADIAL` / `NOISE` の 4 種 |
| レア度（rarity） | `COMMON` / `RARE` / `EPIC` の 3 段 |
| 型（type） | 系統 × レア度の組。合計 12 種。図鑑のマス 1 つに対応する |
| 標本（specimen） | 1 回の抽選で得られる模様 1 枚。型 + シード整数で完全に定まる |
| シード（seed） | 標本の jitter を決める 32bit 符号なし整数 |
| 傾き区分（bucket） | シェイク検知時の姿勢の分類。`UPRIGHT` / `LANDSCAPE` / `DIAGONAL` / `INVERTED` の 4 種 |
| 相性系統 | 各傾き区分に対応づけられた、出やすい系統 |
| センサーモード | 実センサーで抽選が駆動されている状態 |
| フォールバックモード | センサーが使えず、タップで抽選が駆動されている状態 |

### 2.1 系統と傾き区分の対応

| 傾き区分 | 表示（フレーバー） | 相性系統 | 系統の日本語 | 骨格 |
|---|---|---|---|---|
| `UPRIGHT` | たて | `FLOW` | ながれ | 波打つ縦線の束 |
| `LANDSCAPE` | よこ | `GRID` | こうし | ドットの格子 |
| `DIAGONAL` | ななめ | `RADIAL` | ほうしゃ | 同心円 |
| `INVERTED` | さかさま | `NOISE` | ゆらぎ | 散らばった点 |

## 3. 機能要件

### 3.1 センサーと許可（FR-0xx）

- **FR-001** 待機画面に「振ってみる」ボタンを 1 つ置く。このボタンのタップは次の 3 つを兼ねる。
  - **FR-001.1** iOS Safari で必要な `DeviceMotionEvent.requestPermission()` および
    `DeviceOrientationEvent.requestPermission()` の呼び出し。**ユーザージェスチャーのハンドラから同期的に呼ぶ**こと
    （`await` を挟んだ後の呼び出しはジェスチャー文脈を失って拒否されるため、2 つの許可要求は
    どちらも同一ハンドラの同期パスから起動し、その後に `Promise.all` で待つ）。
  - **FR-001.2** シェイク検出の開始（センサーモードへの移行）。
  - **FR-001.3** センサーが使えない環境では、そのタップ自体が 1 回の抽選になる（FR-020）。
- **FR-002** `requestPermission` が存在しない環境（Android Chrome・PC 等）では許可要求を行わず、直接リスナーを登録する。
- **FR-003** 許可が `denied` だった場合、または `requestPermission` が例外を投げた場合は、
  エラーで停止せず**フォールバックモードへ降格**する（FR-020）。降格したことは画面上に明示する（FR-053）。

### 3.2 シェイク検出（FR-01x）

- **FR-010** `devicemotion` の `accelerationIncludingGravity` を用い、直前サンプルとの差分ベクトルの大きさが
  閾値を超えたときにシェイクと判定する。
  - **FR-010.1** 判定式は `|Δa| = hypot(Δx, Δy, Δz)`。閾値は **18 (m/s²)**。
  - **FR-010.2** 誤検知抑制のため、最短サンプル間隔 **40ms** 未満のサンプルは無視する。
  - **FR-010.3** 1 度検知したら **900ms** のクールダウンを設け、その間の検知を捨てる
    （1 回の振りで複数枚出るのを防ぐ）。
  - **FR-010.4** `accelerationIncludingGravity` が `null` または全成分 `null` のイベントは、
    「イベントは来たが値がない」として扱い、判定に使わない（FR-021 の降格判定では「値のあるイベント」のみを到達とみなす）。
- **FR-011** シェイク検知と同時に、直近に受信した `deviceorientation` の `beta` / `gamma` を読み取り、傾き区分に分類する。
  - **FR-011.1** 姿勢の読み取りはシェイク検知**時点**の最新値を使う（過去の平均を取らない）。
  - **FR-011.2** `deviceorientation` が一度も到達していない場合は、傾き区分をランダムに割り当てる（FR-020.2 と同じ扱い）。

### 3.3 傾き区分の分類（FR-02x 前段）

- **FR-012** `classifyTilt(beta, gamma)` は次の順で判定する純関数とする。順序に意味があり、上から順に最初に成立したものを返す。

  1. `beta` または `gamma` が `null` / `NaN` → `null`（分類不能。呼び出し側がランダム割り当てにフォールバックする）
  2. `b = normalize(beta)` を `[-180, 180)` に正規化、`g = clamp(gamma, -90, 90)`
  3. `|b| >= 120` → `INVERTED`（画面が伏せ気味 / 完全に反転している）
  4. `b <= -25` → `INVERTED`（水平を越えて奥へ倒れている）
  5. `|g| >= 45` → `LANDSCAPE`
  6. `b >= 55 && |g| < 25` → `UPRIGHT`
  7. 上記以外 → `DIAGONAL`

  - **FR-012.1** この関数は全実数入力に対して必ず 4 区分のいずれか（または `null`）を返し、例外を投げない。
  - **FR-012.2** 卓上に平置き（`beta=0, gamma=0`）は `DIAGONAL` に落ちる。これは仕様であり、
    4 区分のどれでもない「平ら」を 5 つ目の区分として導入しない（確定要件が 4 方向のため）。

### 3.4 抽選（FR-03x）

すべての抽選関数は乱数源 `rng: () => number`（`[0, 1)`）を**引数で受け取る**。
モジュール内部で `Math.random` を直接呼んではならない（NFR-008.3：決定的テストの前提）。

- **FR-030 系統の重み付き抽選** `pickFamily(bucket, rng)`
  - **FR-030.1** 相性系統の重み **0.55**、残り 3 系統に **0.15** ずつ（合計 1.00）。
  - **FR-030.2** 抽選順序は `FLOW → GRID → RADIAL → NOISE` の固定順で累積比較する（テストの決定性のため）。
  - **FR-030.3** `bucket` が `null` の場合は 4 系統均等（各 0.25）とする。
- **FR-031 レア度の重み付き抽選** `pickRarity(rng)`
  - **FR-031.1** `COMMON` **0.70** / `RARE` **0.25** / `EPIC` **0.05**。
  - **FR-031.2** 比較順は `COMMON → RARE → EPIC` の固定順。
- **FR-032 シード** 標本のシードは `rng` から `Math.floor(rng() * 2**32)` で生成する 32bit 符号なし整数。
- **FR-033** 1 回の抽選は `(bucket, rng) → { family, rarity, seed, bucket }` を返す純関数 `drawSpecimen` に集約する。

### 3.5 フォールバック（FR-02x）— 必須要件

- **FR-020** 次のいずれかに該当する環境では、待機画面のボタンタップ 1 回がそのまま 1 回の抽選になる。
  - `DeviceMotionEvent` が存在しない
  - `requestPermission` が `denied` を返した / 例外を投げた
  - FR-021 の降格条件を満たした
  - **FR-020.1** フォールバック時も抽選ロジック（FR-030〜033）は共通のものを使う。
  - **FR-020.2** 傾き区分は 4 区分から**一様ランダム**に割り当てる。フレーバーテキストは「（センサーなし）」の旨を添える（FR-053）。
- **FR-021 自動降格** センサーモードに入った後、**1200ms 以内に値を伴う `devicemotion` イベントが 1 件も到達しない**場合、
  センサー不在とみなしてフォールバックモードへ降格し、その場で 1 回抽選する。
  - 根拠: 実機では静止していても `devicemotion` は連続的に発火するため、「1 件も来ない」ことは
    「シェイクされていない」ではなく「センサーが無い」の十分な判別条件になる。
- **FR-022** センサーモードで待機中も、画面上に**タップで引く導線**を常に残す
  （振れない状況・アクセシビリティ・キーボード操作のため）。この導線は FR-020 と同じ経路を通る。

### 3.6 模様の生成（FR-1xx）

すべての模様は `viewBox="0 0 240 240"` の SVG。**単色・細線**が原則。

- **FR-100 決定性** `buildPattern(family, rarity, seed)` は同一入力に対し常に同一の SVG 構造を返す純関数。
  - **FR-100.1** 乱数は seed から作る `mulberry32`。`Math.random` / `Date` / ロケール依存処理を含めてはならない。
  - **FR-100.2** 出力座標は小数第 2 位に丸める（環境差・スナップショット差を防ぐ）。
- **FR-101 線の原則**
  - **FR-101.1** すべての描画要素は `stroke` で描き、`fill` は `none`（点描の NOISE / GRID のドットのみ `fill` 可）。
  - **FR-101.2** 線幅は **0.6〜1.4** の範囲。細線であることが Book of Shapes の意匠の核であり、太線化してはならない。
  - **FR-101.3** 色は要素側で指定せず `currentColor` を用いる。レア度アクセント色は SVG を包む要素の `color` で与える
    （図鑑のサムネイルと出現演出で同じ生成物を色だけ変えて使い回すため）。
- **FR-102 レア度と層** レア度は**層（layer）の数**として表現する。COMMON = 1 層、RARE = 2 層、EPIC = 3 層。
  - **FR-102.1** 追加層は基層と同じ系統の骨格を保ち、別系統に見えてはならない。
  - **FR-102.2** 追加層は基層より低い不透明度（RARE 第 2 層 0.55、EPIC 第 3 層 0.35）で描き、
    情報量が増えても画面が濁らないようにする。
- **FR-110 系統ごとの骨格とパラメータ範囲**

| 系統 | 基層 | 第 2 層（RARE 以上） | 第 3 層（EPIC） | 主パラメータ範囲 |
|---|---|---|---|---|
| `FLOW` | 波打つ縦線の束 | 逆位相の縦線束 | 横方向の休符帯（水平線 3〜5 本） | 本数 18〜28、振幅 6〜14、周期 1.5〜3.0 周、位相ステップ 0.15〜0.45 |
| `GRID` | ドット格子（半径が中心からの距離で変化） | 半セル分ずらした副格子 | 格子を結ぶ細いヘアライン | 列数 8〜14、基本半径 1.2〜2.6、半径変調 0.3〜1.0 |
| `RADIAL` | 同心円（間隔は非線形） | 放射スポーク 6〜16 本 | 途切れた円弧のリング 2〜4 本 | 円数 10〜20、中心オフセット ±10、間隔指数 0.75〜1.25 |
| `NOISE` | 散らばった点 | 密度の偏り（クラスタ 2〜4 個） | クラスタを囲う破線の輪 | 点数 220〜420、点半径 0.5〜1.1 |

  - **FR-110.1** パラメータは型（系統 × レア度）ごとに範囲が固定され、seed による jitter はその範囲内でのみ動く。
    レア度が上がるほど基層のパラメータ範囲がわずかに密になる方向へシフトしてよいが、
    **系統の骨格が読めなくなるほどの変化を与えてはならない**。
  - **FR-110.2** 生成される要素数の上限は 1 標本あたり **600 要素**。これを超えるパラメータの組を作ってはならない
    （モバイルでの描画コストと、図鑑に 12 枚同時表示したときの負荷のため）。

### 3.7 図鑑と永続化（FR-2xx）

- **FR-200 収集モデル** 図鑑は 12 の型（4 系統 × 3 レア度）を持つ。
  - **FR-200.1** 各型について `{ count, firstSeed, firstAt }` を保持する。
    `count` は通算取得数、`firstSeed` は**初回に引いた標本のシード**、`firstAt` は初回取得時刻（ISO 8601）。
  - **FR-200.2** 図鑑のサムネイルは `firstSeed` から再生成する。したがって
    **同じ型のマスの見た目は初回取得時から変化しない**（「そのとき引いたもの」が標本として残る）。
  - **FR-200.3** 「はじめて発見」の判定は、記録**前**にその型の `count === 0` であったかどうかで行う。
- **FR-201 永続化** `localStorage` のキー `tilt-gacha:collection:v1` に JSON で保存する。
  - **FR-201.1** 保存形式は `{ version: 1, entries: { [typeId]: { count, firstSeed, firstAt } } }`。
  - **FR-201.2** 読み込み時に**スキーマ検証**を行い、次のものは黙って捨てて既定値に落とす:
    JSON パース失敗 / `version` 不一致 / `entries` が非オブジェクト / 未知の `typeId` /
    `count` が正整数でない / `firstSeed` が 32bit 範囲外。破損データで画面が壊れてはならない。
  - **FR-201.3** `localStorage` が利用不可（Safari プライベート・容量超過・例外）でも**アプリは動作を続ける**。
    その場合はメモリ上のみで収集状態を保持し、その旨を図鑑画面に表示する。
  - **FR-201.4** 書き込みは毎回の記録時に行い、失敗しても例外を呼び出し側へ伝播させない。
- **FR-202 進捗** 図鑑の進捗は「収集済みの型の数 / 12」で表す（通算取得数ではない）。

### 3.8 画面（FR-3xx / FR-4xx / FR-5xx）

画面は 3 つ。同時に 1 つだけが表示される。

#### 3.8.1 待機画面（FR-3xx）

- **FR-300** アプリ名 / 説明 / 「振ってみる」ボタン / 図鑑への導線 / 現在の進捗（n / 12）を表示する。
- **FR-301** ボタンタップ後、センサーモードに入ったら**振る待ち状態**の表示に切り替える
  （文言・アニメーションで「振れ」と伝える）。この状態でもタップで引ける（FR-022）。
- **FR-302** フォールバックモードに降格した場合はボタンの文言・補助テキストを「タップで引く」意味に変える（FR-053）。

#### 3.8.2 出現演出画面（Reveal）（FR-4xx）

- **FR-400** 生成された模様を画面中央に大きく表示する。
- **FR-401** 模様の背後にレア度アクセント色の**ソフトなグロー**を敷く（COMMON はニュートラルグレーで、ほぼ無彩な弱いグロー）。
- **FR-402** 次を表示する。
  - 系統名（英語表記 + 日本語訳）例: `FLOW / ながれ`
  - レア度バッジ（`COMMON` / `RARE` / `EPIC`）
  - 検出した傾きのフレーバーテキスト 例: `検出した傾き: たて`
  - 初取得なら「はじめて発見」バッジ
- **FR-403** CTA は 2 つ。「図鑑を見る」（図鑑画面へ）と「もう一度振る」（待機状態へ戻る）。
  - **FR-403.1** 「もう一度振る」で戻ったとき、**許可要求は再度行わない**（既に許可済みならセンサーモードへ直接復帰する）。
- **FR-404** 演出は不透明度とスケールの控えめな変化で行う。派手なパーティクル・画面フラッシュを用いない。

#### 3.8.3 図鑑画面（Collection）（FR-5xx）

- **FR-500** 画面上部に全体進捗 `n / 12 CATALOGUED` とプログレスバーを表示する。
- **FR-501** 4 系統をそれぞれセクションとして縦に並べる。各セクション見出しに系統名（英 + 日）と
  その系統の収集数（例 `2/3`）を表示する。
- **FR-502** 各セクション内は `COMMON` / `RARE` / `EPIC` の **3 列グリッド**。
  - **FR-502.1** 収集済みのマス: その型の模様を（`firstSeed` から再生成して）レア度アクセント色で小さく表示し、
    レア度ラベルと取得数を添える。
  - **FR-502.2** 未収集のマス: **破線枠 + 「?」**でグレーアウト表示する。
- **FR-503** 前の画面へ戻る導線を置く。
- **FR-504** 図鑑が完全に空（0/12）のときも、12 マスすべてが未収集状態で正しく表示される（空状態で崩れない）。

### 3.9 状態表示とフィードバック（FR-05x）

- **FR-050** 画面遷移・抽選結果は `aria-live="polite"` の領域で読み上げ可能にする。
- **FR-051** センサー許可要求中は待機状態であることが分かる表示にする（無反応に見えない）。
- **FR-052** 許可が拒否された場合、原因と次にすべきこと（タップで引ける旨）を明示する。
- **FR-053** フォールバックモードで動作していることは、待機画面と出現演出画面の双方で分かるようにする
  （「センサーなし」でランダムな傾きが割り当てられたことを隠さない）。

## 4. 非機能要件

- **NFR-001 バックエンド非依存** 通信を一切行わない。フォントもセルフホストし、実行時の外部リクエストを 0 にする。
  - **NFR-001.1** モックアップ上は Google Fonts 指定だが、実装では同一書体の
    `@fontsource-variable/space-grotesk` / `@fontsource-variable/jetbrains-mono` をバンドルする。
    理由: 外部リクエストの排除、オフライン動作、レンダリングブロックの回避。**書体そのものは変更しない**。
- **NFR-002 配信**
  - **NFR-002.1** Docker マルチステージ（build → `nginx:alpine` が `dist/` を配信）。
  - **NFR-002.2** `vite.config.ts` に `base: './'`。`deploy.json` は `{"pages": true}`。
- **NFR-003 性能** 出現演出の描画が体感的に引っかからないこと。図鑑 12 マス同時描画で
  DOM 要素数が過大にならないこと（FR-110.2 の上限がこれを担保する）。
  - **NFR-003.1** JS バンドル（gzip）40KB 以内を目安とする（フォントは除く）。
- **NFR-004 モバイルファースト** 主対象は縦持ちスマートフォン。320px 幅で横スクロールが発生しないこと。
  デスクトップ幅でも破綻しないこと。
- **NFR-005 モーション配慮** `prefers-reduced-motion: reduce` のとき、
  出現演出のスケール・移動・ループアニメーションを止め、不透明度の変化のみ（または即時表示）にする。
- **NFR-006 意匠の保全** 1.2 の視覚方向は、テスト容易性や実装の都合で薄めない。
- **NFR-007 アクセシビリティ** すべての操作要素は `<button>` としてキーボード到達可能。
  未収集マスは装飾ではなく状態として読み上げ可能にする。
- **NFR-008 コード品質とテスト**
  - **NFR-008.1** TypeScript `strict` + `noUncheckedIndexedAccess`。
  - **NFR-008.2** DOM 取得は検査付きヘルパを通し、無検査 `as` を使わない。
  - **NFR-008.3** `lib/` は DOM に触れず、乱数・時刻を引数で受け取る（Node 上で決定的に単体テストできる）。
  - **NFR-008.4** Vitest + v8 カバレッジ。**行・分岐・関数・文すべて 80% 以上**をしきい値として強制する
    （対象 `src/**/*.ts`、除外はブートストラップの `src/main.ts` と型のみのファイル）。
  - **NFR-008.5** 1 ファイル 400 行を目安、800 行を上限とする。

## 5. 受け入れ基準（AC）

### 抽選ロジック
- **AC-01** `classifyTilt` が `(beta, gamma)` の代表点 12 通り以上に対し、期待どおりの区分を返す。
- **AC-02** `classifyTilt` が `null` / `NaN` / `±Infinity` / 範囲外角度（`beta=270` 等）で例外を投げず、規定どおりに振る舞う。
- **AC-03** `pickFamily` が、相性系統の境界値（`rng` が 0 / 0.549 / 0.55 / 0.999 を返す）で期待どおりの系統を返す。
- **AC-04** `pickFamily` を各区分について 10,000 回モンテカルロした分布が、相性系統 0.55 ± 0.03 に収まる。
- **AC-05** `pickRarity` が境界値（0 / 0.699 / 0.70 / 0.949 / 0.95 / 0.999）で期待どおりのレア度を返す。
- **AC-06** `pickRarity` の 10,000 回分布が 0.70 / 0.25 / 0.05 それぞれ ± 0.03 に収まる。
- **AC-07** `pickFamily` / `pickRarity` は `rng` が常に 0 を返しても常に 1 を返す直前の値でも、必ず有効な値を返す（未定義を返さない）。

### 生成
- **AC-08** `buildPattern` が同一 `(family, rarity, seed)` に対し 2 回呼び出して**完全に同一の出力**を返す。
- **AC-09** 12 の型 × 50 シードの全数（600 標本）で、要素数が 600 以下、線幅が 0.6〜1.4、`fill` が原則 `none`、
  座標に `NaN` を含まない、という不変条件を満たす。
- **AC-10** レア度 COMMON / RARE / EPIC の層数がそれぞれ 1 / 2 / 3 である。
- **AC-11** 同一型・異なるシードで出力が異なる（jitter が効いている）。

### 永続化
- **AC-12** 未取得の型を記録すると `count=1`・`firstSeed` が記録され、「はじめて発見」と判定される。
- **AC-13** 同じ型を再記録すると `count` が増え、`firstSeed` / `firstAt` は**変わらず**、「はじめて発見」にならない。
- **AC-14** 保存 → 読み込みで収集状態が完全に往復する。
- **AC-15** 壊れた JSON / `version` 不一致 / 未知の `typeId` / 不正な `count` を読み込んでも例外を投げず、
  健全なエントリのみが復元される（またはすべて破棄される）。
- **AC-16** `localStorage` が例外を投げる環境でも記録・読み出しが動作し、アプリが停止しない。

### 画面と体験
- **AC-17** 初回ロード時、待機画面が表示され進捗が `0 / 12` である。
- **AC-18** **センサーが存在しない環境**で「振ってみる」を押すと、1200ms 以内に出現演出画面へ遷移し、
  模様・系統名・レア度・傾きフレーバーが表示される。
- **AC-19** 出現演出画面から「図鑑を見る」で図鑑へ遷移し、今引いた型のマスが収集済み表示になっている。
- **AC-20** 図鑑の未収集マスが破線枠 + 「?」で表示され、収集済みマスに模様が描かれている。
- **AC-21** 「もう一度振る」で待機状態へ戻り、続けて抽選できる。
- **AC-22** リロード後も図鑑の内容が保持されている。
- **AC-23** シェイクイベントを合成して発火させると（`devicemotion` を dispatch）、シェイク経由で抽選が成立する。
- **AC-24** 1 回の連続した振り（クールダウン内の複数閾値超え）で標本が 2 枚以上出ない。
- **AC-25** 320 / 375 / 768 / 1024 / 1440px で横スクロールが発生しない。
- **AC-26** `prefers-reduced-motion: reduce` でスケール・移動アニメーションが無効化される。
- **AC-27** ブラウザのコンソールに ERROR レベルの出力が 0 件。

### 配信と品質
- **AC-28** `npm run build` が型エラー 0 で完了し、`dist/` が生成される。
- **AC-29** `npm test` が全件成功し、カバレッジが行・分岐・関数・文すべて 80% 以上。
- **AC-30** `docker build` が成功し、起動したコンテナの `/` が 200 を返す。
- **AC-31** `deploy.json` が `{"pages": true}` で、`base: './'` によりサブパス配信でもアセットが解決する。
