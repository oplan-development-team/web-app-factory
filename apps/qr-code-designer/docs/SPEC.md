# SPEC: QR Code Designer

**Feature ID**: 001-qr-code-designer
**Status**: Approved (implemented)
**Last updated**: 2026-08-17

---

## 1. 概要

デザイン性の高い QR コードを、ブラウザ内だけで作成・書き出しできる Web ツール。

既存の無料 QR ツールの多くが画一的な黒白の四角ドットしか出力できない点を差別化ポイントとし、
ドット形状・ファインダーパターン形状・グラデーション・ロゴ埋め込みに対応する。
名刺・パンフレット・店舗 POP など**印刷用途**での実用を主眼に置く。

### 1.1 対象ユーザー

- 名刺やショップカードに QR を載せたい個人事業主・小規模店舗
- クライアント資料に QR を配置するデザイナー・コーダー

### 1.2 スコープ外（非目標）

- 動的 QR（短縮 URL リダイレクト、アクセス解析）— サーバーが必要になるため対象外
- QR の読み取り（デコード）機能
- 複数 QR の一括生成 / CSV 取り込み
- 生成物のクラウド保存・共有リンク

---

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| モジュール | QR コードを構成する最小単位の正方形セル |
| マトリクス | モジュールの明暗を表す 2 次元配列。`count × count`（count = 4×version + 17） |
| ファインダーパターン | 3 隅にある 7×7 の位置検出パターン。外枠リング（frame）と中央 3×3（ball）から成る |
| クワイエットゾーン | QR の周囲に必要な余白。仕様上 4 モジュール以上 |
| ECC レベル | 誤り訂正レベル。L(7%) / M(15%) / Q(25%) / H(30%) の 4 段階 |
| ペイント | 塗り指定。単色 / 線形グラデーション / 放射グラデーション のいずれか |

## 3. 機能要件

### FR-001: テキスト入力

- **FR-001.1** 単一のテキストエリアに URL または任意のテキストを入力できる。
- **FR-001.2** 日本語を含むマルチバイト文字を正しくエンコードできる（UTF-8 バイトモード）。
- **FR-001.3** 入力は QR 生成に対してデバウンス（150ms）して反映する。
- **FR-001.4** 入力が空のとき、プレビューはプレースホルダ状態を表示し、書き出しは無効化される。
- **FR-001.5** 現在の ECC レベルで容量超過となる長さが入力された場合、エラーメッセージを表示し、
  プレビューは直前の正常な状態を保持せず「生成できません」状態を表示する。

### FR-002: QR コード生成

- **FR-002.1** ECC レベルを L / M / Q / H から選択できる。
- **FR-002.2** バージョン（サイズ）は入力長と ECC レベルから自動決定する。
- **FR-002.3** **自動 ECC モード**（既定 ON）:
  - ロゴが設定されている場合、ECC を **H** に自動設定する。
  - ロゴが未設定の場合、ECC を **M** に自動設定する。
  - 自動設定が働いた旨を UI 上に明示する。
- **FR-002.4** 自動 ECC モードを OFF にすると、ユーザーが手動で L/M/Q/H を選べる。
- **FR-002.5** クワイエットゾーン（余白）を 0〜8 モジュールの範囲で調整できる。既定値 4。

### FR-003: ドット形状

- **FR-003.1** 本体モジュールの形状を以下から選択できる。
  - `square` — 角ばった四角（既定）
  - `rounded` — 角丸（各モジュール独立、固定半径）
  - `fluid` — 連結角丸（隣接モジュールと繋がり、外周のみ丸める）
  - `dot` — 丸
- **FR-003.2** 形状変更はファインダーパターンには影響しない（FR-004 で独立管理）。
- **FR-003.3** 本体モジュールは単一の SVG `<path>` にまとめて描画する（DOM ノード数・出力サイズ削減のため）。

### FR-004: ファインダーパターン

- **FR-004.1** 外枠（frame）の形状を `square` / `rounded` / `circle` / `leaf` から選択できる。
- **FR-004.2** 中央（ball）の形状を `square` / `rounded` / `circle` / `leaf` から**独立して**選択できる。
- **FR-004.3** frame と ball の色（ペイント）を**それぞれ独立して**指定できる。
- **FR-004.4** 「本体の色を継承」トグルを持ち、ON のとき frame / ball は本体ペイントを使う（既定 ON）。
- **FR-004.5** 3 隅すべてのファインダーパターンに同一の設定が適用される。

### FR-005: カラー / グラデーション

- **FR-005.1** 前景（本体）ペイントとして以下を指定できる。
  - 単色（solid）
  - 線形グラデーション（linear、2 ストップ + 角度 0〜360°）
  - 放射グラデーション（radial、2 ストップ）
- **FR-005.2** 背景ペイントとして FR-005.1 と同じ 3 種を指定できる。
- **FR-005.3** 背景を**透過**（transparent）にできる。
- **FR-005.4** 色はカラーピッカー（`<input type="color">`）と 16 進テキスト入力の両方から設定できる。
  16 進入力は `#RGB` / `#RRGGBB` を受理し、不正値は反映しない。
- **FR-005.5** グラデーションは SVG の `linearGradient` / `radialGradient` として出力され、
  SVG 書き出し・PNG ラスタライズの双方で再現される。

### FR-006: ロゴ埋め込み

- **FR-006.1** 画像ファイル（PNG / JPEG / SVG / WebP）をクリックまたはドラッグ&ドロップでアップロードできる。
- **FR-006.2** アップロードした画像は `FileReader` で data URL 化し、**メモリ上のみで保持**する。
  ネットワーク送信は一切行わない。
- **FR-006.3** ロゴサイズを QR 全体に対する辺の比率 10%〜32% で調整できる。既定 20%。
- **FR-006.4** ロゴ周囲の余白（padding）を 0〜3 モジュールで調整できる。既定 1。
- **FR-006.5** ロゴ背面の座布団形状を `none` / `square` / `rounded` / `circle` から選択できる。既定 `rounded`。
  座布団の塗りは背景ペイントを使う（背景が透過の場合は白）。
- **FR-006.6** ロゴ + padding が覆う矩形領域と重なるモジュールは描画しない（マスクする）。
- **FR-006.7** ロゴを削除できる。削除すると自動 ECC モードは M に戻る。
- **FR-006.8** ファイルサイズ上限は 2MB。超過時はエラーメッセージを表示し読み込まない。
- **FR-006.9** 画像以外の MIME タイプは拒否する。

### FR-007: リアルタイムプレビュー

- **FR-007.1** すべての設定変更はプレビューに即時反映される（テキスト入力のみ 150ms デバウンス）。
- **FR-007.2** プレビューは SVG として DOM に描画され、これがそのまま書き出しの単一ソースとなる
  （プレビューと出力の乖離を構造的に排除する）。
- **FR-007.3** プレビュー背景には市松模様を敷き、背景透過時に透過であることが判別できる。
- **FR-007.4** デスクトップ幅ではプレビューが sticky 表示され、設定をスクロールしても常に見える。

### FR-008: 書き出し

- **FR-008.1** **SVG 書き出し**: プレビューの SVG をシリアライズして `.svg` としてダウンロードする。
  - `xmlns` / `xmlns:xlink` を付与し、単体ファイルとして開けること。
  - ロゴは data URL として埋め込まれ、外部参照を持たないこと。
- **FR-008.2** **PNG 書き出し**: 512 / 1024 / 2048 / 4096 px から解像度を選択してダウンロードする。
  - 各解像度について 300dpi 換算の実寸（mm）を UI に併記する。
  - 背景透過設定時は透過 PNG として出力する。
- **FR-008.3** ファイル名は入力内容から生成した安全なスラグ + 日付（例: `qr-example-com-20260817.svg`）。
- **FR-008.4** 書き出しはすべて `Blob` + `URL.createObjectURL` によるローカルダウンロードで行う。

### FR-009: スキャン耐性チェック

プレビュー更新のたびに以下を評価し、結果を一覧表示する。
総合判定は `safe`（安全） / `caution`（注意） / `risk`（危険）の 3 段階。

- **FR-009.1 ロゴ被覆率**: マスク領域の面積 ÷ QR 本体面積 を算出し、ECC 容量と比較する。
  - `coverage <= capacity * 0.5` → safe
  - `coverage <= capacity * 0.8` → caution
  - それ以上 → risk
- **FR-009.2 コントラスト比**: 背景から浮き上がる必要のある**すべての層**（前景、および
  色を継承していない場合はファインダー外枠・中央）について、
  各層の全ストップ × 背景の全ストップの WCAG コントラスト比の**最小値**を取る。
  - `>= 4.5` → safe / `>= 3.0` → caution / それ未満 → risk
  - 最も弱い層の名前をメッセージに含める（ファインダーは読み取り機が最初に探す部位のため、
    ここが低コントラストだと本体が読めても検出に失敗する）。
- **FR-009.3 明暗反転**: 前景の相対輝度が背景より高い場合 caution（一部の古い読み取り機が非対応）。
- **FR-009.4 クワイエットゾーン**: margin < 4 のとき caution、margin = 0 のとき risk。
- **FR-009.5 背景透過**: 透過時、配置先の地色によっては読み取れない旨を info として表示。
- **FR-009.6 ドット形状**: 丸ドットはモジュールの塗り面積が約 79%（π/4）に減る。
  読み取り機はモジュール中心付近をサンプリングするため通常は問題にならないので、
  警告は訂正の余裕が無い場合に限る。
  - `dot` かつ ECC = L → caution
  - `dot` かつ ECC = M → info（総合判定は下げない）
  - それ以外 → 判定なし
- **FR-009.7** 総合判定が `risk` のとき、書き出しは可能だが警告を明示する（ブロックはしない）。
- **FR-009.8** 判定結果は `aria-live="polite"` 領域で読み上げ可能にする。

### FR-010: デザインプリセット

- **FR-010.1** 6 種のキュレーション済みプリセットをギャラリーから 1 クリックで適用できる。
- **FR-010.2** プリセット適用はテキスト・ロゴ・ECC 設定を保持し、見た目に関する設定のみ差し替える。
- **FR-010.3** 各プリセットは実際の QR サムネイルではなく、配色と形状を表す軽量なスウォッチで表示する。

## 4. 非機能要件

### NFR-001: プライバシー（最重要）

- **NFR-001.1** 入力テキスト・ロゴ画像を含む一切のユーザーデータをネットワーク送信しない。
- **NFR-001.2** アプリケーションは実行時に**いかなる外部ドメインへのリクエストも発行しない**。
  - Web フォントの CDN 読み込みを禁止する（フォントは同梱するか、システムフォントを使う）。
  - アナリティクス・エラー収集 SDK を一切導入しない。
- **NFR-001.3** 上記をユーザーに明示するバッジを UI に常設する。

### NFR-002: 配信形態

- **NFR-002.1** バックエンド不要。静的ホスティング（`dist/` を置くだけ）で動作する。
- **NFR-002.2** ルート相対パス依存を避け、サブディレクトリ配信でも動作させる（`base: './'`）。

### NFR-003: パフォーマンス

- **NFR-003.1** 初期 JS バンドル 150KB（gzip）未満、CSS 30KB（gzip）未満。
- **NFR-003.2** 設定変更からプレビュー反映までの体感遅延を 100ms 未満に保つ
  （マトリクス生成とパス生成をメモ化する）。
- **NFR-003.3** 本体モジュールは 1 つの `<path>` に統合し、DOM ノード数を抑える。

### NFR-004: レスポンシブ

- **NFR-004.1** 320 / 375 / 768 / 1024 / 1440 / 1920 px で横スクロールが発生しないこと。
- **NFR-004.2** 1024px 以上で 2 カラム（プレビュー sticky + 設定レール）、
  それ未満で 1 カラム（プレビュー → 設定の順）。

### NFR-005: アクセシビリティ

- **NFR-005.1** すべての操作をキーボードのみで完了できる。
- **NFR-005.2** 形状ピッカーは `role="radiogroup"` / `role="radio"` を持ち、矢印キーで選択を移動できる。
- **NFR-005.3** すべてのフォーム要素に可視ラベルまたは `aria-label` を持つ。
- **NFR-005.4** フォーカスリングを `:focus-visible` で明示する。
- **NFR-005.5** UI テキストと背景のコントラスト比は本文 4.5:1 以上、大きな文字 3:1 以上。
- **NFR-005.6** `prefers-reduced-motion: reduce` を尊重し、装飾アニメーションを無効化する。

### NFR-006: デザイン品質

- **NFR-006.1** 汎用テンプレート然とした外観（均一カードグリッド、中央寄せヒーロー、
  ライブラリ既定値そのまま）を避ける。
- **NFR-006.2** 印刷スタジオを想起させる方向性を採用し、
  プレビューをトンボ（トリムマーク）付きの「校正紙」として提示する。
- **NFR-006.3** スケールのコントラスト、意図的な余白リズム、レイヤー感、
  設計されたホバー/フォーカス状態を備える。

### NFR-007: ブラウザサポート

- Chrome / Edge / Firefox / Safari の最新 2 バージョン。
- `<input type="color">`、`FileReader`、`URL.createObjectURL`、`canvas.toBlob` に依存する。

## 6. エッジケース

| ケース | 期待挙動 |
|--------|---------|
| 入力が空 | プレースホルダ表示、書き出しボタン無効 |
| 入力が容量超過（ECC H で約 1000 文字超など） | 「テキストが長すぎます」エラー + ECC を下げる提案 |
| 入力が空白のみ | 空と同等に扱う |
| ロゴが 2MB 超 | エラーメッセージ、読み込まない |
| ロゴが画像以外 | エラーメッセージ、読み込まない |
| ロゴが極端な縦横比 | `preserveAspectRatio="xMidYMid meet"` で枠内に収める |
| 16 進入力に不正値 | 直前の有効値を維持し、反映しない |
| グラデーション 2 ストップが同色 | 実質単色として描画（エラーにしない） |
| 余白 0 かつ背景透過 | クワイエットゾーン risk + 透過 info の両方を表示 |
| PNG 書き出し中に設定変更 | 書き出し中はボタンを disabled にし、多重実行を防ぐ |
| ロゴ SVG に外部参照が含まれる | data URL 化された時点で外部参照は解決されない旨は仕様の限界として許容 |

## 7. アーキテクチャ制約

- **単一ソース原則**: プレビュー SVG が唯一の描画実装。PNG はその SVG をラスタライズして得る。
  Canvas 用の別描画パスを持たない。
- **純粋関数分離**: マトリクス生成・パス生成・色計算・安全性判定は React に依存しない純関数として
  `src/lib/` に置き、単体テスト対象とする。
- **状態は単一の `QrDesign` オブジェクト**として保持し、更新は常に新しいオブジェクトを返す（不変更新）。

## 8. 既知の限界（仕様として許容）

- スキャン耐性チェックは**静的な推定**であり、アプリ実行中に実際のデコード検証は行わない。
  実運用前の実機テストを UI 上で促す。
- 明暗反転デザイン（ネオンプリセット等）は、素の ZXing のように反転リトライを持たない
  読み取り機ではデコードできない。スマートフォンのカメラアプリは概ね対応する。
  この差は FR-009.3 の caution として明示する。
- ロゴ SVG 内の外部リソース参照（外部フォント・外部画像）は解決されない。
- 4096px PNG の生成はブラウザとマシンによって数百 ms〜数秒かかる。
