# PLAN: QR Code Designer

対応 SPEC: `./SPEC.md`

---

## 1. 技術選定

| 領域 | 選定 | 理由 |
|------|------|------|
| ビルド | Vite 8 | 設定ゼロに近く、`base: './'` で静的ホスティングにそのまま置ける。開発時の HMR がリアルタイムプレビュー開発と相性が良い |
| UI | React 19 + TypeScript | 設定項目が多く状態が複雑。SVG を宣言的に組み立てられる点が「プレビュー = 出力ソース」原則と噛み合う |
| QR 生成 | `qrcode-generator` 2.0.4 | **生のモジュールマトリクス**（`isDark(r,c)`）を取れる最小ライブラリ。描画を持たないため独自形状描画に最適。UTF-8 対応あり |
| 描画 | 手書き SVG（React 要素） | Canvas を持たず SVG 単一実装。SVG 書き出しがシリアライズだけで済み、PNG はそれをラスタライズするだけになる |
| スタイル | 素の CSS + カスタムプロパティ | Tailwind を使うとテンプレート的な見た目に流れやすい。デザイントークンを CSS 変数で定義し、意図的な設計を保つ |
| フォント | `@fontsource` で同梱 | NFR-001.2（外部リクエスト禁止）を満たすため CDN を使わない。日本語はシステムフォントにフォールバック |
| テスト | Vitest | 純粋ロジック（`src/lib/`）の単体テスト。Vite と設定を共有できる |

### 却下した選択肢

- **`qr-code-styling`**: 要件の大半を内包するが、描画・エクスポートまで抱え込むため独自デザインの自由度が下がり、
  差別化ポイント（ファインダー個別制御・独自形状）を実装しにくい。バンドルも重い。
- **`qrcode` (npm)**: マトリクスは取れるが CJS + Node 向け依存（pngjs 等）を含み、ブラウザバンドルが太る。
- **素の HTML/CSS/JS（ビルドなし）**: 状態管理が手続き的になり、設定項目数に対して破綻しやすい。
- **Next.js**: SSR/API が不要な純クライアントアプリに対して過剰。

## 2. アーキテクチャ

```
入力 (QrDesign state)
   │
   ├─ lib/qr.ts        text + ecc  →  Matrix { size, isDark(r,c) }        [memo]
   │
   ├─ lib/paths.ts     Matrix + shape + logoMask  →  SVG path "d" 文字列   [memo]
   │                     ├ buildBodyPath()      本体モジュール（1 path に統合）
   │                     ├ buildEyeFramePath()  ファインダー外枠（evenodd リング）
   │                     └ buildEyeBallPath()   ファインダー中央
   │
   ├─ lib/safety.ts    Design + Matrix  →  SafetyReport { level, findings[] }
   │
   └─ components/QrPreview.tsx
          └ <svg viewBox="0 0 W W">   ← モジュール単位の座標系（解像度非依存）
                <defs> gradients </defs>
                <rect> background </rect>
                <path> body </path>
                <path> eye frames ×3 </path>
                <path> eye balls ×3 </path>
                <shape+image> logo </shape+image>
                       │
                       ├─ lib/export.ts  serializeSvg()  → .svg ダウンロード
                       └─ lib/export.ts  rasterize()     → canvas → .png ダウンロード
```

**単一ソース原則**: `QrPreview` が描画した実際の DOM ノードを `exportSvg` / `exportPng` が読む。
別の描画実装を持たないため、プレビューと出力が構造的に一致する。

**座標系**: SVG の `viewBox` を「モジュール単位」（`size + margin*2`）にする。
これにより全パス生成が整数格子上の単純な計算になり、任意解像度へのスケールは viewBox が吸収する。

## 4. デザイン方向性

**「プリントスタジオ」** — 印刷用途（名刺・POP）という文脈に合わせた、紙とインクの質感を持つ明るいエディトリアル。

- **地**: 温かみのあるオフホワイト（`oklch(97.5% 0.008 85)`）。設定レールは 1 段沈んだ紙面。
- **インク**: 深いウォームブラック。見出しは高コントラストのセリフ（Instrument Serif）で字面に主張を持たせる。
- **アクセント**: 単一の朱色（`oklch(58% 0.19 32)`）。装飾ではなく「現在の選択」「警告」の意味に紐づけて使う。
- **プレビュー台**: カッティングマット風のドットグリッド + **トンボ（トリムマーク）**を四隅に配置し、
  校正紙のメタファーを作る。これが「よくある QR ツール」との第一印象の差になる。
- **リズム**: 均一パディングを避け、セクション見出しは大きく空け、コントロール間は詰める。
- **状態**: hover で紙が持ち上がる（`translateY` + shadow）、focus-visible で朱色のリング + オフセット。

避けるもの: 均一カードグリッド、中央寄せグラデーションヒーロー、既定のダークモード、
ライブラリ既定のシャドウ/角丸の使い回し。

## 5. リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| SVG → Canvas ラスタライズが Safari で寸法を誤る | PNG が壊れる | シリアライズ時に `width`/`height` 属性を明示的に付与する |
| ロゴ data URL が canvas を汚染し `toBlob` が失敗 | PNG 書き出し不可 | 外部 URL を使わず必ず data URL 化する（FR-006.2 と整合） |
| 4096px ラスタライズが重くフリーズ | UX 低下 | 書き出し中は非同期 + ボタン disabled + ラベル変更で状態を明示 |
| `qrcode-generator` が容量超過で throw | 画面が落ちる | 生成を try/catch し、`{ ok: false, error }` を返す形に包む |
| 日本語が文字化け | 実用不能 | `qrcode.stringToBytes = stringToBytesFuncs['UTF-8']` をモジュール読み込み時に一度だけ設定 |
| 形状変更でスキャン不能な QR を出力してしまう | 実害 | FR-009 の静的判定 + 実機テスト推奨の常設表示 |
| 日本語 Web フォント同梱でバンドル肥大 | NFR-003 違反 | 欧文のみ同梱し、日本語はシステムフォントにフォールバック |

## 6. 検証計画

1. `npm run build` が型エラー 0 で通ること、バンドルサイズが NFR-003.1 を満たすこと。
2. `npm run test` で `src/lib/` の単体テストが全通過すること。
3. 実ブラウザで起動し、コンソールエラー 0 件を確認（AC-20）。
4. AC-01〜AC-18 を実ブラウザ操作で確認。
5. 書き出した PNG / SVG を実際に読み取り、AC-19 を確認。
6. DevTools Network で外部ドメインへのリクエストが 0 件であることを確認（AC-16）。
7. 320px / 768px / 1440px で横スクロールが無いことを確認（AC-17）。
