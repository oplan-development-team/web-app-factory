# QR Designer

デザイン性の高い QR コードを、ブラウザの中だけで作成・書き出しできるツール。
ロゴ埋め込み・ドット形状・ファインダー形状の個別制御・グラデーションに対応する。
名刺・パンフレット・店舗 POP など**印刷用途**を主眼に置いている。

仕様は [`docs/SPEC.md`](docs/SPEC.md)、設計は [`docs/PLAN.md`](docs/PLAN.md)、
タスク分割は [`docs/TASKS.md`](docs/TASKS.md) を参照。

---

## 使い方

```bash
npm install
npm run dev     # 開発サーバー
npm run build   # dist/ を生成（静的ホスティングにそのまま置ける）
npm run test    # 単体テスト
```

バックエンドは不要。`dist/` を任意の静的ホストに置くだけで動く。
`base: './'` を設定しているのでサブディレクトリ配信でも動作する。

### Docker

```bash
docker build -t qr-code-designer .
docker run --rm -p 8080:80 qr-code-designer
# http://localhost:8080
```

ビルド済みの `dist/` を nginx で配信するだけのマルチステージ構成（実行時イメージは約62MB）。

## 機能

- **入力**: URL または任意テキスト（日本語を含むマルチバイト対応）
- **誤り訂正レベル**: L / M / Q / H。自動モードではロゴの有無で H / M を選択
- **ドット形状**: 四角 / 角丸 / 連結（隣接モジュールが繋がる） / 丸
- **ファインダーパターン**: 外枠と中央を、形状（四角 / 角丸 / 円 / リーフ）も色も**個別に**設定
- **カラー**: 前景・背景それぞれ単色 / 線形グラデーション（角度指定） / 放射グラデーション。背景の透過も可
- **ロゴ**: ドラッグ&ドロップで埋め込み。サイズ・余白・座布団形状を調整でき、下のモジュールは自動でマスク
- **プリセット**: 6 種。配色と形だけを差し替え、入力内容とロゴは保持
- **スキャン耐性チェック**: コントラスト・余白・ロゴ被覆率・明暗反転などを常時判定して表示
- **書き出し**: SVG と PNG（512 / 1024 / 2048 / 4096px、300dpi 換算の実寸を併記）

## プライバシー

入力テキストもロゴ画像も**端末の外に出ない**。

- サーバーを持たない（純クライアントアプリ）
- 実行時に**外部ドメインへのリクエストを一切発行しない**
  - Web フォントも CDN ではなく `@fontsource` で同梱している
  - アナリティクス・エラー収集の類は入れていない

この性質は Playwright でネットワークを記録して検証済み（外部リクエスト 0 件）。

## 技術選定

| 領域 | 選定 | 理由 |
|------|------|------|
| ビルド | Vite + React + TypeScript | 設定項目が多く状態が複雑なため宣言的に SVG を組み立てたい。静的出力がそのまま配信できる |
| QR 生成 | `qrcode-generator` | **生のモジュールマトリクス**だけを返す最小ライブラリ。描画を持たないため独自形状を自由に描ける |
| 描画 | 手書き SVG | Canvas 実装を持たない。SVG 書き出しはシリアライズだけ、PNG はそれをラスタライズするだけで済む |
| スタイル | 素の CSS + カスタムプロパティ | Tailwind はテンプレート的な見た目に流れやすい。トークンを CSS 変数で定義している |
| フォント | `@fontsource` で同梱 | 外部リクエスト禁止のため。日本語はシステムフォントにフォールバック |
| テスト | Vitest | 純粋ロジック（`src/lib/`）の単体テスト |

`qr-code-styling` は要件の大半を内包するが、描画とエクスポートまで抱え込むため
ファインダー個別制御などの差別化ポイントを実装しにくく、バンドルも重いので採用しなかった。

### 設計上の要点

**プレビューの SVG が唯一の描画実装**である。`ExportPanel` は画面に出ている SVG ノードを
そのままシリアライズ／ラスタライズするので、プレビューと出力が構造的にずれない。

座標系は `viewBox` を「モジュール単位」に取っているため、すべてのパス生成が整数格子上の
単純な計算になり、任意解像度へのスケールは `viewBox` が吸収する。

```
src/lib/     React に依存しない純粋ロジック（テスト対象）
  qr.ts        text + ECC → モジュールマトリクス
  geometry.ts  コーナー別半径の角丸矩形パス（全形状の共通プリミティブ）
  paths.ts     マトリクス + 形状 + ロゴマスク → SVG パス
  color.ts     hex 正規化 / 相対輝度 / コントラスト比 / グラデーション
  safety.ts    スキャン耐性の判定
  export.ts    シリアライズ / ラスタライズ / ファイル名生成
src/components/  UI
src/hooks/       状態管理とメモ化
```

## 検証状況

- 単体テスト 92 件（`src/lib/` 全モジュール）
- 実ブラウザ（Chromium）で受け入れ基準 27 項目を自動確認：コンソールエラー 0 件、
  外部リクエスト 0 件、320〜1920px で横スクロールなし
- キーボード操作：88 個のタブストップすべてにアクセシブルな名前とフォーカスリングがあること、
  ラジオグループの矢印キー移動を確認
- **読み取り検証**: ドット形状 4 種 × 外枠 4 種 × 中央 4 種 = 64 通りを 320px / 1024px で
  書き出し、ZXing でデコード → **128/128 成功**。プリセット全種・ロゴ埋め込み・
  透過背景・4096px 出力についてもデコード成功を確認

> 検証スクリプトはリポジトリに含めていない（このアプリの依存を軽く保つため）。
> 恒久的な E2E が必要になった時点で Playwright を devDependency に追加する。

## 既知の制約

- スキャン耐性チェックは**静的な推定**。実際のデコード検証はアプリ内では行わないので、
  印刷・掲出の前に実機での読み取りテストを推奨する（UI 上にも常時表示している）。
- **明暗反転デザイン**（「ネオン」プリセットなど）は、反転リトライを持たない読み取り機では
  デコードできない。スマートフォンのカメラアプリは概ね対応する。この差はアプリが「注意」として警告する。
- ロゴに SVG を使った場合、その SVG 内部からの外部リソース参照（外部フォント・外部画像）は解決されない。
- 4096px の PNG 生成はマシンによって数百 ms〜数秒かかる。生成中はボタンを無効化している。
- 動的 QR（短縮 URL / アクセス解析）は非対応。サーバーが必要になるため意図的にスコープ外。
