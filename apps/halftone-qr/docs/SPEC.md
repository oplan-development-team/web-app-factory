# SPEC: Halftone QR Generator

**Feature ID**: 002-halftone-qr
**Status**: Approved (依頼内容および `PROJECTS.md` の要件記述をもって承認済みとみなす)
**Last updated**: 2026-08-18

---

## 1. 概要

画像をアップロードすると、その画像の見た目を保ったまま読み取り可能な QR コードに変換する
ブラウザ完結型ツール。

姉妹アプリ `apps/qr-code-designer/` の「QR の中央にロゴを載せる」方式とは異なり、
**画像全体を QR コードの模様そのものに溶け込ませる**点が本アプリの差別化ポイントである。

理論的背景は Chu et al. "Halftone QR Codes"（SIGGRAPH Asia 2013）。
本アプリはその中核アイデア（3×3 サブモジュール分割 + 中央ビット固定）を実装する。

### 1.1 対象ユーザー

- ポスター・ZINE・フライヤーなど印刷物に「絵として成立する QR」を載せたいデザイナー
- SNS プロフィール画像やアー写を QR にしたい個人クリエイター

### 1.2 スコープ外（非目標）

- **カラー画像対応**（初期版はグレースケール・ハーフトーンのみ。カラーは将来拡張）
- 動的 QR（短縮 URL、アクセス解析）— サーバーが必要になるため対象外
- QR 以外のコード（バーコード、Data Matrix 等）
- 生成物のクラウド保存・共有リンク
- 論文にある「誤り訂正符号の再エンコードによる最適化」（複数の等価コードワード候補から
  画像適合度が最大のものを選ぶ手法）。初期版では実装しない（PLAN §6 参照）
- SVG 書き出し（ハーフトーンは本質的にビットマップのためスコープ外。PNG のみ）

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| モジュール | QR コードを構成する最小単位の正方形セル |
| マトリクス | モジュールの明暗を表す 2 次元配列。`N × N`（N = 4×version + 17） |
| **サブモジュール** | 1 モジュールを 3×3 に分割した各セル。全体では `3N × 3N` のグリッドになる |
| **中央サブモジュール** | 各モジュールの 3×3 の中心。元 QR のビット値を必ず保持する |
| 機能パターン | ファインダー / 分離パターン / タイミング / 位置合わせ / 形式情報 / 型番情報の総称 |
| クワイエットゾーン | QR 周囲に必要な余白。仕様上 4 モジュール以上 |
| ECC レベル | 誤り訂正レベル。L(7%) / M(15%) / Q(25%) / H(30%) |
| ハーフトーン | 濃淡を白黒 2 値のドット密度で表現する手法 |
| 誤差拡散 | ハーフトーン化の手法。量子化誤差を近傍画素へ配分する（Floyd–Steinberg 等） |
| **QR らしさ** | 非中央サブモジュールを元モジュール値へ引き寄せる強度 λ。画像再現度とのトレードオフ |

## 3. 機能要件

### FR-001: エンコード対象テキスト入力

- **FR-001.1** テキストエリアに URL または任意のテキストを入力できる。
- **FR-001.2** 日本語を含むマルチバイト文字を正しくエンコードできる（UTF-8 バイトモード）。
- **FR-001.3** 入力は QR 生成に対してデバウンス（200ms）して反映する。
- **FR-001.4** 入力が空のとき、プレビューはプレースホルダ状態を表示し、書き出しを無効化する。
- **FR-001.5** 現在の ECC レベルで容量超過となる長さが入力された場合、
  エラーメッセージを表示し「生成できません」状態にする（直前状態は保持しない）。
- **FR-001.6** 初期状態ではデモ用の既定テキストが入っており、画像未選択でも通常 QR は表示される。

### FR-002: QR コード生成

- **FR-002.1** ECC レベルは既定で **H**（30%）とする。
- **FR-002.2** ECC レベルは H / Q / M から選択できる。L は選択肢に含めない
  （ハーフトーン化により大量のノイズが乗るため、L では実用に耐えないと判断）。
- **FR-002.3** バージョン（サイズ）は入力長と ECC レベルから自動決定する。
- **FR-002.4** **ECC 自動調整**（既定 ON）: 画像が読み込まれている間は ECC を H に固定する。
  ユーザーが明示的に自動調整を OFF にした場合のみ Q / M を選択できる。
- **FR-002.5** 生成した QR の各モジュールについて、機能パターンの種別
  （finder / separator / timing / alignment / format / version / data）を判定できる。

### FR-003: 画像アップロード

- **FR-003.1** ファイル選択ダイアログから画像を選択できる。
- **FR-003.2** ドロップゾーンへのドラッグ&ドロップで画像を読み込める。
- **FR-003.3** ドラッグ中はドロップゾーンの状態変化を視覚的に示す。
- **FR-003.4** 対応形式は PNG / JPEG / WebP / GIF（静止画として先頭フレーム）/ SVG。
  非対応形式・画像以外が投入された場合はエラーメッセージを表示し、既存の画像は保持する。
- **FR-003.5** ファイルサイズ上限は 20MB。超過時はエラーメッセージを表示する。
- **FR-003.6** 読み込んだ画像はメモリ上（`ImageBitmap` / ObjectURL）でのみ扱い、
  ネットワークへ送出しない（NFR-001）。
- **FR-003.7** 画像はクリアでき、クリア後は通常 QR のみのプレビューに戻る。
- **FR-003.8** ドロップゾーンはキーボード操作（Tab フォーカス → Enter / Space）で
  ファイル選択ダイアログを開ける。

### FR-004: 画像とモジュールのアライメント

- **FR-004.1** ズーム倍率を 0.5〜3.0 の範囲で調整できる（既定: 画像全体が収まる cover フィット = 1.0）。
- **FR-004.2** 水平位置 / 垂直位置のオフセットを -1.0〜1.0 の範囲で調整できる（既定 0）。
- **FR-004.3** 「リセット」でズーム・オフセットを既定値に戻せる。
- **FR-004.4** 画像はアスペクト比を保ったまま QR の正方形領域に **cover** 方式で配置する
  （はみ出した部分はトリミングされる）。
- **FR-004.5** 透明ピクセルは**白**として合成してからグレースケール化する。

### FR-005: 階調調整

- **FR-005.1** 明度を -100〜+100 で調整できる（既定 0）。
- **FR-005.2** コントラストを -100〜+100 で調整できる（既定 0）。
- **FR-005.3** 白黒反転のオン/オフを切り替えられる（既定 OFF）。
- **FR-005.4** グレースケール化は Rec.709 輝度係数（0.2126 / 0.7152 / 0.0722）で行う。

### FR-006: ハーフトーン変換（本アプリの中核）

- **FR-006.1** QR の 1 モジュールを 3×3 のサブモジュールに分解し、`3N × 3N` のグリッドを構成する。
- **FR-006.2** **各モジュールの中央サブモジュールは、元 QR のモジュール値（黒/白）を必ず保持する。**
  この不変条件は QR らしさスライダーや他の設定によって破られてはならない。
- **FR-006.3** 中央以外の 8 サブモジュールは、対応位置の画像の濃淡に応じて誤差拡散法で決定する。
- **FR-006.4** 誤差拡散は Floyd–Steinberg 係数（7/16, 3/16, 5/16, 1/16）を用い、
  蛇行走査（serpentine）で行う。奇数行では係数を左右反転する。
- **FR-006.5** 中央サブモジュール（および機能パターン保護されたサブモジュール）で発生した
  量子化誤差も近傍へ拡散する。ただし誤差は ±0.55 にクランプし、
  強制ビットが縞状アーティファクトを生むのを防ぐ。
- **FR-006.6** **QR らしさ** λ（0〜1、既定 0.35）で、非中央サブモジュールの目標輝度を
  元モジュール値へ引き寄せる:
  `mix = λ·w + λ²·(1 - w)`
  `target' = target × (1 - mix) + moduleLuma × mix`
  重み w は 4 近傍（上下左右）で 1.0、斜め 4 隅で 0.55 とする
  （隅は隣接モジュールと視覚的に共有されるため、自由度を残して画像再現度を優先する）。
  - 二次項を持たせているのは、単純な `λ·w` だと λ を最大にしても斜め 4 隅が
    画像に従い続け、**スライダーを振り切っても元の QR に戻らない**ためである。
    スライダー上端は「最も読み取りやすい状態」である必要がある。
  - したがって **λ = 1 のとき、保護レベルによらず出力は元の QR の 3 倍拡大と完全一致する**。
- **FR-006.7** **機能パターン保護レベル**を 3 段階から選択できる:
  | 値 | ラベル | 保護対象（9 サブモジュール全てを元モジュール値で塗る） |
  |----|--------|------|
  | `none` | 画像優先 | なし（中央固定のみ） |
  | `patterns` | 標準（既定） | ファインダー / 分離パターン / タイミング / 位置合わせ |
  | `all` | 最大 | 上記 + 形式情報 + 型番情報 |
- **FR-006.8** 変換は同期的に実行され、設定変更に対してリアルタイム（NFR-003）に反映される。

### FR-007: プレビュー

- **FR-007.1** 変換前（通常の QR）と変換後（ハーフトーン QR）を**並べて比較表示**する。
- **FR-007.2** 設定（テキスト・画像・アライメント・階調・λ・保護レベル）の変更を
  リアルタイムに反映する。
- **FR-007.3** 画像が未選択のときは、ハーフトーン側に「画像を選択してください」の
  プレースホルダを表示する。
- **FR-007.4** プレビューは canvas で描画し、`image-rendering: pixelated` により
  サブモジュールの輪郭がぼやけないようにする。
- **FR-007.5** 狭い画面幅（< 720px）では 2 面比較を縦積みに切り替える。

### FR-008: 読み取り可能性の判定

- **FR-008.1** 生成したハーフトーン QR の**実ピクセルを実際にデコード**して読み取り可能性を判定する。
  判定器には ZXing（`@zxing/library` の `QRCodeReader`）を用いる。
- **FR-008.2** 判定は「スキャン条件マトリクス」で行う。
  解像度 3 段階（サブモジュールあたり 2 / 3 / 5 px 相当）× ぼかし 3 段階
  （半径 0 / 1 / 2 px 相当）の計 **9 試行**を実施する。
- **FR-008.3** 各試行は、デコードに成功し、かつ**復号結果が入力テキストと完全一致**した場合のみ成功とみなす。
- **FR-008.4** 成功数から総合判定を表示する:
  | 成功数 | 判定 | 意味 |
  |--------|------|------|
  | 9 / 9 | 良好 | 全条件で読めた |
  | 6〜8 | 概ね良好 | 悪条件で読めないことがある |
  | 1〜5 | 不安定 | 印刷サイズ・照明によっては読めない |
  | 0 | 読み取り不可 | 設定の見直しが必要 |
- **FR-008.5** 判定は重い処理のため **Web Worker** 上で実行し、UI をブロックしない。
- **FR-008.6** 判定中は「判定中」状態を表示する。設定が連続変更された場合は
  最新の入力に対する結果のみを反映する（古い結果は破棄する）。
- **FR-008.7** 判定結果が「不安定」「読み取り不可」の場合、改善のための具体的な助言を表示する
  （QR らしさを上げる / 保護レベルを上げる / コントラストを下げる / テキストを短くする）。
- **FR-008.8** 判定結果によらず、**「実機での読み取りテストを必ず行ってください」**の
  注意書きを常時表示する。判定はあくまで目安である旨を明記する。
- **FR-008.9** 判定は結果の成否にかかわらずアプリの他機能をブロックしない
  （Worker 起動失敗時は「判定不可」を表示し、書き出しは可能なままとする）。

### FR-009: PNG 書き出し

- **FR-009.1** ハーフトーン QR を PNG としてダウンロードできる。
- **FR-009.2** 解像度を 3 段階から選択できる（サブモジュールあたりのピクセル数）:
  | 値 | ラベル | px/サブモジュール |
  |----|--------|-----------------|
  | `standard` | 標準 | 6 |
  | `high` | 高解像度 | 12 |
  | `print` | 印刷用 | 24 |
- **FR-009.3** 選択中の解像度における**実際の出力ピクセル寸法**を UI に表示する。
- **FR-009.4** クワイエットゾーンは 4 モジュール（= 12 サブモジュール）分を白で確保する。
- **FR-009.5** ファイル名は `halftone-qr-<YYYYMMDD-HHmmss>.png` とする。
- **FR-009.6** 画像未選択時・QR 生成失敗時は書き出しボタンを無効化する。
- **FR-009.7** 出力上限は一辺 8192px。超える設定は選択できないよう抑止する。

### FR-010: 状態・エラー表示

- **FR-010.1** エラー（容量超過 / 非対応ファイル / サイズ超過 / 画像デコード失敗）は
  該当箇所の近傍に日本語で表示する。
- **FR-010.2** 読み取り判定の状態変化は `aria-live="polite"` でスクリーンリーダーに通知する。
- **FR-010.3** プライバシー方針（すべてブラウザ内で完結し、画像も入力も送信しない）を
  UI 上に明示する。

## 4. 非機能要件

### NFR-001: プライバシー / セキュリティ

- **NFR-001.1** 画像・テキストを含む一切のユーザーデータをサーバーへ送信しない。
  実装上、`fetch` / `XMLHttpRequest` / `WebSocket` / `navigator.sendBeacon` による
  外部通信コードを含めない。
- **NFR-001.2** 解析タグ・外部フォント CDN・外部画像を読み込まない。
  Web フォントは npm 経由でバンドルに同梱する。
- **NFR-001.3** `dangerouslySetInnerHTML` / `innerHTML` によるユーザー入力の描画を行わない。
- **NFR-001.4** アップロードされた SVG は `<img>` 経由で canvas に描画する
  （スクリプト実行されない経路）。`innerHTML` での DOM 挿入は行わない。
- **NFR-001.5** ObjectURL は不要になった時点で `revokeObjectURL` する。

### NFR-002: 配信構成

- **NFR-002.1** 静的ホスティングのみで動作する（バックエンド不要）。
- **NFR-002.2** `base: './'` で相対パス出力とし、サブディレクトリ配信に対応する。
- **NFR-002.3** ビルドは `npm ci && npm run build` のみで完結する。

### NFR-003: パフォーマンス

- **NFR-003.1** 初期ロードの JS は gzip 150KB 未満（ZXing は Worker 内の動的読み込みとし、
  初期バンドルに含めない）。
- **NFR-003.2** スライダー操作に対するプレビュー更新は 60ms 以内を目標とする
  （典型ケース: version 6 前後、3N ≒ 123 → 約 15,000 サブモジュール）。
- **NFR-003.3** 読み取り判定は Worker 実行とし、メインスレッドを 16ms 以上ブロックしない。
- **NFR-003.4** 画像の再サンプリングは、画像・アライメント・階調が変わったときのみ行い、
  λ / 保護レベルのみの変更ではキャッシュを再利用する。

### NFR-004: レスポンシブ

- **NFR-004.1** 360 / 768 / 1024 / 1440px で横スクロールが発生せず、崩れない。
- **NFR-004.2** タッチ操作でスライダー・ボタンが操作できる（最小タップ領域 44px）。

### NFR-005: アクセシビリティ

- **NFR-005.1** すべての操作要素がキーボードのみで到達・操作できる。
- **NFR-005.2** フォーカスリングを可視化する（`:focus-visible`）。
- **NFR-005.3** 本文テキストのコントラスト比は 4.5:1 以上、大きな文字は 3:1 以上。
- **NFR-005.4** すべてのフォーム要素に `<label>` を関連付ける。
- **NFR-005.5** canvas プレビューに説明的な代替テキスト（`role="img"` + `aria-label`）を付与する。
- **NFR-005.6** `prefers-reduced-motion: reduce` でトランジションを無効化する。

### NFR-006: デザイン品質

- **NFR-006.1** 汎用テンプレート然とした見た目にしない。
  印刷所 / 暗室（darkroom）の道具を思わせるエディトリアル方向を採る。
- **NFR-006.2** 色・タイポグラフィ・余白は CSS カスタムプロパティのトークンとして定義し、
  ハードコードを避ける。
- **NFR-006.3** 姉妹アプリ `qr-code-designer` とはフォント・配色・レイアウト構成を意図的に変える。

### NFR-007: テスト

- **NFR-007.1** コアロジック（QR 生成 / モジュール分類 / 画像サンプリング / ハーフトーン /
  レンダリング / 書き出し寸法）に単体テストを置く。
- **NFR-007.2** **FR-006.2 の中央固定不変条件**は、λ・保護レベル・階調の全組み合わせに対して
  テストで保証する。
- **NFR-007.3** `npm run build` と `npm test` がいずれも成功する状態を維持する。

## 6. エッジケース

| # | ケース | 期待挙動 |
|---|--------|----------|
| E-01 | テキストが空 | ハーフトーン側・通常 QR ともプレースホルダ。書き出し無効 |
| E-02 | テキストが ECC H の容量を超える | エラー表示。生成しない（FR-001.5） |
| E-03 | 画像が真っ黒 / 真っ白 | 変換は成功する。読み取り判定は真っ黒側で低下しうるので助言を出す |
| E-04 | 画像のアスペクト比が極端（例 4000×100） | cover フィットで中央基準にトリミングされる |
| E-05 | 画像デコードに失敗（壊れたファイル） | エラー表示。既存の画像状態を保持 |
| E-06 | 20MB 超のファイル | エラー表示。読み込まない（FR-003.5） |
