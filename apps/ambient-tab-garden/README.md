# 浮遊光庭 — Ambient Tab Garden

開いているタブの数だけ光の群れが増える、観賞用のアンビエント・ジェネレーティブアート。

このページを複数のブラウザタブで開くと、**タブ1つにつき1つの粒子クラスタ**が3D空間に生まれる。タブが開かれている時間に応じてクラスタは育ち、同時に「きらめき」が貯まる。きらめきはアップグレードに使い、粒子の密度・軌道・発光・色域が育っていく。

放置していること自体が進行になる、置いておくためのオブジェクト。ゲーム的な達成や催促はしない。

## 動かす

```bash
npm install
npm run dev          # 開発サーバ
npm run build        # dist/ に静的サイトを出力
npm run preview      # ビルド結果を配信
npm test             # ユニットテスト
npm run test:coverage
```

Docker（本番想定、リポジトリ標準のコンテナ化方針に従う）:

```bash
docker build -t ambient-tab-garden .
docker run --rm -p 8080:80 ambient-tab-garden
```

## 技術選定

| 選択 | 理由 |
|---|---|
| three.js | 主題が「実際の3D空間に浮かぶ粒子」であるため。2Dキャンバスの疑似3Dでは、クラスタが前後に散らばることで生まれる奥行きのパララックスが出ない |
| フレームワーク非採用（素のDOM + CSS） | 画面はパネル2枚と通知だけで、状態はtickで押し出す一方向。フレームワークを入れる理由がない |
| ポストプロセス（Bloom）非採用 | 加算合成の2層スプライト（コア＋ハロー）で代替。EffectComposerはバンドルとGPU負荷が重く、`backdrop-filter`のパネルとの合成順の制御も面倒になる |
| 通常合成（NormalBlending） | 加算合成ではない。淡い背景に光を足すと白へ飽和して背景に溶ける。参照モックアップの粒子が見えているのは「明るいから」ではなく「背景より彩度が高いから」で、そちらを再現している |

バンドルは gzip 約136KB（ほぼ全量がthree.js）。

## 設計上の判断

### きらめきは加算せず導出する

```
残高 = banked + Σ(生存タブの earned) - spent
```

各タブは自分の `earned` だけを実時間の差分から進める。タブがレジストリから外れるとき、その `earned` を `banked` へ**移す**だけなので、タブが閉じた瞬間に残高が飛んだり減ったりしない。複数のタブが同じゴーストを同時に精算しても、どちらも同じ結果を書くため二重計上にならない（リーダー選出は不要）。

### アップグレードはブラウザ全体でグローバル

タブは事故で閉じられうる短命な存在なので、購入物をタブに紐づけると「絶対にタブを閉じない」が最適戦略になり、落ち着いた観賞物というコンセプトと矛盾する。

### タブの生存判定

- 正常に閉じたタブは `pagehide` で自分のレコードを削除し、他タブから即座に消える
- クラッシュ・強制終了は `lastSeenAt` が **120秒** 古くなった時点でゴーストとみなす。この値は短くできない。Chromeはバックグラウンドタブのタイマーを最短1分に1回まで間引くため、60秒では生きているタブを誤って消してしまう

## 既知の制約

- **バックグラウンドタブが長時間凍結されると、一時的に他タブの表示から消える。** ブラウザが非アクティブなタブを完全に凍結した場合、120秒のハートビートが途切れてゴースト扱いになる。きらめきは実時間から計算しているため進捗は失われず、前面に戻れば再登録されて復帰する（このとき二重計上を防ぐため、そのタブの未精算分はリセットされる）
- **ポイントスプライトの最大サイズはGPUドライバ依存。** `ALIASED_POINT_SIZE_RANGE` を実測してクランプしているが、上限が極端に小さい環境（一部の古いGPUで63px）ではハローが頭打ちになる
- **同一ブラウザ・同一プロファイル内でのみ同期する。** 別のブラウザや別ウィンドウのシークレットモードとは共有されない（`BroadcastChannel` と `localStorage` の仕様どおり）
- **他サイトのタブは一切参照していない。** 通常のWebページから他タブのURLやfaviconを読むことは技術的に不可能で、試みてもいない。数えているのはこのアプリ自身のタブだけ
- **モバイルは表示のみ想定。** 縦画面ではクラスタの場を90度回して収めているが、そもそもモバイルブラウザで同じページを複数タブ同時に開いて眺める使い方は現実的でない
