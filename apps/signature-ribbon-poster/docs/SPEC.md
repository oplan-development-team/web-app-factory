# SPEC: Signature Ribbon Poster

**Feature ID**: 001-signature-ribbon-poster
**Status**: Approved
**Base**: app-factory が生成したプロトタイプ（`apps/signature-ribbon-poster/` v1.0.0）
**Last updated**: 2026-08-24

---

## 1. 概要

マウス・タッチ・ペンで描いた署名や一筆書きを、**動かした速度に応じて太さと発光の強さが連続的に変化する「リボン」の光跡**として暗い背景に描画し、任意のキャプション（署名者名・日付など）を添えた一枚のポスターとして高解像度 PNG で書き出すツール。

完全クライアントサイド。サーバー送信・アカウント・外部 API を一切持たない。

### 1.1 プロトタイプからの変更方針

本実装はプロトタイプを**土台として引き継ぐ**。コンセプト・ビジュアル（ダークラグジュアリー / ギャラリーのキャプションカード）・操作フロー（描く → 色を選ぶ → キャプション → 書き出す）は維持する。

変更するのは以下の 3 点に限定する。

| # | 変更 | 動機 |
|---|------|------|
| A | 描画パイプラインの再設計（軽量化） | ユーザーから「描画時の動作が重い」という指摘 |
| B | 機能追加（§4） | 本実装として実用に足る水準への引き上げ |
| C | テスト整備・状態表示の充実 | プロトタイプにはテストが無く、エラー/空/成功状態も未整備 |

### 1.2 対象ユーザー

- 記念品・ギフトカード・案内状などに手書きサインを載せたい個人
- 展示・イベントで来場者のサインをその場で作品化したい主催者
- 自分の署名を SNS アイコン／ヘッダーの素材にしたい人

### 1.3 対象環境

- 主対象: PC（マウス・トラックパッド）、タブレット（ペン・指）
- 対象ブラウザ: Chromium 系 / Firefox / Safari の各最新版
- 副次対象: スマートフォン（レイアウトは破綻させないが、最適化の主対象ではない）

### 1.4 スコープ外（非目標）

- SVG 等ベクター形式での書き出し（グロー表現がラスター前提）
- 筆圧（`pressure`）・傾き（`tilt`）による追加の線幅制御
- 自由なカラーピッカー、グラデーション軌跡、複数色の混色
- キャプションの詳細カスタマイズ（フォント・位置・サイズ・複数行）
- サーバー保存・共有リンク・ギャラリー・アカウント機能
- キャンバスのズーム / パン（§4.6 で不採用理由を記載）
- 描画のアニメーション再生（リプレイ）

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| ポスター空間 | 作品の論理座標系。原点左上、既定サイズ 1800 × 2545（ISO A 判と同じ 1:√2 比） |
| ストローク | pointerdown から pointerup / pointercancel までの連続した 1 本の軌跡 |
| リボン点 | ストロークを構成する 1 点。ポスター空間座標 `x, y`、時刻 `t`、平滑化済み速度 `speed` を持つ |
| 速度 | 直近 2 点間の移動距離 ÷ 経過時間（px/ms、ポスター空間基準）。移動平均で平滑化した値を使う |
| コア層 | リボンの実体（芯）を描いたレイヤー。グロー処理を含まない |
| ブルーム層 | コア層を縮小・ぼかして生成する発光層。加算合成でコア層に重ねる |
| レスポンス | 速度が太さ・発光に与える影響の強さ。ユーザーが調整できる（§4.4） |
| ドラフト | 現在の制作状態（ストローク列・背景・色・キャプション・レスポンス値）のスナップショット |

## 3. 機能要件（プロトタイプから継承する中核機能）

### FR-001: ストローク入力

- **FR-001.1** Pointer Events を用い、マウス・タッチ・ペンのいずれの入力でも描画できる。
- **FR-001.2** 同時に処理するポインタは 1 本のみ。描画中に別のポインタが押下されても無視する。
- **FR-001.3** `pointerdown` で `setPointerCapture` を行い、キャンバス外へドラッグしても軌跡が途切れないようにする。
- **FR-001.4** `pointerup` / `pointercancel` でストロークを確定する。`pointerleave` ではストロークを確定しない（キャプチャ中は発火しないため。境界をまたぐ描画を許容する）。
- **FR-001.5** 直前の採用点から **1.5px（ポスター空間）未満**の移動しかしていない `pointermove` は点として採用しない。
- **FR-001.6** 押下したまま動かさずに離した場合（点が 1 つのみ）、円形のドットとして描画する。
- **FR-001.7** キャンバス上では `touch-action: none` を設定し、タッチ操作でページがスクロールしないようにする。
- **FR-001.8** ブラウザ表示サイズと関係なく、座標はポスター空間へ正規化して保持する。ウィンドウをリサイズしても既存ストロークの形状は変化しない。

### FR-002: 速度の算出と平滑化

- **FR-002.1** 生の速度は `距離 / max(1, Δt)` （px/ms、ポスター空間）で求める。
- **FR-002.2** 直近 **5 サンプル**の単純移動平均で平滑化し、センサーノイズによる線幅のちらつきを抑える。
- **FR-002.3** ストローク開始時、平滑化バッファはリセットする。ストロークの 1 点目の速度は 0 とする。

### FR-003: 速度 → 見た目のマッピング

- **FR-003.1** 平滑化速度を `speedNorm = clamp(speed / maxSpeed, 0, 1)` で 0〜1 に正規化する。`maxSpeed` はレスポンス設定（§4.4）で決まる。
- **FR-003.2** 線幅は `speedNorm` に対して線形に **34px（最遅）→ 5px（最速）** を取る（ポスター空間基準）。
- **FR-003.3** 不透明度は **0.95（最遅）→ 0.38（最速）** を取る。
- **FR-003.4** 発光量（ブルームへの寄与）は **1.0（最遅）→ 0.35（最速）** を取る。
- **FR-003.5** すなわち「ゆっくり動かすほど太く濃く強く光り、速く動かすほど細く淡く弱く光る」。この関係は本アプリの中核体験であり、変更しない。

### FR-004: 描画表現

- **FR-004.1** リボンは以下 3 要素の重ね合わせで表現する。
  1. **コア** — 選択色を `speedNorm` に応じた幅・不透明度で描いた本体
  2. **ホットコア** — コアを白方向に 72% 混色した細いハイライト（幅はコアの 32%、最小 1.2px）
  3. **ブルーム** — コア層全体から生成する発光ハロー（§NFR-001）
- **FR-004.2** リボン同士が重なる箇所は加算合成（`globalCompositeOperation = "lighter"`）で明るくなる。
- **FR-004.3** 隣接点は中点を通る二次ベジェで接続し、折れ線特有の角を出さない。
- **FR-004.4** 線端・接合は `round`。

### FR-005: 背景プリセット

- **FR-005.1** 背景は次の 3 プリセットから選択する。既定は Noir。

  | id | ラベル | hex |
  |----|--------|-----|
  | `noir` | Noir | `#0a0908` |
  | `midnight-navy` | Midnight Navy | `#0b1220` |
  | `deep-bordeaux` | Deep Bordeaux | `#1a0a10` |

- **FR-005.2** 背景変更は既存ストロークを保持したまま即座に反映される。

### FR-006: リボンの発光色

- **FR-006.1** 発光色は次の 5 プリセットから選択する。既定は Gold。

  | id | ラベル | hex |
  |----|--------|-----|
  | `gold` | Gold | `#d9ac4c` |
  | `ice-blue` | Ice Blue | `#9fd3ff` |
  | `crimson` | Crimson | `#d1264f` |
  | `pearl` | Pearl | `#f4efe4` |
  | `emerald` | Emerald | `#3fb08a` |

- **FR-006.2** 色は**ストローク単位**で保持する。色を変更しても既に描いたストロークの色は変わらず、以降に描くストロークへ適用される。1 枚の中に複数色を混在させられる。

### FR-007: キャプション

- **FR-007.1** 1 行のテキスト（最大 60 文字）を入力できる。
- **FR-007.2** 入力中はキャンバス下部にプレビュー表示する。
- **FR-007.3** 書き出し時、ポスター下部に固定レイアウトで焼き込む。構成は「下端グラデーションのスクリム → ゴールドのヘアライン → 小文字間隔を空けた `S I G N E D` の見出し → イタリックのセリフ体本文」。
- **FR-007.4** 未入力（空白のみを含む）の場合、スクリム・ヘアライン・見出しを含めキャプション要素は一切描画しない。
- **FR-007.5** キャプション本文がポスター幅の 80% を超える場合、収まるまでフォントサイズを段階的に縮小する（下限は基準サイズの 55%）。それでも超える場合は末尾を省略記号で切り詰める。

### FR-008: 取り消し操作

- **FR-008.1** Undo で直前の操作を取り消せる。取り消し対象は「ストロークの追加」および「全消去」。
- **FR-008.2** Redo で取り消した操作をやり直せる。**（本実装で追加）**
- **FR-008.3** 新しいストロークを描くと、Redo 履歴は破棄される。
- **FR-008.4** Clear で全ストロークを消去する。Clear 自体も Undo で取り消せる。
- **FR-008.5** 履歴の保持上限は 50 手。超えた分は古い側から破棄する。
- **FR-008.6** Undo / Redo / Clear の各ボタンは、実行できない状態では `disabled` にする。

### FR-009: PNG 書き出し

- **FR-009.1** 「Download Poster」で、背景・リボン・キャプションを合成した PNG をダウンロードできる。
- **FR-009.2** ファイル名は `signature-ribbon-poster-<ISO8601 タイムスタンプ>.png`（`:` と `.` は `-` に置換）。
- **FR-009.3** 書き出しはプレビュー用とは独立した専用パスで、**最終品質**（§NFR-001.4）で描画する。
- **FR-009.4** キャプション描画前に Web フォントの読み込み完了を待つ。フォント読み込みに失敗した場合もフォールバックのセリフ体で書き出しを続行する。
- **FR-009.5** ストロークが 1 本も無い状態では書き出しボタンを `disabled` にする。
- **FR-009.6** 書き出し処理中はボタンを `disabled` にし、多重実行を防ぐ。

## 4. 機能要件（本実装で追加する機能）

追加機能は「ユーザーからの具体的要望がまだ無い」状況で選定した。選定基準は次の 2 つ。

1. **プロトタイプ運用中に実際に困る欠落を埋めるもの**（作りかけが消える、書き出しサイズが選べない、Undo しすぎると戻せない）
2. **本アプリの中核体験＝速度と光跡の関係を、ユーザー自身が操作できる方向に広げるもの**

逆に、単に機能数を増やすだけのもの（ズーム/パン、ベクター書き出し、テンプレート集など）は採用しない。

### FR-010: 書き出し解像度の選択 【追加】

**選定理由**: プロトタイプは 1800×2545 固定。SNS に上げるだけなら過剰でファイルが重く、印刷したい場合は逆に足りない。実際の使い道が「共有」と「印刷」に分かれるため、固定値では片方が必ず不便になる。

- **FR-010.1** 書き出し解像度を次の 3 段階から選択できる。既定は Edition。

  | id | ラベル | 解像度 | 想定用途 |
  |----|--------|--------|---------|
  | `study` | Study | 900 × 1273 | 画面共有・SNS・下書き確認 |
  | `edition` | Edition | 1800 × 2545 | 既定。汎用（プロトタイプと同一） |
  | `archival` | Archival | 3600 × 5090 | 印刷（300dpi で約 A3） |

- **FR-010.2** 選択中の解像度は px 値とともに UI に表示する。
- **FR-010.3** 解像度が変わっても作品の見た目（リボンの相対的な太さ・発光の広がり・キャプションの配置）は変わらない。すべての描画パラメータはポスター空間基準で定義し、書き出し倍率でスケールする。
- **FR-010.4** 解像度の選択は画面プレビューには影響しない（プレビューは常に表示サイズに応じた解像度で描画する）。

### FR-011: ドラフトの自動保存と復元 【追加】

**選定理由**: 署名は「何度も描き直して納得のいく一筆を選ぶ」使い方になる。リロードやタブの誤操作で消えると、その試行がすべて失われる。ローカル完結というアプリの前提を崩さずに解決できる（localStorage）ため、費用対効果が最も高い。

- **FR-011.1** ストローク確定時・設定変更時に、ドラフト（ストローク列・背景・キャプション・レスポンス値・書き出し解像度）を `localStorage` に自動保存する。保存は 800ms のデバウンスを挟む。
- **FR-011.2** ストロークを含むドラフトが保存されている状態で起動すると、復元バナーを表示する。ユーザーは「復元する」または「破棄する」を選べる。**自動では復元しない**（意図せず前回の作品が出てくる混乱を避けるため）。
- **FR-011.3** 保存する座標は小数第 1 位に丸め、時刻はストローク先頭からの相対値にすることで保存サイズを抑える。
- **FR-011.4** 保存データにはスキーマバージョンを含める。バージョン不一致・JSON パース失敗・形式不正のいずれの場合も、例外を投げずに「ドラフト無し」として扱い、破損データは削除する。
- **FR-011.5** `localStorage` が使用できない（プライベートモード・容量超過など）場合も、アプリの主要機能は動作を継続する。保存に失敗した場合は 1 度だけ通知し、以降は無音で保存を試行しない。
- **FR-011.6** Clear 実行後、保存済みドラフトも空の状態で上書きする。

### FR-012: Redo 【追加】

**選定理由**: プロトタイプは Undo のみで、1 手戻しすぎたら取り返せない。取り消し系操作の対称性は基本的な期待であり、欠落は体験の粗さとして直に出る。実装コストも小さい。

- 要件は FR-008 に統合済み。

### FR-013: レスポンス（速度感度）の調整 【追加】

**選定理由**: 本アプリ唯一の表現軸が「速度 → 太さ・発光」の写像である以上、その写像自体をユーザーが握れることが最も表現力を広げる。書き味は入力デバイス（マウス / トラックパッド / ペン）で大きく変わるため、固定値では特定デバイスに最適化された状態が続く。

- **FR-013.1** レスポンスを 0〜100 のスライダーで調整できる。既定は 50。
- **FR-013.2** レスポンス値 `r`（0〜1 に正規化）に対し、`maxSpeed = 3.2 - 2.4 × r`（px/ms）とする。すなわち
  - 低い（0）: `maxSpeed = 3.2` — 速度差が出にくく、太く均一で重厚な線
  - 既定（50）: `maxSpeed = 2.0`
  - 高い（100）: `maxSpeed = 0.8` — わずかな速度差で細く鋭くなる、抑揚の激しい線
- **FR-013.3** 変更は**既に描いたストロークにも遡って適用**され、即座に再描画される（同じ一筆を異なる表情で見比べられるようにするため）。
- **FR-013.4** スライダーには現在値の意味を示すラベル（`Calm` / `Balanced` / `Volatile`）を併記する。

### FR-014: キーボードショートカット 【追加】

- **FR-014.1** `Cmd/Ctrl + Z` で Undo、`Cmd/Ctrl + Shift + Z` で Redo。
- **FR-014.2** テキスト入力中（キャプション欄フォーカス時）はショートカットを横取りしない。

### FR-015: ズーム / パン 【不採用】

検討したうえで採用しない。理由:

- 本アプリの中核は「一筆を止めずに描き切ったときの速度の連続性」にある。パンを挟むとポインタ移動が実質的に分断され、速度由来の抑揚が壊れる。
- ポスターは A 判比率の縦長 1 枚であり、画面に全体が収まる。拡大しないと描けない場面が構造的に存在しない。
- 代替として、レスポンス調整（FR-013）で細い線の表現力を確保する。

## 5. 非機能要件

### NFR-001: 描画性能（本実装の最重要要件）

プロトタイプは 1 フレームごとに **全ストロークの全セグメント**を、`shadowBlur` 付きで **3 パス**、1800×2545 の固定バッキングストアに再描画していた。`shadowBlur` は描画呼び出しごとにガウシアンぼかしを走らせるため、点数に比例して急激に重くなる。

本実装では次のとおり再設計する。

- **NFR-001.1 レイヤー分離** — リボンは以下の 2 レイヤーで構成する。
  - **コア層**: `shadowBlur` を使わず、単純な可変幅ストロークのみで描く
  - **ブルーム層**: コア層を縮小コピー → ぼかし → 加算合成で拡大して重ねる。ぼかしはフレームあたり**レイヤー単位で数回**であり、セグメント数に依存しない
- **NFR-001.2 増分描画** — ドラッグ中はコア層に**新しく確定したセグメントのみ**を追記する。全再描画は「Undo / Redo / Clear / 背景変更 / レスポンス変更 / リサイズ / ドラフト復元」でのみ行う。
- **NFR-001.3 表示解像度の適正化** — 表示キャンバスのバッキングストアは `CSS 表示サイズ × min(devicePixelRatio, 2)` とし、横幅 1400px を上限にクランプする。1800×2545 固定は廃止する。
- **NFR-001.4 品質の二段構え** — 画面プレビューは表示解像度・ブルーム 2 段。書き出しは選択解像度・ブルーム 3 段＋高品質補間で描画する。書き出しは 1 回きりの処理なので品質を優先する。
- **NFR-001.5 目標値** — 参照環境（Chromium、1440×900 相当のウィンドウ、devicePixelRatio 2）において、**1000 点のストロークを保持した状態で 1 点追加あたりの描画時間 2ms 以下**、かつ**全再描画 30ms 以下**。
- **NFR-001.6** 見た目の質感（発光する光跡としての説得力）を損なわないこと。ブルーム 2 段構成により、プロトタイプの `shadowBlur` より**広く滑らかな**ハローを得る。
- **NFR-001.7** `requestAnimationFrame` ループは再描画が必要なときのみ描画する（`needsRedraw` フラグ）。アイドル時に無駄な描画をしない。
- **NFR-001.8** 計測手段をリポジトリに残す（`bench/` の Playwright ベンチ）。プロトタイプ実装との比較値を README に記載する。

### NFR-002: 品質保証

- **NFR-002.1** テストは単体 / 統合 / E2E の 3 種を用意する。
- **NFR-002.2** 単体・統合テストの行カバレッジ **80% 以上**を維持し、CI 相当のコマンド（`npm run test:coverage`）で機械的に検証できる。
- **NFR-002.3** 実装は TDD（テスト先行）で進める。
- **NFR-002.4** E2E は Playwright で「描く → 色を変える → Undo/Redo → キャプション入力 → 書き出し → 復元」の主要導線を検証する。
- **NFR-002.5** 型チェック（`tsc --noEmit`）が `strict` で通ること。`any` を使わないこと。

### NFR-003: アーキテクチャ

- **NFR-003.1** アプリは `apps/signature-ribbon-poster/` で自己完結し、他の `apps/` 配下と一切コード・依存を共有しない。
- **NFR-003.2** 副作用のない純粋ロジック（速度・幾何・履歴・ドラフト・解像度）と、Canvas / DOM に触れる層を分離する。純粋ロジックはブラウザ非依存でテストできること。
- **NFR-003.3** Canvas を持つ描画層は、キャンバス生成をコンストラクタ引数で差し替えられるようにし、テストで実物の Canvas を必要としないこと。
- **NFR-003.4** 1 ファイル 400 行以内を目安とする（上限 800 行）。
- **NFR-003.5** フレームワーク非依存（Vite + TypeScript + Canvas 2D）の構成を維持する。

### NFR-004: デザイン品質（Anti-Template Policy）

プロトタイプで確立した方向を維持・強化する。

- **NFR-004.1 スタイル方向**: ダークラグジュアリー。ギャラリーのキャプションカードのような佇まい。
- **NFR-004.2 タイポグラフィ**: 見出し・作品テキストに Playfair Display（イタリック多用）、ラベル・UI に Cormorant Garamond。小文字間隔を広く取ったオールキャップスのラベルを一貫して使う。
- **NFR-004.3 配色**: ほぼ黒の地に、ゴールド（`#c9a24b`）1 色のアクセントとパール（`#f2ece2`）の文字。装飾のための色は足さない。作品自体の発光色が主役であることを崩さない。
- **NFR-004.4 追加 UI の意匠**: 新規に足す UI（解像度セレクタ・レスポンススライダー・復元バナー・トースト）は、既存のヘアライン罫線とゴールドの下線モチーフを流用する。ブラウザ標準の `select` / `input[type=range]` の見た目をそのまま出さない。
- **NFR-004.5 禁止**: 画一的なカードグリッド、中央寄せ + グラデーションブロブのヒーロー、単調な余白・角丸・影、ライブラリのデフォルト外観。
- **NFR-004.6 hover / focus / active**: すべての操作要素に個別に設計した状態を与える。`:focus-visible` はゴールドのリングで統一する。

### NFR-005: 体験品質

- **NFR-005.1 空状態**: ストロークが 1 本も無いとき、キャンバス中央に描画を促すヒントを表示する。1 本目を描き始めた時点でフェードアウトする。
- **NFR-005.2 ローディング状態**: 書き出し中はボタンのラベルを変更し、進行中であることを示すヘアラインの走査アニメーションを出す。
- **NFR-005.3 エラー状態**: 書き出し失敗・ドラフト保存失敗・ドラフト読み込み失敗は、原因と次の行動が分かる日本語のトーストで通知する。`console.error` だけで握りつぶさない。
- **NFR-005.4 成功状態**: 書き出し完了・ドラフト復元・ドラフト破棄をトーストで通知する。
- **NFR-005.5 モーション**: すべてのアニメーションは状態遷移か注意誘導のために使う。`prefers-reduced-motion: reduce` を尊重し、その場合はトランジションを無効化する。
- **NFR-005.6 レイアウトシフト**: トースト・復元バナーはレイアウトフローから浮かせ、既存要素を押し出さない。
- **NFR-005.7 繰り返し操作の軽減**: Undo/Redo のキーボードショートカット（FR-014）、および操作可能性を示す `disabled` 状態で、無駄な試行を減らす。

### NFR-006: アクセシビリティ

- **NFR-006.1** 色選択群は `role="radiogroup"` / `role="radio"` + `aria-checked` で表現し、矢印キーで移動できる。
- **NFR-006.2** トーストは `role="status"` `aria-live="polite"`、復元バナーは `role="region"` とする。
- **NFR-006.3** すべての操作要素にアクセシブルな名前（`aria-label` またはテキスト）を与える。
- **NFR-006.4** キャンバスには代替テキストと操作説明を与える。

### NFR-007: セキュリティ / プライバシー

- **NFR-007.1** データは一切外部送信しない。ネットワークアクセスは Google Fonts の取得のみ。
- **NFR-007.2** ユーザー入力（キャプション）は `textContent` / Canvas `fillText` 経由でのみ扱い、`innerHTML` に流し込まない。
- **NFR-007.3** `localStorage` から読み出した値は必ず形式検証してから使う（信頼しない）。
- **NFR-007.4** シークレット・API キーを持たない。

### NFR-008: デプロイ

- **NFR-008.1** 既存のマルチステージ Dockerfile（`node:22-alpine` でビルド → `nginx:alpine` で `dist/` 配信）構成を維持し、`docker build` が通ること。
- **NFR-008.2** ビルド成果物は静的ファイルのみで、実行時の環境変数を要求しないこと。

## 7. エッジケースと期待動作

| # | 状況 | 期待動作 |
|---|------|---------|
| E-01 | 押下してすぐ離す（点 1 つ） | 円形のドットとして描画され、1 ストロークとして履歴に積まれる |
| E-02 | 描画中にウィンドウをリサイズ | 表示解像度を再構築し、既存ストロークは形状を保ったまま再描画される |
| E-03 | 描画中に別指 / 別ペンで触れる | 無視される（1 ポインタのみ処理） |
| E-04 | キャンバス外へドラッグして離す | `setPointerCapture` により軌跡が繋がり、外で離してもストロークが確定する |
| E-05 | ストローク 0 本で書き出しボタン | ボタンが `disabled` で押せない |
| E-06 | 書き出し中に再度クリック | `disabled` により多重実行されない |
| E-07 | キャプションが 60 文字ぎりぎりで幅超過 | フォントサイズを段階縮小、それでも超えたら省略記号で切り詰め |
| E-08 | `localStorage` が使えない | 主要機能は動作継続。保存失敗を 1 度だけトースト通知し、以降は無音 |
| E-09 | 保存済みドラフトが壊れている / スキーマ違い | 例外を出さずに「ドラフト無し」として扱い、該当キーを削除する |
| E-10 | Undo を履歴の先頭まで実行 | Undo ボタンが `disabled` になる |
| E-11 | Undo 後に新しいストロークを描く | Redo 履歴が破棄され、Redo ボタンが `disabled` になる |
| E-12 | Web フォントの読み込みに失敗 | フォールバックのセリフ体でキャプションを焼き込み、書き出しは成功する |
| E-13 | `canvas.toBlob` が null を返す | エラートーストで通知し、アプリは動作を継続する |
| E-14 | Archival 解像度（3600×5090）で書き出し | 数秒かかる場合があるためローディング表示を出し、完了までボタンを `disabled` にする |
| E-15 | 履歴が 50 手を超える | 最古の手から破棄し、メモリが単調増加しないようにする |
| E-16 | ブラウザが `ctx.filter` 未対応 | 縮小・拡大のみで生成するブルームへフォールバックし、描画は成立する |

## 8. 画面構成

プロトタイプの 2 カラム構成（左: 作品ステージ / 右: 320px の操作パネル）を維持する。

```
┌──────────────────────────────┬─────────────────────┐
│                              │ ATELIER SERIES No.01│
│      ┌────────────────┐      │ Signature           │
│      │                │      │ 《Ribbon》          │
│      │   poster       │      │ 速度が光跡を彫る…   │
│      │   (A 判比率)   │      │ ─────────────────── │
│      │                │      │ BACKGROUND  ●●●     │
│      │   caption      │      │ RIBBON HUE  ●●●●●   │
│      └────────────────┘      │ RESPONSE    ──◆──   │
│    マウス・タッチ・ペンで      │ SIGNATURE LINE      │
│    ここに署名してください      │ ___________________ │
│                              │ RESOLUTION          │
│   [ トースト ]                │ Study Edition Archiv│
│                              │ ─────────────────── │
│                              │ UNDO REDO CLEAR     │
│                              │ [ DOWNLOAD POSTER ] │
└──────────────────────────────┴─────────────────────┘
```

復元バナーは操作パネル最上部にオーバーレイで重なる。トーストはステージ下部中央に浮かせる。

860px 未満では縦積みにフォールバックする（主対象外だが破綻させない）。
