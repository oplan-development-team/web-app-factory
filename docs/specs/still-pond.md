# still-pond（凪の池）

## 目的
スマートフォンでの短時間の休息・マインドフルネス体験を求めるユーザーに向けて、端末の傾きに物理的に反応するフォトリアルな3D水面を提供する。既存の類似アプリ（`puddle-tilt`は2D・玩具的なトイ、`karesansui-composer`は静的な砂紋書き出しツール）にはない、リアルタイム3Dインタラクションによる禅のヒーリング体験を実現することが目的。

## スコープ
- 含む:
  - three.jsによるフォトリアルな3D水面シーン（PBRマテリアル、HDRI環境ライティング、ソフトシャドウ、Bloomポストプロセス）
  - 水面に浮かぶ蓮の葉・丸石等の小物オブジェクト（PBR質感）
  - `DeviceOrientationEvent`のbeta/gammaを用いた傾き検知と、水面傾斜・波の移流・浮遊物の物理反応への反映
  - iOS 13+の`DeviceOrientationEvent.requestPermission()`によるユーザージェスチャー起点の許可フロー
  - 許可拒否時・センサー非対応時のマウスドラッグによる疑似傾き入力フォールバック
  - 初回訪問時のオンボーディング画面（案内＋許可要求ボタン）
  - スマホ縦画面を第一優先としたレスポンシブレイアウト
  - Docker化（マルチステージDockerfile）と`deploy.json`によるGitHub Pages配信設定
- 含まない:
  - 音声再生・BGM
  - 画像/動画等の書き出し・共有機能
  - サーバーサイド処理・外部API通信
  - ユーザーアカウント、進捗や設定の永続化（Cookie/LocalStorage含む）
  - マルチプレイヤー・複数ユーザー間の共有機能

## 機能要件
- FR-1: three.jsで3D水面シーンをレンダリングする。水面マテリアルはPBRベースとし、反射・屈折、波紋を表現する法線マップ、環境マップ反射を持つ。
- FR-2: 水面上に浮かぶ蓮の葉・丸石などの小物オブジェクトを、水面と同様にPBR質感で表示する。
- FR-3: HDRI環境マップによる環境ライティングを適用する。トーンは穏やかな空・黄昏〜薄明かりとする。
- FR-4: シーン内の主要オブジェクトにソフトシャドウを適用する。
- FR-5: Bloom程度の控えめなポストプロセスを適用する。
- FR-6: 初回訪問時、簡潔な案内文と「はじめる」ボタンを含むオンボーディング画面を表示する。
- FR-7: 「はじめる」ボタン押下時、実行環境が`DeviceOrientationEvent.requestPermission`を持つ場合（iOS 13+相当）、そのユーザージェスチャーの中で許可要求を実行する。
- FR-8: 許可が得られた場合、以後`deviceorientation`イベントのbeta/gamma値を継続的に取得し、水面の傾斜、波の移流方向・速度、浮遊物の転がりに反映する。
- FR-9: 許可が拒否された場合、エラーでアプリを停止させず、マウス操作へのフォールバックを案内するメッセージを表示したうえで、マウスドラッグ入力モードに切り替える。
- FR-10: 実行環境が`DeviceOrientationEvent`自体を持たない、または`requestPermission`を持たない場合（Android Chrome等）、許可要求UIを表示せず、自動的にマウスドラッグ入力モードで起動する。
- FR-11: マウスドラッグ入力モードでは、ドラッグの移動量を疑似傾き値として扱い、傾き検知モードと同様の水面傾斜・波の移流・浮遊物反応を再現する。
- FR-12: レイアウトはスマホ縦画面を基準にしつつ、横画面・PC幅でも表示が破綻しないレスポンシブ対応を行う。
- FR-13: 傾き入力値（beta/gamma、またはマウスドラッグ由来の疑似値）を、シーンが破綻しない範囲にクランプしてから反映する。

## 受入基準（テストで確認できる文で書く）
- AC-1: `DeviceOrientationEvent.requestPermission`を持つ環境（iOS 13+相当）で「はじめる」ボタンを押すと、`requestPermission()`がユーザージェスチャーのコールスタック内で呼び出される。
- AC-2: `requestPermission()`の解決値が`"granted"`のとき、以後`deviceorientation`イベントのbeta/gamma値が変化するたびに、水面の傾斜パラメータが追従して変化する。
- AC-3: `requestPermission()`の解決値が`"denied"`のとき、コンソールエラーやアプリのクラッシュを起こさず、マウス操作へのフォールバックを説明する案内メッセージが画面に表示される。
- AC-4: `requestPermission()`がPromiseのreject、または例外をスローしたとき、その例外がキャッチされ、AC-3と同じフォールバック案内が表示される。
- AC-5: `DeviceOrientationEvent`が存在しない、または`requestPermission`メソッドを持たない環境でアプリを開くと、許可要求ボタンや許可関連のエラー表示を一切出さず、起動直後からマウスドラッグ入力モードで操作可能になる。
- AC-6: マウスドラッグ入力モードで画面上をドラッグすると、ドラッグの移動量に応じて水面の傾斜表示・浮遊物の位置が変化する。
- AC-7: 画面をキャプチャしたスクリーンショット上で、水面オブジェクトに周囲環境を映した反射（環境マップ反射）が視認できる。
- AC-8: 光源またはカメラの角度を変えてキャプチャした2枚のスクリーンショットを比較したとき、水面の法線マップに起因する波紋の陰影変化が視認できる。
- AC-9: `beta`または`gamma`に`NaN`を渡しても、シーンの描画が停止・フリーズせず、直前の有効な傾き値（初回は水平姿勢）を用いて描画が継続する。
- AC-10: 初回訪問時、案内文と「はじめる」ボタンを含むオンボーディング画面が表示される。
- AC-11: プロジェクトのビルドコマンド（`npm run build`相当）がエラーなく完了し、`dist/`ディレクトリが生成される。
- AC-12: `apps/still-pond/`のDockerfileに対して`docker build`がエラーなく完了する。
- AC-13: ビルドしたDockerイメージをコンテナとして起動すると、nginx等が`dist/`配下の静的ファイル一式を配信し、ブラウザからアクセスできる。
- AC-14: `apps/still-pond/deploy.json`の内容が`{"pages": true}`である。
- AC-15: `vite.config.ts`の`base`設定値が`'./'`である。
- AC-16: 画面幅375px・768px・1440pxのそれぞれで表示したとき、要素の重なり・はみ出し・横スクロールの発生等のレイアウト崩れが無い。
- AC-17: 画面幅375px・768px・1440pxのそれぞれで表示し一定時間操作したとき、ブラウザの開発者コンソールにエラーが出力されない。
- AC-18: 4x CPU throttling（Chrome DevTools相当のミドルレンジ端末シミュレーション）を有効にしたモバイル幅表示で10秒間シーンを描画したとき、平均フレームレートが30fps以上を維持する。

## 異常系・エッジケース
- DeviceOrientationEventのpermissionが「denied」のとき: エラー表示やアプリ停止をせず、マウス操作へのフォールバック案内を表示し、以降の入力はマウスドラッグで受け付ける（AC-3）。
- センサー自体が存在しない/APIが未実装のブラウザのとき（`requestPermission`メソッド自体が存在しない場合を含む）: 許可要求UIを一切表示せず、直接マウスドラッグ入力モードで起動する（AC-5）。
- 傾き値（beta/gamma）がNaN・null・undefinedを返したとき: その値は無視し、直前の有効な傾き値（初回は水平姿勢）を保持したまま描画を継続し、シーンが停止・フリーズ・欠落しない（AC-9）。
- `requestPermission()`がPromiseをreject、または呼び出し自体が例外をスローしたとき: 例外をキャッチし、denied時と同じフォールバック案内を表示する（AC-4）。
- ユーザーがオンボーディング画面で「はじめる」を押さずにページを離脱し、再訪したとき: 許可状態や進捗を永続化しないため、再訪時も再度オンボーディング画面から開始する。
- 端末を極端な角度（裏返し・真下向き等）に傾けたとき: 傾き反映値を一定範囲にクランプし、水面や浮遊物が画面外へ飛び出す、または物理的に破綻した見た目にならない（FR-13）。

## データ・API
外部API通信は行わない。全ての処理（3Dレンダリング、傾き検知、入力処理）はクライアントサイド（ブラウザ）内で完結する。サーバーへのデータ送信は発生しない。ユーザーデータ・設定・進捗の永続化（Cookie/LocalStorage/IndexedDB等）も行わない。

## 非機能・制約
- 技術スタック: Vite + TypeScript + Three.js（本体および公式addons: EffectComposer/UnrealBloomPass等のpostprocessing、RGBELoader等のローダー）。UIフレームワーク（React等）は用いず、フレームワーク非依存の構成とする。
- パフォーマンス: 4x CPU throttling相当のモバイル環境で、シーン描画中の平均フレームレートが30fps以上を維持すること。多段Bloomやスクリーンスペース反射（SSR）等の重いポストプロセスは避け、Bloom程度の軽量な後処理に留める。
- レスポンシブ: スマホ縦画面（375px相当）を第一優先とし、768px・1440px幅でも表示崩れが発生しないこと。
- 対応ブラウザ: モバイルはiOS Safari最新版・Android Chrome最新版、PCはChrome/Firefox/Safari最新版。
- Docker化: マルチステージDockerfileを用意する（build stageで`npm run build`を実行し、runtime stageで`nginx:alpine`等が`dist/`を配信する構成）。
- `apps/still-pond/deploy.json`に`{"pages": true}`を設定し、GitHub Pagesのサブパス配信に対応するため`vite.config.ts`の`base`を`'./'`にする。
- スタイル方向: 和のライトトーン・静謐な「間」を活かした構成とする（具体的な配色・タイポグラフィは実装フェーズで`frontend-design`スキルにより確定する）。
