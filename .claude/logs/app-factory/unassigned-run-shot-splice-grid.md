
### [14:45:00] prototype-builder（初回実装） — Swissスタイルのスクショ継ぎ足しツールを実装、視覚検証で見つけた2件のバグを修正
- 結果: apps/shot-splice-grid/ にVite+TypeScript+素のCSSで実装完了。2枚の画像アップロード/DnD、重なり自動検出（2段階粗密探索）、ドラッグ/数値/矢印キーでの手動調整、端部カット、前面レイヤー切替、差分表示モード、PNGダウンロードを実装。スタイル方向はスイス/インターナショナルスタイル（オフホワイト+黒+vermillion差し色、Space Grotesk+JetBrains Mono、ハードオフセットシャドウ、測定ブラケット風コーナー装飾）。npm run build / docker build ともに成功を確認済み（確認後にimage/containerは削除済み）。
- 気づき1（アルゴリズムのバグ）: 当初の重なり検出は「粗探索で幅も高さも縮小したサムネイルを使う」実装だったため、Playwrightで実際に800x1400のテスト画像（既知の正解重なり=400px）を食わせて検証したところ、誤って1240pxを検出した。原因は、正解位置での一致が「1px単位でしか成立しないシャープな一致」であるのに対し、高さ方向も縮小するダウンスケールがその鋭いスパイクを均してしまい、画像内で色帯が周期的に類似する別の位置（1240px）の方が粗探索の段階では「なだらかに良さそうに」見えてしまうこと。幅だけを縮小し高さは縮小しないグレースケール変換に変更し、候補数の上限で速度を担保する方式に直してから、正しく400pxを検出できることをnumpyでの独立検証とブラウザでの実機検証の両方で確認した。目視だけのレビューでは気づけなかった不具合で、既知の正解値を仕込んだテスト画像で実際にブラウザ操作するまで発覚しなかった。
- 気づき2（CSSの罠）: `hidden`属性と`.dropzones{display:grid}`/`.dropzone-filled{display:flex}`が同じ詳細度（0,1,0）で衝突し、後勝ちの自スタイルが`hidden`を無効化してしまい、画像読み込み後もアップロード用のドロップゾーンパネルが消えずプレビューと二重表示になっていた。`[hidden]{display:none !important}`をbase.cssに追加して解消。これもコードを読むだけでは気づけず、実際にブラウザで2枚アップロードしてスクリーンショットを撮って初めて発覚した。visual-qaで実ブラウザ検証を省略しないことの重要性を再確認。
