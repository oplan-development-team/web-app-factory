# New_Service_App

単発・小規模なWebアプリを複数つくって試していくための作業ディレクトリ。1つの製品ではなく、独立したアプリの寄せ集め。

## ディレクトリ構成

```
New_Service_App/
├── .claude/
│   └── CLAUDE.md          # このファイル
├── PROJECTS.md            # 全アプリのアイディア・進行状況一覧（ルート）
└── apps/
    ├── <app-slug-1>/       # アプリごとに完全に独立したディレクトリ
    ├── <app-slug-2>/
    └── ...
```

- 新しいアプリは `apps/<app-slug>/` 以下に作る。`<app-slug>` はkebab-case。
- 各アプリは自己完結（依存関係・設定ファイルもアプリ内で完結させる）。アプリ間でコードを共有しない。
- 技術スタックはアプリごとに自由に選ぶ。作る対象に一番合うものを都度選定する（素のHTML/CSS/JS、Vite+React、Next.jsなど、縛りは設けない）。選定理由が非自明な場合は該当アプリのREADME等に一言残す。
- 各アプリ用の`CLAUDE.md`が必要になったら `apps/<app-slug>/CLAUDE.md` として個別に置く（技術スタック固有の指示など）。

## PROJECTS.md の運用

ルート直下の `PROJECTS.md` で、全アプリのアイディア・進行状況を一元管理する。

- 1アプリ = 1セクション。ステータスは以下のいずれかで管理する。
  - `アイディア` — 未着手、思いついた段階
  - `進行中` — `apps/` 配下に着手済み
  - `完成` — 一通り動くところまでできた
  - `保留` — 中断中
- アプリのディレクトリを作成・大きく状況が変わったタイミングで `PROJECTS.md` を更新する。
- 個別アプリの詳細なタスクメモは基本ここに書かず、必要ならアプリ内に置く。`PROJECTS.md` は一覧性を優先する。

## 作業方針

- 単発・小規模という前提を守る。過剰な抽象化・共通基盤化はしない（YAGNI）。
- グローバルのコーディング規約・セキュリティ規約（`~/.claude/rules/`）はここでも適用される。技術スタックに応じて該当する言語別ルールに従う。
