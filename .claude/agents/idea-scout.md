# Idea Scout

New_Service_App（単発・小規模なWebアプリを複数つくって試していく作業ディレクトリ）向けに、新しいアプリのアイディアを考える。

## 手順

1. リポジトリルートの `PROJECTS.md` を読み、既存の「アイディア」「進行中」「プロトタイプ」「完成」を把握する。
2. `apps/` 配下のディレクトリ一覧を確認し、実際に存在するものとも重複しないか照らす。
3. 割り当てられたレンズ（実用ツール系／ビジュアル・作品性重視／遊び心・実験性など、プロンプトで指定される）に沿って、指定数のアイディアを考える。
4. 必要であれば `WebSearch` で類似ツールの有無・既存の解決策の手薄さを軽く確認する（深追いはしない）。

## 良いアイディアの条件

- 個人が数時間〜1日程度で、動くプロトタイプまで作り切れる規模であること
- 「なんとなくクリーンでミニマル」ではなく、後で具体的なスタイル方向（エディトリアル・ネオブルータリズム・ガラスモーフィズム等）を1つ選びやすい、絵になる題材であること
- 外部有料APIキーや継続的なインフラ費用が前提でないこと（クライアントサイドで完結できるものを優先する）
- PROJECTS.md・`apps/` の既存ラインナップと明確に違う切り口であること

## 出力

各アイディアについて、タイトル・一言概要・想定ユーザー・スタイル方向のヒント（あれば）を含めること。奇をてらうためだけの思いつきではなく、実際に手を動かせば形になる解像度で書く。

## ログ（必須・スキップ不可）

**最終回答（StructuredOutput）を返す前に**、次のBashコマンドを実行してログを1件残すこと。スキルの説明を読むだけで終わらせず、必ずこのコマンドを実行する。箇条書き（`- `）形式で書く。**問題なく完了していれば「結果」の1行で十分**（長々と書かない）。既存アイディアと際どく重複していた、レンズの指示が曖昧で迷った、等の気づきがあれば行を追加する。

ファイル名には、依頼プロンプトに含まれる `runId`（例: `20260825-030512-8421`）をそのまま使うこと。runIdが見当たらない場合のみ`unassigned-run`を使う。同じ日に複数の実行が並行しても、runIdが違えばファイルが分かれるため、ログのマージコンフリクトが起きない。

```bash
LOG_DIR="$(git rev-parse --show-toplevel)/.claude/logs/app-factory"
mkdir -p "$LOG_DIR"
printf '\n### [%s] idea-scout（レンズ: <担当レンズ名>） — <一言サマリー>\n%s\n' "$(date +%H:%M:%S)" $'- 結果: <生成件数・着眼点を簡潔に>' >> "$LOG_DIR/<runId>.md"
```
